# 用語集(このプロジェクト固有の言葉)

このプロジェクトの中でしか通じない言葉、または一般的な単語を特別な意味で使っている
ものの一覧。他のプロジェクトでそのまま持ち出しても通じないので、外部に説明するときは
ここの「言い換え」を使う。

---

## 1. 名前(このプロジェクトが勝手に付けた固有名)

| 語 | 意味 | 由来・言い換え |
|---|---|---|
| **padctl** | マイコン側のファームウェアの名前。転じてシステム全体の呼び名 | pad(ゲームパッド)+ ctl(control)。C の関数名 `padctl_*`、ビルド成果物 `padctl.bin`、設定の保存名、ログの見出し、mDNS のホスト名 `padctl.local` に全部これが出る。言い換え: 「このコントローラー自動化システム」 |
| **switchctl** | PC 側の道具の名前(コマンドと Python パッケージ) | Switch + ctl。`python -m switchctl ...` で使う。言い換え: 「PC 側の操作ツール」 |
| **PDT0** | 手順データのバイナリ先頭 4 バイト(識別子) | ProceDure daTa v0 の略。ファイルが壊れていないかの最初の判定に使う |
| **`_padctl._tcp`** | mDNS でマイコンが名乗るサービス名 | ネットワーク上で自分を見つけてもらうための名前 |

## 2. データの呼び方

| 語 | 意味 | 注意 |
|---|---|---|
| **手順**(手順データ) | 自動操作の内容そのもの。「A を 5 フレーム押して 60 フレーム待つ」といった一連の操作 | 一般語に近いが、この中では**必ずこの意味**。英語なら procedure。「スクリプト」「マクロ」とは呼ばない |
| **フロー** | 手順の**大きな流れ**を書いた側。`procedures/<名前>.flow.json` | 「フローチャート」の意味ではない。順番と入れ子だけを持つ |
| **部品** | 高密度な同時入力を**1行=1フレームの表**で書いた再利用単位。`parts/<名前>.csv` | 一般語の「部品」とは違い、**時間を持つ操作の断片**を指す。英語なら part |
| **行列 / マトリクス** | 上の表そのもの(縦=フレーム、横=ボタンや軸) | 数学の行列ではない。画面ではボタンをクリックで切り替え、押している所だけが色付きの `ON` になる |
| **ラベル** | 手順の中に置く区切りの名前(「移動」「戦闘」など) | 単なる注釈ではなく、**進捗表示・ログの位置情報・部分実行の開始点**を兼ねる |
| **前提条件** | その手順を始める前にゲームがどんな状態であるべきかのメモ(`pre`) | 実行前に画面に出るだけで、機械は検査しない |
| **並び順(order.json)** | 一覧の表示順。プロジェクト直下に保存 | 実行・監視/手順/部品の各画面で共有。載っていない名前は名前順で末尾に付く |
| **生値** | 変換を一切かけていない整数値 | スティックは中心 0 の -2048〜+2047(左と下が負)、ジャイロ・加速度は 16 ビット整数。**+1 が送信できる最小の差**という意味を持つ |
| **静止姿勢** | 何も操作していないときの加速度 (0, 0, 4096) | 加速度センサーは重力も測るため、静止していても 1G(=4096)が出続ける。全軸 0 は自由落下で実機には無い状態。「指定なし」はこの値になる |
| **IMU** | ジャイロ+加速度センサーの総称 | Switch 本体がサブコマンド 0x40 で有効化して初めて読まれる。有効化されたかは状態表示の「ジャイロ」行(imu_enabled)で見える |
| **ゆらぎ** | 素の値を間隔フレーム続けるたびに +幅/−幅 の対を短く入れる糖衣(既定: 幅7・1回2F・間隔60F) | Switch 側のゼロ点自動較正(一定値を誤差として吸収)を防ぐ。実測境界「差13」の最小対称対が±7、保持60Fまで安全の実測から間隔60。合計回転量は 値×長さ に厳密一致 |
| **GP / GY / GR** | ジャイロ3軸の列名 | **GR = 左右(水平)・正 = 左回り、GY = 上下・正 = 下向き(いずれも実機確認済み 2026-08-01)**。GP = ひねり(ロール)は推定・未確認。上下は重力補正により回し終えると水平へ戻る。生値 1 ≒ 0.07°/秒(実測一致) |
| **AX / AY / AZ** | 加速度3軸の列名 | AZ が重力の軸(静止で 4096)。空欄は静止姿勢になる |
| **フレーム周期** | 1 フレームが何ナノ秒か(既定 16666667 = 60.00Hz) | 実機に合わせて調整する設定値 |

## 3. 動きの呼び方

| 語 | 意味 |
|---|---|
| **実行エンジン** | 手順データを解釈して、決めた時刻に入力を送り出す部分。マイコンのタイマー割り込みで動く |
| **転送層** | 「Switch にコントローラーとして見せる」部分。USB の名乗りとレポート生成を担う |
| **プロコン方式** | 転送層の本命。純正 Pro コントローラーと同じ振る舞いをする。ジャイロが使える |
| **HID ゲームパッド方式**(**保険モード**) | 転送層のもう一方。単純な有線パッドとして見せる。**スティックが 256 段階に落ち、ジャイロは使えない**。プロコン方式が Switch 2 で通らなかった場合の逃げ道 |
| **周回** | 手順全体を何回繰り返すか(1 回ぶんを 1 周と数える) | 
| **周回分岐** | 待たない分岐。「奇数周と偶数周で操作を変える」など。変換時に展開するので実行中の判断が発生しない |
| **待機分岐** | 待つ分岐。全ボタンを離した状態で止まり、人が枝を選ぶと続きが走る |
| **腕**(うで) | 待機分岐・周回分岐の、それぞれの分かれ道 | 英語 arm の直訳。「選択肢」と言い換えてよい |
| **再開点** | 手順の途中から実行を始められる位置。**ラベルがそのまま再開点になる** |
| **区切り停止** | 今の周回を最後までやってから止まる(ゲームの状態が整う)。画面表記は「今の周で止める」 |
| **即時停止** | その場で全ボタンを離して止まる(ゲームは操作の途中で放置される)。画面表記は「今すぐ止める」 |
| **パススルー**(手動操作) | PC のゲームパッド/キーボードの入力を、そのままコントローラー出力として流す機能。Joy-Con を繋がずに手で操作できる |
| **装置台帳** | 登録済みマイコンの一覧(`switchctl.json` の devices)。1台ごとに 個体ID(MAC)・名前・接続先 を持つ。名前は付け替え自由、個体IDが本人確認の正 |
| **レーン** | 装置が2台以上のときの実行・監視画面の縦一列。1台ぶんの操作(接続・手順×周回・開始/停止・状態・タイムライン)がこの中で完結し、ボタンは装置名入り(「◼ 1P を今の周で止める」)。1台だけのときはレーンは現れず従来の画面 |
| **識別** | どのマイコンがどの Switch につながっているかを目で確かめる機能。その装置だけに小さな入力(左スティック半分の左右ゆらし)を約1秒送る。待機中の装置にだけ送れる |
| **対象** | 反復テスト・手動操作で「どの装置に対して行うか」の選択(2台以上のときだけ現れる)。手動操作の対象は開始時に固定される |
| **連結** | 2台をまとめて動かす宣言。連結すると**連結バー**(まとめて開始・両方停止・自動合流・両方へ同時に選ぶ)が現れ、外すと語彙ごと消える。連動(片方の異常で相方も止める)は「連結バーから開始した組」にだけ働き、レーンから開始した実行は連結中でも独立 |
| **連動停止** | 連結して開始した組の片方に**異常**(装置の異常報告・約5秒見えない)が起きたとき、相方も止めること。走行中は今の周で、駐機中は即時で止める。**人が止めたときは連動しない**(人為停止) |
| **自動合流** | 連結実行中、両方が待機分岐に着いたら設定の「進む腕」を自動で同時に選んで進めること。対応付けは到達順。「次の合流は自分で選ぶ(1回だけ)」で1回だけ保留できる(ワンショット) |
| **相方待ち** | 連結実行中、自分だけ先に待機分岐へ着いた状態(青表示・正常)。相方が来れば自動で進む。いつもの待ち(実測の中央値)を大きく超えると黄色の警告になる |
| **編成** | 盤面(連結・装置×手順×周回×開始位置・合流の腕)に名前を付けて残したもの。`sets/<名前>.json`。保存キーは装置の個体ID(改名に耐える)。通算周回も編成ごとに数える |
| **開始ズレ / 選択ズレ** | 2台へ続けて送った RUN / SELECT の完了時刻差(ms)。毎回実測して表示・記録する。装置内のずれ(µs)とは別の量 |
| **駐機タイムアウト** | 待機分岐で待つ上限(手順の `timeout_frames`)。超えたら `on_timeout` に従い中断するか指定の腕へ自動で進む(放置運転で永久に待たないための保険。既定は無期限) |
| **本体識別子** | Switch 本体が USB ペアリング(サブコマンド 0x01)の引数で名乗る16バイト中の先頭8バイト。実測(2026-08-06)で本体ごとに固有・毎回同一を確認。装置カードの「本体 XXXX」表示と本体の命名(consoles)に使う |

## 4. 設計の考え方につけた名前

| 語 | 意味 |
|---|---|
| **ブロック意味論**(ブロックモデル) | 手順データの解釈の取り決め。**「各フレームの入力状態を並べた表」**として読み、くり返しは「その表を回数分コピーして貼ったもの」と同じ結果になる。押しっぱなしなどの状態がくり返しの境界を暗黙にまたがない |
| **スナップショット** | ある時点の**全入力の状態**(差分ではない)。手順の先頭・くり返しの先頭・再開点に必ず置かれ、そこから始めても状態が確定する |
| **到達段階**(ブレッドクラム) | Switch との初期化がどこまで進んだかを表すビットの集まり。「挿しても無反応」のとき、どの段階で止まったかを切り分けるために使う |
| **模擬デバイス** | マイコンの代わりに PC 上で同じ通信を話すプログラム。実機なしで PC 側を開発・検証するためのもの |
| **模擬 Switch** | Switch 本体の代わりに、プロトコルの応答を検査するプログラム(`switchsim.py`) |
| **実操作検査** | 操作画面を実際にブラウザで動かし、「こうしたらこうなるはず」と突き合わせる検査(`pctool/tools/uicheck.py`)。見た目だけの確認と区別するためこう呼ぶ |

## 5. 監視・ログに出る言い方

| 語 | 意味 |
|---|---|
| **応答落ち** | Switch からの問い合わせに対する返事が、USB の送信待ちで捨てられた回数。**正常なら 0** |
| **遅延** | 予定した時刻より遅れて入力を送った回数と、その最大のずれ。入力精度が崩れていないかの指標 |
| **ログ落ち** | 記録が溢れて捨てられた件数 |

## 6. 設計文書の中の記号

`docs/hardware-design.md` で定義した番号。コードのコメントにも根拠として出てくる。

| 記号 | 意味 |
|---|---|
| **R1** | 唯一の第一原理。「入力精度が最優先。他はすべて R1 を毀損しない範囲で採用する」 |
| **D1 / D2** | R1 から必然的に決まった事項。D1=有線接続にする、D2=手順データをマイコン側に持たせて自律実行する |
| **W1〜W4** | 運用上の要望。W1=PC から転送、W2=実行/停止、W3=ログと無線更新、W4=ジャイロ |
| **A-1** | 付録の節番号。「フレーム境界での欠落・重複は原理的に消せない」= 1 フレーム精度の操作は確率的に外れる |
| **A-2** | 「ずれの発生確率は送信精度に比例する」= 精度を上げれば頻度は下げられる |
| **A-3** | 「時刻は開始時刻からの絶対時刻で計算する」= 誤差を積み上げない |
| **A-4** | 「記録するのは異常のみ。正常時の全フレームは記録しない」 |
| **未検証事項1〜4** | 実機がないと確かめられない項目。1=bInterval=1 の受理、2=無線更新後の再認識、3=プロコン方式が Switch 2 で動くか、4=分岐の表現 |

## 7. 一般用語だがこの中では特定の意味

| 語 | この中での意味 | 誤解しやすい点 |
|---|---|---|
| **フレーム** | ゲームの 1 描画周期(約 16.7 ミリ秒)。**時間の単位**として使う | PC ⇔ マイコンの通信でも1件のデータを「フレーム」と呼ぶ箇所がある(`docs/specs/comm-protocol.md`)。**用語の統一は未着手** |
| **転送** | PC からマイコンへ手順データを送ること | USB の「転送」とは別 |
| **保存**(COMMIT) | マイコン内のフラッシュメモリへ書いて電源を切っても残す操作 | PC 側のファイル保存とは別 |
| **bInterval** | USB の「何ミリ秒ごとに入力を読みに来るか」を宣言する値。1 にすると精度が上がる | USB 規格の用語そのもの |
