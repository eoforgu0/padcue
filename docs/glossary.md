# 用語集

padcue で使う用語と、このプロジェクトでの意味をまとめる。概念の正式な定義は [concepts.md](concepts.md) にあり、一致しないときはそちらに従う。

---

## 1. 名前

| 語 | 意味 | 由来 |
|---|---|---|
| **padcue** | このシステム全体の名前。PC 側のツール(コマンドと Python パッケージ)もこの名前である | pad(ゲームパッド)と cue(舞台で次の動きを促す合図) |
| **pademu** | 装置のファームウェアの名前。C の識別子、mDNS の名前、探索の識別文字列に出る | pad と emulator |
| **PDT0** | 装置へ送る手順データの先頭 4 バイト。形式を判別するための固定値 | procedure data |
| `_pademu._tcp` | 装置が mDNS で公開するサービス名 |  |

## 2. データの呼び方

| 語 | 意味 | 補足 |
|---|---|---|
| **手順** | 自動操作の内容。ブロックの列として書く。`procedures/<名前>.json` | concepts.md §3。スクリプトのブロックとは別のもの |
| **フレーム表** | 密度の高い同時入力を、1 行を 1 フレームとする表で書いたもの。`frametables/<名前>.csv` | 手順からフレーム表のブロックで参照する。同じ表を複数の手順から使える |
| **ラベル** | 手順の中に置く、名前の付いた区切り | 進捗の表示、記録の位置、開始位置を兼ねる |
| **区切り** | padcue が停止と開始の位置として扱う点。ラベル、周の境、選択待ちになる点の 3 種 | concepts.md §5 |
| **前提条件** | その手順を始める前に、ゲームがどんな状態であるべきかを書いた文(`precondition`) | 実行の前に画面に出すだけで、自動ではチェックしない |
| **プロジェクト** | 手順、フレーム表、条件、登録情報、プリセットを保存するフォルダー。`padcue.bat` では `data\`、`padcue-demo.bat` では `demo\` | concepts.md §11 |
| **padcue ファイル** | 手順を、参照するフレーム表と条件ごと 1 つのファイルにまとめたもの | エクスポートで作り、インポートで読み込む。ほかのものを使わない手順 1 件は手順の `.json`、フレーム表 1 件は `.csv` のままエクスポートする |
| **構成情報** | padcue ファイルの中の `pack.json`。入っている手順・フレーム表・条件の一覧 | インポートするときに、足りないものと名前の衝突を確認するのに使う |
| **並び順** | 一覧の表示順。プロジェクト直下の `order.json` | 手順・フレーム表・プリセット・条件の一覧が使う |
| **送った手順のコピー** | 装置へ転送した手順の記録。`sent/<id>.json` と送ったバイト列 `sent/<id>.bin` | 装置は名前を持たず、中身の id で報告する。そのため、ログに出す手順の名前と、実行中に条件で選ぶときの判断点の情報は、このコピーから読む(coupling.md D5) |
| **生値** | 変換をかけずに Switch へ送る整数の値 | スティックは中心 0 の -2048〜+2047(左と下が負)。ジャイロと加速度は 16 ビットの整数 |
| **静止姿勢** | 空欄の加速度に入る値 (AX, AY, AZ) = (0, 0, 4096)。水平に置いて静止した状態にあたる | 加速度センサーは重力も測るので、静止していても AZ に 1G(= 4096)が出る |
| **IMU** | ジャイロと加速度センサーの総称 | Switch 本体が有効にして初めて読まれる。有効になったかは、「状態を表示」と `python -m padcue status` の「ジャイロ」の行に出る |
| **ゆらぎ** | 一定のジャイロの値に、短い増減の対を一定の間隔で入れる指定 | 一定の値を長く送ると回転が止まるのを防ぐ。根拠は runbook.md の付録「ジャイロの実測記録」 |
| **GY / GR / GP** | ジャイロ 3 軸の列名 | 画面では縦・横・ひねり。GY は上下(正 = 下向き)、GR は左右(正 = 左回り)で、実機で確認した。GP はひねりで、確認していない。列と軸の対応は、Switch へ送るデータの並びで決まる |
| **AX / AY / AZ** | 加速度 3 軸の列名 | 画面では X・Y・Z。AZ が、水平に置いたときに重力がかかる軸。AX と AY のどちらが左右でどちらが前後かは確認していない |
| **フレーム周期** | 1 フレームの長さ(ナノ秒)。既定は 16666667(60.00Hz) | Switch 側の周期に合わせて変えられる設定値(runbook.md §3-2) |

## 3. 実行と装置の呼び方

| 語 | 意味 |
|---|---|
| **操作画面** | ブラウザーで開く padcue の画面。`padcue.bat` か `python -m padcue gui` で開き、padcue を動かしている PC のブラウザーからだけ使える。コードのコメントと名前では GUI とも書く |
| **コマンド** | `python -m padcue <コマンド名>` で使うツール。コードのコメントと名前では CLI とも書く |
| **実行エンジン** | 手順データを解釈して、決めた時刻に入力を送信する部分。装置のタイマー割り込みで動く |
| **転送層** | Switch にコントローラーとして見せる部分。USB のディスクリプターとレポートの生成を担当する |
| **周回** | 周回数のくり返しを 1 回通すこと。周回数は実行のときに指定する(concepts.md §2) |
| **周回を終える** | 実行中に周回数を変えて、予定より早く周回を終えること。周回数のくり返しの後ろのブロックまで実行する(concepts.md §5) |
| **選択肢** | 分岐の、それぞれの分かれ道 |
| **開始位置** | 実行を始める位置。先頭、ラベル、停止した位置から選ぶ |
| **停止した位置** | 前回の実行で最後に通った区切りと、そのときのくり返しの回。開始位置に選ぶと、そこから始め直せる(concepts.md §5) |
| **周回数** | 周回数のくり返し(なければ手順全体)を通す回数。実行・監視のレーンの欄で決め、空欄なら停止させるまでくり返す |
| **一括操作** | 実行・監視のレーンの上の行。選んだレーンを一緒に開始し、一緒に停止する |
| **待つ間の入力** | 分岐と合流点で待っている間の入力。「離す」(既定)か「そのまま」(直前の入力を続ける)を選ぶ |
| **それ以外** | 分岐で、どの選択肢の「対象の回」も当てはまらない回の行き先 |
| **区切りで停止** | 次の区切りまで動かしてから止めること |
| **停止** | その場で全入力を離して止めること(concepts.md §5 の「全入力を離す」) |
| **手動操作** | PC のゲームパッド・キーボード・画面のコントローラーの入力を、そのまま装置の出力として送ること |
| **装置** | 手順を受け取り、コントローラーの入力を Switch へ送るもの。実機(pademu を書き込んだ M5Stack AtomS3 Lite)と模擬装置がある |
| **登録情報** | 使うと決めた装置の一覧。プロジェクトの `padcue.json` にあり、1 台ごとに名前・装置 ID・接続先を持つ |
| **装置 ID** | 装置の Wi-Fi の MAC を 12 桁の 16 進で表したもの。登録情報と実行記録は、これで装置を指す |
| **割り当て** | 登録情報の名前に装置 ID を結び付けること。装置 ID が空の行は「未割り当て」 |
| **レーン** | 装置 1 台ぶんの操作の単位。手順・周回数・開始位置、開始と停止、状態、タイムラインを持つ(concepts.md §8) |
| **グループ** | 一緒に開始したレーンの集まり。合流点で待ち合わせる。見出しの停止は全レーンを止め、レーンの停止はそのレーンだけを止める |
| **グループを解除** | 停止したグループのレーンを、1 本ずつのグループに戻すこと(concepts.md §8) |
| **操作権** | 装置を動かせる権利。1 つの padcue だけが持つ。開始や手動操作のように装置を動かす操作と、手順の転送や設定の変更のように装置の中身を変える操作に必要で、停止と状態の読み出しには要らない。要求ごとの区別は [specs/comm-protocol.md](specs/comm-protocol.md) にある |
| **手動操作の対象** | 手動操作をどの装置に対して行うかの選択。装置が 2 台以上のときに出る |
| **デッドゾーン** | 手動操作を記録するとき、これ未満のスティックの傾きを 0 とみなす値。ゲームパッドのぶれを消すためのもので、ゲームパッドがつながっているときだけ欄が出る |
| **連動停止** | グループの 1 台が装置の側で停止したとき(完了、異常、装置のボタンなど)、残りも停止すること。止まり方は、停止した 1 台の止まり方で決まる。人が画面かコマンドでレーンを停止したときと、「未検出」は、連動停止のトリガーにしない |
| **プリセット** | どのレーンでどの手順を、何回、どの開始位置から始めるかに名前を付けて残したもの。`presets/<名前>.json` |
| **開始のずれ** | グループの開始を複数の装置へ続けて送ったときの、開始の要求と状態の読み出しを終えた時刻の差(ミリ秒)。毎回測って記録する。装置の中の遅れ(マイクロ秒)とは別の量 |
| **自動で進む待ち** | 人が選ばなくても進む待ち。選択肢がどれも条件、スクリプトの結果、時間切れのいずれかである分岐と、合流点と、スクリプトのブロックの待ち。操作画面の設定で、その行を出さないようにできる |
| **時間切れ** | 分岐と合流点で待つ上限。分岐では時間切れの選択肢へ進み、合流点では相手を待たずに続きへ進む。装置が数える |
| **本体識別子** | Switch 本体が装置の登録のときに送る値(本体の Bluetooth MAC)。画面では下 4 桁を「本体 ID XXXX」と出す。形式は procon-protocol.md にある |

## 4. 設計の考え方につけた名前

| 語 | 意味 |
|---|---|
| **ブロック意味論** | 手順の解釈の規則。手順を「各フレームの全入力の状態の並び」として読む。押し続けている状態は、くり返しの境界を暗黙にはまたがない(concepts.md §4) |
| **スナップショット** | ある時点の全入力の状態(差分ではない)。手順の先頭、くり返しの先頭、ラベルに置かれ、そこから始めても状態が決まる |
| **到達段階** | Switch との初期化がどこまで進んだかを表すビットの集まり。認識されないときに、どの段階で止まったかを切り分けるのに使う(getting-started.md §3-2) |
| **模擬装置** | 実機の代わりに、PC の上で同じ通信をするプログラム。実機なしで PC 側を開発し、デモで試すためのもの |
| **デモ** | 実機をつながずに、模擬装置 2 台で操作画面を試す使い方。`padcue-demo.bat` で開き、`demo` フォルダーをプロジェクトに使うので、実機用の登録情報と手順には触れない |
| **模擬 Switch** | Switch 本体の代わりに、コントローラーとしての応答を確認するテストのツール(`pctool/tests/switchsim.py`) |

## 5. 状態の表示とログの用語

| 語 | 意味 |
|---|---|
| **フレーム処理**(最大遅延) | 手順を 1 フレーム進めるタイマーが、予定の時刻からどれだけ遅れて動いたか。ログには「フレームの処理が遅れました」と出る |
| **読み取り待ち**(最大遅延) | 入力が変わってから、その値を USB へ載せられるまでの時間。前の値を Switch が読みに来るまでは載せられない。Switch が受け取った時刻でも、ゲームが読んだ時刻でもない |
| **USB の問い合わせの間隔** | 装置が USB で宣言している、Switch が入力を読みに来る間隔(bInterval)。Switch が実際に読みに来る間隔は、これより長いことがある |
| **送信失敗** | Switch への応答か入力を、送れずに捨てた件数。正常なら出ない |
| **記録落ち** | 装置の記録があふれて捨てられた件数 |
| **待機中** | 装置が手順を実行していない状態。Switch とつながっていれば、開始を受け付ける |
| **実行中** | 装置が手順を実行している状態 |
| **選択待ち** | 分岐、合流点、スクリプトのブロックで止まって待っている状態。選択肢が選ばれるか、相手が揃うか、スクリプトが終わると続きへ進む(concepts.md §5)。レーンのバッジは、分岐の待ちを「選択待ち」、合流点の待ちを「合流待ち」、スクリプトの待ちを「スクリプト実行中」と呼び分ける。ログの状態の行は、装置が待ちの種類を持たないので、どれも「待ち」と書く |
| **合流待ち** | レーンの状態のバッジで、合流点の選択待ちと、周回の終え方で先に周の境に停止し、ほかのレーンが停止するのを待つ間を呼ぶ語。どちらもグループのほかのレーンが来るのを待っている |
| **スクリプト実行中** | レーンの状態のバッジで、スクリプトの選択待ちを呼ぶ語。コマンドが終わるのを待っている |
| **待ち** | ログの状態の行で、分岐の選択待ち、合流点の合流待ち、スクリプト実行中をまとめて呼ぶ語。装置の記録は待ちの種類を持たない |
| **異常停止** | 装置が異常を検出し、全入力を離して停止した状態。LED が赤く点滅する。装置が開始を受け付けなかったときも、PC は異常停止として扱う(このとき LED は赤くならない)。次の開始か「異常を解除」で解除される |
| **完了** | 手順を最後まで実行して終わったこと。周回数のくり返しを周回数ぶん通し、その後ろのブロックも実行する。通知とタブの名前に出る |
| **見えている** | 装置から応答があり、装置と Switch が USB でつながっている状態。画面には出ない。開始できるかの判定に使い、開始できるのは見えているときだけである |
| **未検出** | 装置から 10 秒続けて応答がない状態。この間、レーンは最後に読めた進捗を出し続ける |
| **操作権なし** | 装置の操作権を、別のフォルダーに置いた padcue が持っている状態。操作権が要る操作はできず、停止と状態の読み出しはできる |

## 6. 文書とコードが引く番号

文書とコードのコメントは、根拠をこの番号で引く。どの番号も、振るのは 1 つの文書だけである。文書の節は「文書の名前 §節の番号」で引く(例: hardware-design.md §1-2)。

| 記号 | 文書 | 意味 |
|---|---|---|
| **R1〜R28** | [requirements.md](requirements.md) | 要件。R1 は時間の正しさ、R2 は状況の正しさ |
| **C1〜C8** | [requirements.md](requirements.md) | 制約。変えられない環境の事実 |
| **P1〜P30** | [principles.md](principles.md) | 方針 |
| **D1〜D12** | [specs/coupling.md](specs/coupling.md) | 複数の装置の同時運用と実行についての決定 |

## 7. 一般の語だが、ここでは決まった意味で使うもの

| 語 | ここでの意味 | 補足 |
|---|---|---|
| **フレーム** | 手順の時間の単位で、padcue が入力を切り替える単位。既定は約 16.7 ミリ秒で、ゲームや USB の周期には同期しない | 通信の 1 単位は「パケット」と呼ぶ |
| **パケット** | PC と装置の通信の 1 単位(`len u16 \| type u8 \| payload \| crc32`)。[specs/comm-protocol.md](specs/comm-protocol.md) |  |
| **転送** | PC から装置へ手順データを送ること |  |
| **保存**(COMMIT) | 送った手順データを、装置のフラッシュメモリへ書くこと | PC 側のファイルの保存とは別 |
| **bInterval** | USB のディスクリプターで、問い合わせの間隔を宣言する値(ミリ秒) | USB の規格の用語 |

## 8. 観測と判断

映像を見て自動で選ぶ仕組みと、スクリプトを実行する仕組みの用語。詳細は [specs/observe-and-decide.md](specs/observe-and-decide.md)。

| 語 | 意味 |
|---|---|
| **映像ソース** | 画面を 1 枚の画像として取る手段(OBS の仮想カメラなどのカメラ、デスクトップ、ウィンドウ、画像ファイル)。どの装置の映像かという情報は持たない |
| **条件** | 映像が基準画像と一致しているかを判定するもの。判定する映像、基準画像、判定する範囲、しきい値を持ち、名前で保存して参照する。`conditions/<名前>/` |
| **基準画像** | 条件が比べる画像。何枚でも登録でき、いずれか 1 枚に一致すれば一致である |
| **一致度** | いまの映像が基準画像にどれだけ近いかを 0〜100 で表した数。100 が同じ。しきい値以上なら一致 |
| **採点** | いまの映像を基準画像と比べて、一致度を出すこと |
| **一致しないはずの画面** | しきい値を決めるために条件に持たせる画像。判定には使用しない |
| **装置に設定している映像** | 実行している装置に設定した映像。条件の「判定する映像」と、スクリプトに渡す画像の選択肢にある。設定は装置の一覧の「映像」で行う |
| **対象の回** | 分岐の選択肢に付ける、回数の絞り込み(「最初の回」「n 回ごと」など) |
| **選択条件** | 分岐の選択肢に付ける、選び方の指定。手動、条件、スクリプトの結果、時間切れのいずれか。条件とスクリプトの結果は、操作用の PC が判定する |
| **分岐** | 選択肢のどれかへ進む判断点。その回に当てはまる選択肢のうち、選択条件のないものがあれば待たずに進む。選択条件を持つ選択肢だけが残る回は、止まって待つ |
| **合流点** | グループが同じ名前で待ち合わせる点。選択肢を持たない。すべての台が着いたら、それぞれ続きへ進む。1 台のグループでは待たずに通過する |
| **スクリプト** | 手順の中から、利用者が用意した任意の処理を呼ぶブロック。完了を待つかどうかを選べ、渡す映像ソースを指定できる |
