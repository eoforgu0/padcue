## 1. 自分の手順を作る

画面だけで作れます。ファイルを直接編集する必要はありません。

### 1-1. 考え方

手順は、ボタンやスティックなどの操作をブロックで並べて作ります。細かい同時入力はフレーム表(1-6)で書きます。

- 1 フレーム = 約 1/60 秒
- **「押して離す」は、押してから離すまで**を 1 つのブロックで表します
- くり返しは、書いた区間をそのままくり返します。押しっぱなしはくり返しの境界を勝手に越えません(越えさせたいなら、くり返しの**外**で押す)

### 1-2. 画面で組む

「**手順の編集**」タブの **＋ 新規** で名前を付けます。左の「追加するブロック」を押すと、**選択中のブロックの直後**に入ります(くり返しか、分岐の選択肢か「それ以外」の見出しを選んでいるときは、その中の末尾に入ります)。くり返しの後ろや選択肢の途中など、好きな位置へは、「追加するブロック」の項目をドラッグして置きます。似た手順は **複製** から作ると早いです。

**名前を変更**すると、その手順を使用している手順とプリセットも自動で更新し、更新した件数を出します。フレーム表と条件の名前を変えたときも、使用している手順を更新し、更新した件数を出します。

「追加するブロック」は 3 列です。左の列が装置への入力、中の列が時間と流れのブロックです。右の列は、別の手順、フレーム表、スクリプトのように、手順の外で作ったものを使うブロックです。表は左の列から順に並べています。

| ブロック | 意味 | よく使う場面 |
|---|---|---|
| **押して離す** | 指定フレーム数だけ押して離す | ほとんどの操作 |
| **押し続ける** / **離す** | 押した状態を保つ / やめる | ダッシュしながら移動 |
| **スティック** | 傾きを指定(中心 0、左と下がマイナス) | 移動 |
| **ジャイロ** | 回転の**速さ**(生値)と**長さ**を指定。長さぶん回して自動で止まる(長さ 0 = 次に変えるまで同じ値を送り続ける。1-7) | カメラを回す |
| **待つ** | 入力を変えずに待つ(押し続けているボタンはそのまま) | ロード待ち、演出待ち |
| **くり返し** | 中身を N 回 | 同じ入力の組み合わせを何度も送る |
| **分岐** | 選択肢のどれかへ進みます。選択肢ごとに「対象の回」(最初の回、n 回ごとなどの絞り込み)と「選択条件」(手動・条件・スクリプトの結果・時間切れ)を決められます(6 節) | 結果を見て分かれる / 偶数周だけ違う操作 |
| **合流点** | グループの相手が同じ合流点に来るまで待ちます(5 節) | 2 台の進み具合を揃える |
| **ラベル** | 区切りの名前 | 途中から試せるようになる |
| **別の手順** | ほかの手順を呼ぶ | 共通部分の使い回し |
| **フレーム表** | 細かい同時入力を表で(1-6) | 同時押し |
| **スクリプト** | PC 側のコマンドを実行し、終わったら先へ進みます(6-3) | 外部のツールに任せる |

区切りのよい所ごとに「ラベル」を置くと、そこから後だけを試せます(1-4)。

各ブロックには「メモ」を付けられます(右の編集欄)。「押して離す A を 2F  項目を選ぶ」のように薄く表示されるので、ゲーム中で何をする操作なのかが一目で分かります。実行の内容には影響しません。

フレーム表のブロック、別の手順のブロック、分岐の選択肢の条件は、右の編集欄の「フレーム表を開く」「手順を開く」「条件を開く」で中身を開けます。「手順を開く」は同じ画面で開くので、保存していない変更があるときは、保存してから開くかを確認します。開いた先では、保存ボタンの並びに、「「サンプル」へ戻る」のように呼んでいた手順の名前が付いたボタンが出て、押すとその手順へ戻れます。呼び出しを何段たどっても、たどった順に戻れます。

ブロックの並べ替え、複製、削除は、次のように操作します。

| したいこと | 操作 |
|---|---|
| 並べ替え | ブロック左端の **⠿** をドラッグ(くり返しや分岐の中へも出し入れできます。移動先は線で示されます)。**Alt+↑/↓** でも動かせます |
| 好きな位置に追加 | 左の「追加するブロック」から**ドラッグ**して置きたい場所へ(クリックだと選択中の直後に入ります。くり返しか、選択肢か「それ以外」の見出しを選んでいるときは、その中の末尾に入ります) |
| 別の手順を呼ぶ | 左の手順の一覧の行の **⠿** を、開いている手順の置きたい場所へ**ドラッグ**(その手順を呼ぶ「別の手順」のブロックが入ります) |
| 複製 | ブロック右端の複製のアイコン |
| 削除 | ブロック右端の **×** |

くり返しには名前を付けられます。回数は、数、「無限」、「周回数」から選びます。「周回数」にすると、回数は実行・監視のレーンの周回数の欄で決まります。

結果によって操作を分けたいときは、「**分岐**」ブロックを使います。実行が止まって画面に選択肢のボタンが出るので、見て選べば続きが実行されます。待っている間は手順のフレームを数えず、選ばれた所から続きを数えるので、選ぶまでにかかった時間は、その後の入力の時刻に影響しません。

偶数周だけ違う操作にするには、分岐の選択肢の「対象の回」を「手順全体」にし(回数を「周回数」にしたくり返しがある手順では、分岐を囲むそのくり返しを選びます)、「n 回ごと」を選んで n を 2 にします。

分岐と合流点の「待つ間の入力」では、待っている間の入力を、「離す」(既定)か「そのまま」(直前の入力を続ける)から選びます。合流点の「時間切れ」は、相手が来なくても進む上限です(空欄なら待ち続けます)。

ブロックの編集は、どれも **Ctrl+Z** で元に戻せます。

手順そのものは、左の一覧で操作します。行の右端の **⋯** を押すか、行を右クリックすると、名前を変更、複製、エクスポート(ファイルにして保存)、実行・監視で非表示、使用している場所を表示、削除が並んだメニューが出ます。フレーム表と条件の一覧も同じです(実行・監視で非表示は手順だけにあります)。

読み込めないフレーム表と条件(文字コードが UTF-8 でない、列の名前が違うなど)も、変換できない手順と同じく一覧に「エラー」と出ます。理由は「エラー」にマウスポインターを合わせると出ます。フレーム表は、値の誤りなら編集画面で開いて修正できます。列の名前が違うときと、1 行目の列の名前より値の多い行があるときは、編集画面では開けません。理由に「ファイルの N 行目」と出るので、その行をエディターで修正します。

受け取ったファイル(padcue ファイル、手順の `.json`、フレーム表の `.csv`)は、手順・フレーム表・条件のどの一覧の下の **インポート** からでも入れられます。入れる前に中身の一覧が出て、1 件ずつインポートするかを選べます。「置き換える」を選んだ行には、置き換えると見つからなくなる開始位置(プリセットとレーン)が出ます。別の名前で入れても、それを使う手順がどれもインポートされない物は、その行に「別の名前でインポートすると、どの手順も使用しません」と出ます(使う手順も別の名前で入れると、その写しが新しい名前を使います)。インポートできるファイルは 48MB までです。

⠿ をドラッグすると一覧を並べ替えられます。行を選んで **Alt+↑/↓** を押しても動かせます。この並びは「実行・監視」タブと共通です(よく使う手順を上に置けます)。フレーム表と条件の一覧も同じように並べ替えられます。

手順が増えてきたら、一覧の下の **＋ フォルダー** でフォルダーを作り、手順をドラッグで入れられます。フォルダーの行をクリックすると開閉します。フォルダーを削除しても、中の手順は外に出るだけで消えません。フォルダーの中にフォルダーは作れません。

**実行・監視で非表示**を選ぶと、その手順が「実行・監視」タブの手順の一覧に出なくなります。一覧では行が薄くなり、名前の右にアイコンが付きます。編集はいつでもでき、メニューの **実行・監視で表示** で戻ります。試作中の手順を、実行するときの選択肢から外しておくのに使います。

行のメニューの **使用している場所を表示** には、使っている場所の数が付きます(「使用している場所を表示(2 か所)」)。0 か所なら押せません。

- 押すと、その手順を使っている手順とプリセットが出ます。開いていない手順でも見られます
- 手順の名前を押すと、その手順の、使っているブロックへ移ります。「手順を開く」と同じく、保存ボタンの並びに出るボタンで、それまで開いていた手順へ戻れます
- フレーム表と条件の一覧にも同じものがあります

古い手順を削除するか迷ったときに、メニューを開くだけで、どこでも使っていないかが分かります。削除の確認には、使っている手順と、呼び出しをたどって実行できなくなる手順、それらを使うプリセットが出ます。

一部を外して試したいときは、各ブロックの右端のチェックを外します。外すと、そのブロックを丸ごと飛ばします(時間も消費しません)。削除せずに残せるので、戻すのもチェックを入れるだけです。くり返しや分岐で外すと、**中身ごと**飛ばします。

### 1-3. 保存して、タイムラインで確認する

編集すると、その場で装置へ送る形に変換して確認し、気づきにくい書き方があれば**警告**を出します。置いたばかりのブロックの警告は、別のブロックを選ぶか保存すると出ます。警告が出ていても保存できます。警告は手順を開いたときにも出て、そのブロックは黄色になります。警告を押すと、そのブロックへ移ります。変換できない手順は、一覧に「エラー」と出ます。開くと原因が出て、原因のブロックが赤くなります(「エラー」を押すと、そのブロックが選ばれます)。よく出る警告は次の 4 つです。

| 警告の書き出し | 意味 | どうするか |
|---|---|---|
| 同じフレームで押して離しているため、押した入力が打ち消され… | 押したのと同じフレームで離していて、入力が現れない | 間に「待つ」を入れるか、順番を修正する |
| 同じフレームで離して押し直しているため、「離す」が打ち消され… | 離したのと同じフレームで押し直していて、押したままになる | 間に「待つ」を入れる |
| 同じフレームで左スティックを中央に戻して倒し直しているため… | 長さ付きのスティックの直後に続けて倒していて、中央に戻らない | 間に「待つ」を入れる |
| ジャイロが一定の値のまま …F 続いています | 一定の回転を長く続けると、途中で回転が止まる(1-7) | ジャイロブロックは「ゆらぎを付ける」か、短くする(長さ 0 のブロックは、長さを指定してからゆらぎを付ける)。フレーム表は列にゆらぎを書く |

くり返しの最後で離して、次の回の最初で同じボタンを押すときも、押したままになります。この場合は警告が出ないので、くり返しの最後に「待つ」を入れてください。

長さを 1 フレームにしたときは、その欄の下に注意が出ます(1-5)。

編集画面の下の「タイムライン」を、見出しの ▶ で開いてください(開閉は覚えます。畳んでいても、手順の長さは見出しに出ます)。横が時間、縦が入力(ボタン、スティック、ジャイロ、加速度)です。横棒が出るのは、動かしている区間だけです。加速度は静止していても重力の分の値が出続けるので、静止姿勢の値(AZ = 4096)から変えた区間だけが横棒になります。思った所に横棒が出ていなければ手順が違うので、実機で試す前に気づけます。図と長さには、保存していない編集も反映されます。変換できない間は、前の図が薄く残ります。

待ち(分岐、合流点、スクリプト)の所では時間の軸を切り、破線の枠に待ちの名前を書きます。枠の後ろの目盛りは、待ちの終わりから数え直します(「+1 分」)。枠に名前が入らない図(待ちが多い図や、幅の狭い図)は、枠の代わりに細い縦線で待ちの位置を示し、目盛りは先頭から通して数えます(待つ時間は入りません)。どちらになるかは図の幅で決まり、ウィンドウの幅を変えると切り替わります。実行・監視のレーンの図を畳んでいる間は、この縦線は出ません。

実行・監視のタイムラインは、決まっていることだけを描きます。

- 選択肢が 2 つ以上ある選択待ちの分岐は、選ぶまで待ちの枠だけを描き、枠のすぐ後ろに分岐の後ろの続きを描きます。選ぶと、その周の間は、選んだ選択肢の中身を入れて描き直し、線はその中を進みます。描き直すと、横の縮尺も図の長さに合わせて変わります
- 時間切れで装置が選んだときは、装置がその選択肢の中にいることを PC が読んだ時点で描き直します。PC が読む前に通り抜けるほど短い選択肢は、その回は枠だけのままです
- 開始位置が選択肢の中にあれば、その選択肢を描きます
- 「対象の回」で待たずに決まる分岐は、今の周に選ばれる選択肢で描きます。「最後の回」と「残り n 回」は、待機中は周回数の欄の値(空欄は無限)、実行中はその実行の周回数で適用します。待機中の図は 1 周目です
- 図の行(ボタンと軸)は、その実行で通りうる入力の全部で、描き直しても変わりません。周回数が無限の実行でも、周回の終え方で最後の回を作ったときにだけ通る選択肢の入力の行が、初めから入っています

周回数のくり返しは 1 周ぶんだけ描きます。線は周の終わりまで進むと周の頭へ戻り、最後の周の後は後ろへ進みます。周が替わると、図もその周の形に替わります(まだ選んでいない分岐は枠だけに戻り、「対象の回」の分岐はその周の選択肢になります)。周回数のくり返しを抜けた後は、最後の周の形のまま残ります。同じ周に同じ分岐を何度も通るとき(中のくり返しの中の分岐)と、終わりのないくり返しの中の分岐は、今の回に選んだ選択肢だけを描き、まだ通っていない回は枠だけで描きます。

### 1-4. 途中から試す(手戻りを減らす)

長い手順を毎回先頭から実行すると時間を無駄にします。

1. 「実行・監視」タブの **開始位置** で、試したいラベルを選ぶ
2. **周回数** に 1 を入れて **開始** を押す

選んだ位置からすぐに始まります(飛ばした前半ぶんは待ちません)。飛ばした区間は実行しませんが、入力の状態は、先頭から実行してそのラベルに来たときと同じになります(前半で押し続けにしたボタンは、開始の直後から押されます)。ゲームの側は、そのラベルから始められる状態にしておいてください。

途中で停止した後は、開始位置に「停止した位置」が出ます。選ぶと、停止した所から始め直します。周回数の横には、残りの周回数が「残り 2 周」のように出ます。先頭の次の区切りを通る前に停止したときは、最後に通った区切りが先頭なので、「停止した位置」は出ません。「先頭」から始め直してください。

### 1-5. 「たまに失敗する」ときの考え方

入力の長さは、ゲームから見ると前後に 1 フレームばらつくことがあります。ゲームが入力を読む時刻を外から知る手段がなく、装置が入力を切り替える時刻と合わせられないためです([hardware-design.md](design/hardware-design.md) §1-2)。

| 指示 | ゲームが見る長さ | 起こること |
|---|---|---|
| 1 フレーム | **0〜2** | 読まれないことがある |
| 2 フレーム | 1〜3 | 読まれる。長さがばらつく |
| N フレーム | N−1〜N+1 | 同上 |

この表は、ゲームが 1 フレームごとに入力を読むときのものです。読み取りの周期が長いゲームでは、2 フレームでも読まれないことがあります。実際に動かして、読まれる長さを確認してください。実時間はフレーム周期の設定(3-2)でも変わります。

長さを 1 フレームにすると、編集画面の欄の下に「1 フレームの入力は反映されない場合があります」と出ます。

対処は 2 つです。

1. **2 フレーム以上にする**。長さが必要な操作なら、前後に余裕を持たせます。ゲームの中で操作が成立するかは、実際に動かして確認します
2. **成功するまでくり返す**。1 フレームの精度が必要な検証はこちらです

成功率を確認したいときは、**周回数** を 1 にして **開始** を何度か押し、結果を見比べてください。

### 1-6. 細かい同時入力は「フレーム表」で書く

「1 フレーム目から A を押し、3 フレーム目で B と ZL を加えつつスティックを左」のような密な入力は、ブロックを並べるより表の方が、書くのも読むのも速く済みます。

「**フレーム表の編集**」タブの **＋ 新規** で作り、行を埋めます(「くり返し」の「回数」を使わなければ 1 行が 1 フレーム)。すべてのボタン・スティックの列が最初から並んでいます(列を追加する操作はありません)。

```text
フレーム   A    B    ZL   ... 左スティック 横
   1      ON                                  <- A を押す
   2      ON
   3      ON   ON   ON      -1200             <- A・B・ZL を押しつつ左スティックを左へ
   4      ON        ON      -1200
   5                                          <- すべて離す
```

- ボタンはクリックで切り替えます。**押したままドラッグ**すると連続したセルをまとめて塗れます
- 押しているセルだけが色付きの `ON` になります。押していないセルは**空欄**です(`OFF` を並べると、どこを押しているのか形で追えなくなるため)
- スティックなどの数値は直接入力します(中心 0、左と下が負)
- 空欄は、ボタンなら離した状態、スティックとジャイロなら 0 です。加速度の空欄だけは静止姿勢の値(AZ = 4096)になります(1-7)。フレーム表は、何も押さないことも含めて表のとおりに入力します。手順で押し続けているボタンも、表の間は表のとおりに離れ、表を抜けると戻ります
- 左端の「フレーム」は自動です。行の途中に挿しても番号は振り直されます。「回数」(その行を何フレーム分くり返すか)を入れると、左端はフレームの範囲になります
- 長いフレーム表は、「行を」の前の欄に **100** を入れて「末尾に追加」を押すと、まとめて増やせます。同じ入力が続くだけなら、行を増やすより「回数」に数を入れる方が、表が短く済みます
- 数値の欄は右端の**上下ボタン**でも増減できます。マウスポインターを合わせると、入れられる範囲が出ます。範囲を超える値は、欄を離れたときに上限か下限に修正され、修正したことがそのセルのすぐ下に出ます。数として読めない値(「1e」など)は、元の値に戻して、そのことを同じ所に出します
- 数値を確定したあとの **Ctrl+Z**(または「元に戻す」)は、そのセルの値を戻します。打っている途中の Ctrl+Z は文字単位です
- キーボードでは、**Enter** で下、**Tab** で右のセルへ移ります。最後の行で Enter を押すか、右下のセルで Tab を押すと 1 行増えます。今の行の上への挿入は **Alt+Insert**、今の行の削除は **Alt+Delete** です(行の右端の「＋」は下に入れます)
- 保存ボタンと「未保存」「保存済み」の表示は表の上に固定されています。行が増えてもスクロールせずに保存でき、保存し忘れにも気づけます
- 上の「ジャイロ・加速度の列を表示」のチェックを外すと、ジャイロと加速度の列を隠せます(隠しても値は保存されます)
- 行の右端のチェックを外すと、その行を丸ごと飛ばせます(時間も消費しません)。左端のフレーム番号は自動で振り直されます。セルで **Ctrl+/** を押しても切り替わります
- 作ったフレーム表は、手順の「**フレーム表**」ブロックから選べます

同じ値を縦に続けたいとき(スティックを倒したままボタンを押すなど)は、3 通りのやり方があります。いずれも同じ列の中だけにコピーします。

| 操作 | やり方 |
|---|---|
| 範囲を決めてコピー | セル右下の小さな **■** を上下にドラッグ |
| 1 つずつ下へ | セルで **Ctrl+D**(すぐ上の値が入り、次の行へ進む。連打で連続) |
| 塗るように | **Alt** を押しながらセルを縦にドラッグ |

### 1-7. ジャイロについて

ジャイロには回転速度を表す生値を指定し、そのまま装置へ送ります。長さはフレーム数で指定します。フレーム表では「ジャイロ」の「縦」「横」「ひねり」の列(CSV では `GY`、`GR`、`GP`)に入れます。較正は必要ありません。

「30 フレームで 90°回す」のような角度の指定はありません。ゲームが入力に補正(平滑化、不感帯、加速カーブ)を掛けていると、「生値 × フレーム数」と画面の回転角が比例しないので、角度で指定しても、その角度にはならないためです。

使い方はほかの入力と同じで、実際に試して合う値を見つけ、そのフレーム表を使い回します。値を大きくするほど速く回ります(上限 32767)。目安は、生値 1 で毎秒約 0.07° です。付録「ジャイロの実測記録」と同じ測り方で、2000 を 4 秒送るとカメラが約 1.6 周したことから出した値で、ゲームの補正によって変わります。

軸の対応(本体を水平に構えたとき):

| 列(CSV の列名) | 動き | 確認の状況 |
|---|---|---|
| 縦(GY) | 上下に振る。カメラの上下。正 = 下向き | 実機で確認した |
| 横(GR) | 左右(水平)に振る。カメラの水平回転。正 = 左回り | 実機で確認した |
| ひねり(GP) | ロール | 確認していない |

> 上下(縦)の回転は、水平の回転と違い、重力で基準の向きが決まる軸です。装置は加速度として、いつも「水平に置いて静止」を送ります。そのため、回し終えるとカメラは水平へ戻されます(実機で確認)。見下ろしを保ちたいときは、下向きの値を、ゆらぎを付けて送り続けます。上下に制限の角度があるゲームでは、そこで止まって安定します(実機で確認)。制限の角度がないゲームで見下ろしを保つには、傾いた向きの重力を加速度の列で送る必要があります。この使い方は確認していません

手順のほうでは「**ジャイロ**」ブロックで同じことができます。**長さ(フレーム)** を入れると、その長さだけ回して自動で止まります(「押して離す」と同じ形。こちらが基本です)。長さを 0 にすると、次のジャイロブロックまで同じ値を送り続けます。長さ 0 のブロックにはゆらぎを付けられないので、60 フレームを超えて回すときは長さを指定します(次の段落)。

完全に一定な値を長く送り続けると(実測では 70〜75 フレームを超えたあたりから)、途中で回転が止まります。一定の回転が、センサーのずれとして補正されるためとみられます。ジャイロブロックの「ゆらぎを付ける」は、素の値を 60 フレーム続けるたびに +7 と −7 を 2 フレームずつ対で入れて、これを防ぎます。このチェックは、ブロックを置いたときから入っています。値の根拠は付録「ジャイロの実測記録」にあります。

- ゆらぎを入れても、送る値の合計は「値 × 長さ」に一致します(+ と − を同じフレーム数ずつ対で入れるため)。ゲーム画面の回転角は、ゲーム側の補正で変わります
- フレーム表は書いた値をそのまま送ります(ゆらぎが必要なら、列に手で書きます)

> 加速度(`AX`、`AY`、`AZ` の列)は、通常は空欄のままにします。空欄には、水平に置いて静止したときの値(AX = 0、AY = 0、AZ = 4096)が入ります。加速度センサーは重力も測るので、静止していても `AZ` に 1G(= 4096)が出ます。3 つとも 0 にすると自由落下と同じ値になります。重力の向きから基準の姿勢を決めるゲームでは、ジャイロを送っても向きが変わらなくなることがあります。

### 1-8. 手で動かした操作を下書きにする

ゼロから表を書く手間を省きたいときは、**自分で操作して記録**できます。

1. 「実行・監視」タブを開く。装置が 2 台以上なら「手動操作の対象」で装置を選ぶ
2. **手動操作を開始** を押す。PC のゲームパッド、なければキーボードか、画面のコントローラー図のクリックで操作します。操作中は手動操作のカードが緑の枠になり、画面の見出しに「手動操作中(1P)」が出ます
3. **記録を開始** を押し、実際に操作してから **記録を停止** を押す
4. 記録した量(「86 フレーム」)と「**フレーム表として保存**」ボタンが現れるので、押して名前を付ける。保存しないまま「記録を開始」を押すと、記録を破棄してよいかの確認が出ます
5. **手動操作を終了** を押す
6. 「フレーム表の編集」タブで細かく修正する

※ 記録できるのは手動操作で自分が送った入力だけです(手動操作を開始するまで「記録を開始」は押せません)。記録したまま手動操作を終了すると、記録も停止します(記録したぶんは保存できます)。別のタブや見出しの「手動操作を終了」で手動操作を終了したときも同じです。記録は padcue 全体で 1 つなので、別のタブが記録している間は「記録を開始」を押せません。画面を閉じたり読み込み直したりすると、その画面の記録は破棄されます(保存していなければ、離れる前に確認が出ます)。

記録は **1 秒あたり約 60 回**(ほぼ 1 フレームごと)取ります。時刻は操作画面の時計で取るので、押した時刻は少しずれることがあります。先頭と末尾の何も押していない時間は残りません。下書きとして使い、仕上げは表で修正してください。

### 1-9. 手動操作の入力が反映される範囲

手動操作を開始すると**コントローラーの図**が出ます。図のボタンは **クリックしている間だけ**押されます。スティックは、周囲の矢印を押すとその方向へ最大まで倒れ、中央の丸を押すと押し込みになります。マウスでは、一度に 1 つしか押せません。キーボードやゲームパッドで押している間も、図の同じボタンが光ります。

| 入力 | 反映される範囲 |
|---|---|
| コントローラー図(マウス) | 「実行・監視」の画面にいる間 |
| キーボード | 「実行・監視」の画面で、コントローラーの図か、画面の何もない所を押してから、ほかの欄やボタンを押すまで |
| ゲームパッド | 操作画面のどのタブでも |

手動操作は別のタブ(手順の編集など)へ移っても**継続します**(ゲームパッドで操作しながら手順を眺められます)。ブラウザーから**フォーカスが外れる**(別のアプリを前面にしたときなど)と、安全のため**全ボタンを離した状態**を送ります。記録している間なら、記録にもその間は離した状態として残ります。操作画面を**閉じたり読み込み直したりすると、手動操作も終わります**(押していた入力を Switch に残しません)。

装置が 2 台あるときは、手動操作を続けたまま「手動操作の対象」を選び直せます(前の装置は全ボタンを離した状態にしてから操作を終え、新しい装置へ移ります)。切り替えている短い間だけコントローラーの図が薄くなり、入力を受け付けません。記録中は選び直せません。記録は 1 台の操作を並べたものだからです。自動実行している装置は手動操作を受け付けないため、選択肢が灰色になります。割り当てを解除した装置も、送る先が決まっていないため選べません。

### 1-10. ジャイロの入力が反映されないときの切り分け

1. **ゲーム側の設定**を確認する(ジャイロ操作が ON か、感度、試す画面)。
2. 装置の行の ⋯ の「状態を表示」で「ジャイロ」の行を見る。「本体からの有効化なし」なら、送る値以前に Switch が読んでいません。装置の行の ⋯ の「USB を再接続」で認識からやり直させて、確認し直してください
3. **大きい値で試す**。横を **2000**、長さを 60 フレームのようにします。小さい値は、ゲーム側の不感帯に入って見えないことがあります
4. **軸を 1 つずつ試す**。縦(上下。正 = 下向き)と横(水平の回転。正 = 左回り)は、実機で確認してあります。ひねりは確認していないので、使う前に動かして対応を確認し、逆に回ったら符号を反転してください

一定の値を送り続けると途中で回転が止まり、送るのをやめると元の向きへ戻ります。ジャイロブロックの「ゆらぎを付ける」で防げます(1-7)。ゆらぎなしで一定の値が 60 フレームを超えて続く手順には、編集している間に警告が出ます。測定の記録は付録にあります。

## 2. 長時間実行する

周回数を上げる前に 2〜3 周動かすと、周の境で手順がずれないかを確認できます。

長時間実行するときは、Switch の自動スリープを「しない」にしておくことを推奨します。スリープに入ると、操作が送れなくなります。通知と本体の自動更新も OFF にしておくことを推奨します。割り込みで手順がずれるためです。

`padcue.bat` を開いている間は、どれかのレーンが実行中か選択待ちのとき、padcue が PC の自動のスリープを防ぎます。画面の消灯は防ぎません。Windows の電源の設定を変える必要はありません。実行中の装置が未検出になっても、スリープは防いだままにします。Wi-Fi が一時的に切れただけなら装置は動き続けていて、終わりの通知を受けるには PC が起きている必要があるためです。

- 周回数は、レーンと手順の組ごとに覚えます。初めて選んだ手順では 1 です
- 回数を決めたいときは数を入れます(その回数で自動的に停止します)
- 欄を空欄にすると、停止するまでくり返します。「区切りで停止」か「停止」で終えるか、「区切りで停止」の ▾ で、終える周を決めます(2-4)

1. **周回数** に実行したい回数を入れて **開始** を押す
2. 途中で停止したくなったら **区切りで停止** を押す(次の区切りまで動かしてから停止します。ゲームの中で停止してよい場所にラベルを置いておきます)
3. すぐに停止するときは **停止** を押すか、装置の上面のボタンを 1.5 秒長押しする

> **PC 側を終了しても、装置の実行は停止しません。** 停止するなら先に「停止」を押すか、装置の上面のボタンを 1.5 秒長押しします。PC 側の終了は、`padcue.bat` が開いたウィンドウで Ctrl+C を押します。続けて Y/N を聞かれたら、どちらで答えても構いません。
>
> ふたを閉じるなどで PC がスリープしても、Wi-Fi が切れても、装置だけで進められる部分は続きます。PC が必要なのは、分岐の選択(手動・条件・スクリプトの結果)、合流点、スクリプトのブロックです。PC とつながっていない間、装置はそこで待ち続けます。「時間切れ」は装置が数えるので、付けてあれば、PC とつながっていなくても時間切れで先へ進みます。

手順・フレーム表・条件を編集している間も、動いている装置と異常停止した装置は、画面の見出しに「1P 実行中」「2P 選択待ち」「2P 異常停止」のように出ます。押すと、実行・監視のその装置のレーンへ移ります。見出しには停止ボタンを置いていません。停止するときはレーンで停止します。

動いている装置との接続が途切れて「未検出」になると、レーンに「装置との接続が途切れました。動作状態を確認できません。」と、最後に状態を確認した時刻と状態(「最終確認 07:00:46(実行中)」)が出ます。装置は動き続けているかもしれません。「停止」か「区切りで停止」を押すと、接続が戻ったときにその止め方を送ります。押した「区切りで停止」は、戻るまでの間も「予約を取り消す」で取り消せます。未検出になる前に装置が受け取っていた予約は、接続が戻るまで取り消せません。すぐに停止するときは、装置の上面のボタンを 1.5 秒長押しします。

装置の行の ⋯ の「状態を表示」で、次の項目を見られます。

| 項目 | 目安 | 意味 |
|---|---|---|
| 最大遅延: フレーム処理 | 200µs 以下 | 入力を切り替える処理が、予定の時刻からどれだけ遅れて動いたかです |
| 最大遅延: 読み取り待ち | 5〜8ms 程度 | 入力が変わってから、その値を USB へ渡せるまでの時間です。前の値を Switch が読みに来るまでは渡せないので、Switch が読みに来る間隔で決まります。Switch 2 の本体での測定では、読みに来る間隔は平均 5.8ms、最大 8ms です([hardware-design.md](design/hardware-design.md) §1-1)。1 フレームの長さを超えると、下の「⚠ 超過 N 回」に数えられます |
| 送信失敗 | 出ない | 装置が USB で Switch へ送れなかった、応答と通常入力の件数です。ゲームで入力が欠けたかは、この値だけでは分かりません |
| Switch 登録が「⚠ 未完了」 | 出ない | 本体がこの装置の登録を終えていません。入力が無視されることがあります(「登録が未完了のとき」) |

最大遅延の行の「⚠ 超過 N 回」は、フレーム処理の遅れが 200µs を超えた回数と、読み取り待ちが 1 フレームの長さを超えた回数の合計です。ゲームがどのフレームで入力を読んだかまでは分からないので、入力が実際にずれたかは、この値だけでは分かりません。

### 2-1. 終わったことを知らせてもらう(通知)

実行の完了や異常停止を、音や通知で知らせることができます。右上の **⚙** を押すと、「通知」の欄に、場面を行、知らせ方を列にした表が出ます。

| 場面 | いつ |
|---|---|
| **完了** | 指定した周回数を終えたとき |
| **異常停止** | 装置が異常を報告して停止したとき |
| **選択待ち** | 人が選ばないと進まない選択待ちに入ったとき |
| **未検出** | 実行中の装置から応答がなくなったとき |

| 知らせ方 | どうなるか |
|---|---|
| **音** | 場面ごとに音の種類と音量を選べます(「♪」でその場で聴けます)。ゲームの音に紛れて気づきにくいときは「ピピピッ」が聞き取りやすいです |
| **タブに表示** | ブラウザーのタブ名が「padcue(完了)」のように状態を付けた名前になり、**タブのアイコンに色の点**が付きます(通常は藍色の丸だけ)。点の色は、選択待ちが橙、異常停止が赤、完了が緑、未検出が灰です。完了は画面に戻るまで、ほかはその状態が続く間出ています。状態が 2 つ以上あるときは、選択待ち、異常停止、未検出、完了の順に 1 つだけ出ます。別のタブを見ていても、タブ名が幅で切れていてもアイコンで気づけます。ただし操作画面のウィンドウがほかのアプリの後ろに隠れていると見えません(その場合は音も入れてください) |
| **Windows の通知** | Windows の通知を出します。操作画面のウィンドウが隠れていても、ブラウザーを閉じていても表示されます。設定は、どのブラウザーから開いても同じです(音と「タブに表示」は、このブラウザーだけの設定です) |

知らせ方は、場面ごとにそれぞれオンとオフを選べます(すべて切れば、その場面では何も起きません)。

> ブラウザーがタブを休止させると、音もタブの通知も停止します。Chrome の「メモリセーバー」と、Edge の「タブを自動的にスリープ状態にする」は、しばらく見ていないタブをスリープさせます。長時間の実行で音やタブの通知を使うなら、この画面のアドレスを、スリープさせないサイトへ追加してください(Chrome: 設定 > パフォーマンス > メモリセーバー > 「常にアクティブにするサイト」。Edge: 設定 > システムとパフォーマンス > 「常にこれらのサイトをアクティブに保つ」)。

- 自分で「停止」や「区切りで停止」を押して停止したときは鳴りません(押した本人が停止することを知っているため)。グループのほかのレーンが完了していれば、自分で停止したレーンがあっても、完了として鳴ります(「1P が完了しました」のように、完了したレーンの名前で知らせます)
- 選択待ちで鳴るのは人が選ばないと進まない分岐だけです。合流点の相手待ちや、条件やスクリプトで自動に選ばれる分岐では鳴りません
- グループで動かしているときは、グループのすべてが終わった時点で 1 回だけ鳴ります。動いている間に未検出になったレーンがあるときは、ほかのレーンがすべて完了した時点で、「1P が完了しました。2P は未検出のままです。」のように、完了したレーンだけを知らせます。途中で装置が起動し直して止まり方の分からないレーンがあるときも、完了したレーンだけを「1P が完了しました」と知らせます。未検出のレーンが後で戻っても、完了はもう一度は鳴りません
- 音は、そのブラウザーで一度どこかを押してからでないと鳴らせません(ブラウザーの決まり)。「開始」を押していれば満たされています

### 2-2. 画面の配色

右上の **⚙** の「配色」で選びます(選んだ配色は、このブラウザーに保存されます)。既定の「自動」は、Windows のライトとダークの設定に合わせて、藍のライトとダークを切り替えます。色の系統は **藍**、**墨**、**琥珀** の 3 つで、それぞれにライトとダークがあります。墨は色を状態の表示だけに絞った配色で、日中の長い作業に向きます。琥珀は地と線が暖色で、画面全体が暗めなので、暗い部屋に向きます。異常と注意と良好の色はどの系統でも同じで、変わるのは地と線と文字と強調の色だけです。

### 2-3. ログの見かた

画面の一番下の「ログ」に、装置で起きたことが日時つきで溜まっていきます。記録は `data\logs.jsonl` に保存されるので、操作画面を開き直しても残ります(5000 行を超えると古いぶんを別のファイルへ分け、分けた古いファイルの合計が 100MB を超えたら、古いものから削除します)。

| 色 | 意味 | 例 |
|---|---|---|
| 色なし | 通常の記録 | 「開始: サンプル(3 周)」、「完了: サンプル(3 周)」、「時間切れで進みました(4 秒)」 |
| **黄** | 気に留めるもの | 「⚠ フレームの処理が遅れました」、「⚠ Switch がスリープしたため、USB の通信が停止しました」 |
| **赤** | 異常 | 「⚠ 実行中にエラーが発生しました」、「⚠ Switch との USB 接続が切断されました」 |

**黄と赤が出ていないか**だけ見れば足ります。「フレームの処理が遅れました」は、入力を切り替える時刻が予定より遅れたことを表します。

溜まりすぎたら「**ログを削除**」ですべて削除できます(元に戻せないので確認が出ます)。「自動スクロール」にチェックが入っている間は、新しい行が来ると一番下へ動きます。読むために上へ戻すとチェックが外れ、位置は動かなくなります。一番下まで戻すと、またチェックが入ります。

欄には新しい方から 2000 行ずつ出ます。それより古い行は「**以前のログを表示**」で読みます。押すと、古い行が欄の上に足され、足した行のうち最も新しい行まで戻ります。「自動スクロール」のチェックは外れます。装置で絞り込んでいるときは、その装置の行が出るまで読みます。

### 2-4. 予定より早く周回を終える

実行の途中で、この周で終えたくなったら、**区切りで停止** の右の **▾** を押して、終え方を選びます。周回数のくり返しの後ろに書いたブロック(後処理)まで実行して終わります。実行を途中で停止する「区切りで停止」とは別の操作です。

| 手順の書き方 | 出る項目 |
|---|---|
| 「最後の回」も「残り n 回」も使っていない | 「3 周目で終える」 |
| 周回数のくり返しを指す「最後の回」を使っている | 「4 周目を最後の回にして終える」「今から最後の回にして 3 周目で終える」「最後の回を飛ばして 3 周目で終える」 |
| 周回数のくり返しを指す「残り n 回」を使っている | 「4〜6 周目を残りの回にして終える」など、残りの回で同じ 3 つ |
| 周回数のくり返しを指す「最後の回」と「残り n 回」の両方を使っている | 「4〜6 周目を残りの回と最後の回にして終える」など、残りの回と最後の回で同じ 3 つ。最後の回は残りの回の最後の 1 回なので、飛ばすと両方を飛ばします |

- 「4 周目を最後の回にして終える」は、今の周には手を加えず、次の周を最後の回として実行してから終えます。最初から周回数を 4 にしたのと同じ動きです
- 「今から最後の回にして 3 周目で終える」は、今の周の残りを最後の回として実行します。押す前に通った分岐は普通の周のままです。次の選択待ちか周の境より前に「最後の回」の分岐を通るときは押せません(マウスポインターを合わせると理由が出ます)
- 「最後の回を飛ばして 3 周目で終える」は、最後の回を実行せずに今の周で終えます。最後の周で、最後の回の分岐をもう通った後は出ません(飛ばすものがないため)。次の選択待ちか周の境より前に分岐を通るときは、「今から」と同じく押せません

選ぶと、レーンの周回数が新しい値に変わり、進み具合もその周回数で出ます。開始時の警告も、その周回数で開始したときのものに替わります。メニューには「周回数を 100 周に戻す」のように、元の周回数に戻す項目が出ます(周回数が変わったときだけ)。選び直すこともできます。変えた周回数はその実行だけの物で、停止するとレーンの周回数の欄は開始したときの数に戻ります。

装置へ送った手順は途中で変えられないので、レーンは次の選択待ちか周の境で一度停止し、すぐ続きから始まります。選択待ちで停止したときは、その待ちをやり直すだけです(時間切れまでの残りは引き継ぎます)。スクリプトの実行中に選んだときは、スクリプトが終わってから停止するので、同じスクリプトを 2 度実行することはありません。ログと前回の実行には、続きも含めて 1 回の実行として残ります。

グループでは、見出しの **▾** から選び、全レーンを同じ周回数で終えます。

- レーンの **停止** か **区切りで停止** で停止したレーンは除き、残って動いているレーンで終えます
- レーンの周が揃っていないときは、今の周を指す「今から」と「飛ばして」は押せません。「4 周目を最後の回にして終える」のように周を数で指す項目は選べ、どのレーンもその周で終えます
- 続きは全レーンが停止してから始まるので、先に停止したレーンは、ほかのレーンが停止するまで待ちます(その間、レーンの状態のバッジは「合流待ち」と出ます)。選択待ちや合流点で停止したレーンは、その待ちの表示のまま残り、続きが始まるまで選択肢のボタンと「待たずに進む」は押せません
- 未検出のレーンがあるときは、そのレーンが戻るまで続きを始めません(戻らないときは **停止** を押します)。その間は終了予定を出しません
- 待つ間にレーンの **停止** か **区切りで停止** を押すと、そのレーンだけが元の周回数のまま停止し、続きには加わりません。ほかのレーンは選んだ終え方のまま続きを始めます。レーンの **区切りで停止** の予約を、続きが始まる前に **予約を取り消す** で取り消すと、そのレーンは押す前と同じく終え方に戻ります
- 一括操作の行の **▾** は、選んだレーンが属する動いているグループすべてが対象で、グループによって今の周か選べる終え方が違うときは押せません

選んだ後、続きが始まるまでに次のことが起きると、続きは始まらず、そこで終わります。先に止まって待っているレーンの装置のボタンを押したときも、表のとおりになります。

| 起きたこと | ほかのレーン |
|---|---|
| 見出しの **区切りで停止** を押した | 次の区切りで停止する |
| 装置の上面のボタンを短押しした | 押したレーンが区切りで停止した後の、次の区切りで停止する(押したレーンが先に止まって待っていれば、すぐ次の区切りで) |
| 見出しの **停止** を押した、装置のボタンを長押しした、異常停止した | すぐ停止する |
| 続きを始められなかった(装置が開始を拒否したときなど) | もう停止している |

どの場合も、ログと前回の実行には元の周回数で残ります。ただし、続きを始めるときにもう最後まで終えていたレーンは、選んだ周回数の完了として残ります。周回数が変わっていたレーンのログには、終わりの行の前に「周回数の変更: 3 周に戻す」のように出ます。続きを始められなかったときは、その行の代わりに、終わりの行に「周回の終え方を変更できずに停止」と出て、理由はレーンに出ます。

**▾** の「周回数を 5 周に戻す」のような項目を選ぶと、元の周回数で続けます。先に停止したレーンがあるときと、未検出のレーンがあるときは、全レーンが次の選択待ちか周の境で止まってから続けます。

## 3. 装置の更新と調整

### 3-1. ファームウェアを無線で更新する(OTA)

ファームウェアは無線で更新できます。Switch に**挿したまま**行えます。実行中の手順があれば先に停止します。padcue を更新した後、装置の行に「ファームウェアを更新してください」と出たら、この手順でファームウェアを更新します。装置のファームウェアのほうが新しく、「padcue を更新してください」と出たときは、padcue を更新します。この手順でファームウェアを古いバージョンへ戻すこともでき、そのときはダイアログに「現在のファームウェアより古いバージョンです」と出ます。

1. 装置の行の ⋯ の「**ファームウェアを更新**」を押す(ファームウェアの更新を求められているときは、行にも同じボタンが出ます)
2. 「リリースから自動的に取得する」のまま「**更新**」を押す。使っている padcue と同じバージョンのリリースから取得します。自分でビルドしたものやインターネットにつながらない PC では、「ファイルを指定する」で `-ota.bin` で終わるファイルを選びます
3. 進み具合のバーが終わると、装置が再起動します。戻ってくるのを待ちます

**確認**: ダイアログに「ファームウェア <バージョン> に更新しました」と出ること。

- 起動に失敗した場合と、新しいファームウェアが 1 分以内に Wi-Fi につながらない場合は、自動で前のファームウェアに戻り、ダイアログに「更新前のファームウェアに戻りました」と出ます。Wi-Fi につながらずに戻ったときは、ルーターの電源と、装置との距離を確認します。接続先を変えたばかりなら、行の ⋯ の「設定」で保存し直します。それから、もう一度更新します
- 再起動した装置が報告するファームウェアのバージョンが、更新に選んだバージョンと違うときは、「再起動した装置のファームウェアは <バージョン> で、選択したファームウェア <バージョン> と違います。もう一度更新してください。」と出ます

コマンドで更新するときは、padcue のリリースのページ(getting-started.md §1-1)で、使っている padcue と同じバージョンのリリースから `padcue-firmware-<バージョン>-ota.bin` を保存して、次を実行します。

```powershell
cd C:\path\to\padcue
$env:PYTHONPATH = "pctool"
python -m padcue ota C:\path\to\padcue-firmware-0.1.0-ota.bin
```

OTA の再起動の後、Switch が装置を認識し直さないことがあります。「状態を表示」の到達段階で判別し、次のように対処します。

- **0x7fb** なら、認識し直しています。そのまま使えます
- **0x400 のまま**(入力は送っているが、本体から問い合わせが来ていない)なら、認識し直していません。装置の行の ⋯ の「USB を再接続」で再接続し、到達段階が 0x7fb になることを確認します。変わらなければ、USB を挿し直します
- **0x000** なら、電源とケーブルを確認します

### 3-2. 長い手順のために、フレーム周期を合わせる

初期値は 60.00Hz です。Switch 側の周期が 59.94Hz 相当だと、長い手順の後半でだけずれます。

60.00Hz と 59.94Hz の差は約 0.1% で、1000 フレーム(約 17 秒)ごとに 1 フレームずれます。数フレームの余裕しかない操作なら、3000〜5000 フレームの手順で、はっきり失敗するようになります。短い手順では違いが出ないので、長い手順で試してください。

数千フレームの手順を実行して後半がずれるなら、装置の行の ⋯ の「設定」で「フレーム周期」を `59.94Hz` に切り替えて同じ手順を実行し、比べます。悪くなったら `60.00Hz` に戻します。ずれない方を採用してください。設定は電源を切っても残ります。

コマンドでは次のように切り替えます。

```powershell
python -m padcue config frame_period_ns 16683333    # 59.94Hz 相当
python -m padcue config frame_period_ns 16666667    # 60.00Hz
```

## 4. 2 台目を追加する(2 台同時運用)

> 2 台目にも、1 台目と同じファームウェアを書き込みます。2 台目の Switch 2 とドックとケーブルも、1 台目と同じように用意します。PC は登録した装置 ID(MAC)でしか装置を追跡しないため、2 台目が LAN に現れても勝手につなぎ替わることはありません。コマンドはすべて `padcue.bat` と同じ場所(リポジトリ直下)で実行します。

1. **ケーブルで書き込み、Wi-Fi を設定する**。2 台目も最初は操作画面の「＋ 新しい装置」から、ケーブルで書き込み、Wi-Fi を設定します(getting-started.md §1-1)
2. **登録する**: 操作画面を開いていれば、15 秒以内に、「＋ 新しい装置」のダイアログの「装置の検出」と、画面の左の「見つかった装置」に出ます。どちらかの「追加」を押すと、「2P」という名前で登録されます。追加するまでは動きません。どれが 2 台目か分からないときは、先に「見つかった装置」の行の「LED を点滅」で確認します。名前は、装置の行の ⋯ の「名前を変更」で変えられます(Switch 側のプレイヤー番号とは関係ありません)
   - コマンドで登録したいときは `python -m padcue device add <IP> 2P`
   - どちらも、接続して装置 ID を確認してから登録情報に追加します
3. **確認する**: `python -m padcue device list` で 1P と 2P の装置 ID が並ぶこと。`python -m padcue --device 2P status` が返ること。画面なら装置の一覧に 2 行、実行・監視には各装置 1 本ずつ、合計 2 本のレーンが出る
4. どの装置がどの Switch につながっているかは、自動で分かります
   - 装置を挿すと、Switch 本体が送る識別子を記録し、挿している間は装置の行に「本体 ID XXXX に接続中」と**自動で表示されます**。本体 ID は本体の Bluetooth のアドレスから作るので、本体ごとに異なり、装置を挿し直しても変わりません。左の「Switch 本体」に見つかった本体が並ぶので、行の右端の鉛筆のアイコン(名前を変更)で名前(例: リビングの Switch 2)を付けられます。名前は本体の識別子に付くので、装置をどの本体に挿し替えても、挿した本体の名前が出ます
   - ほかに、手動操作でボタンを押して反応した本体を見る方法と、装置に名前を書いたシールを貼っておく方法もあります
   - 装置の実物と画面の行の対応は、行の ⋯ の「LED を点滅」で確認できます(getting-started.md §2)

装置を交換すると、基板が変わるので装置 ID も変わります。

- 画面では、装置の行の ⋯ の「割り当てを解除」を押し、「見つかった装置」に出た新しい装置の「<名前> に割り当て」を押します。停止してから交換したときは、前回の実行と停止した位置が新しい装置へ引き継がれ、停止した位置から始め直せます(動いている間に見つからなくなった装置は、停止した所が分からないので引き継ぎません)
- 「割り当てを解除」を押せるのは、前の装置が見つからないときと、前の装置の IP に別の装置がいるときです。後者のときは、行に「別の装置(装置 ID XXXX)が接続されています」と出て、その下にも「割り当てを解除」が出ます
- 割り当てを解除しても、前の装置は停止しません。前の装置が手順を続けているときは、装置の上面のボタンを 1.5 秒長押しして停止します
- コマンドでは、`python -m padcue device forget <名前>` で割り当てを解除してから、`python -m padcue --device <名前> device <新しい IP>` で新しい装置を指します。解除しただけでは動きません。どの装置を使うかは、人が指すまで決まらないからです
- 登録そのものを削除するのは、装置の行の ⋯ の「登録を削除」(または `python -m padcue device remove <名前>`)で、割り当ての解除とは別の操作です。登録を削除しても、その装置は停止しません

模擬装置で試すときは `padcue-demo.bat` を使います。`demo\` フォルダーの登録情報を使うので、実機を何台登録していても、その登録情報は変わりません。

## 5. 2 台をグループにして動かす

2 台とも登録できたら(4 節)、実行・監視は装置ごとのレーン 2 本になります。一度に開始したレーンが、そのまま「グループ」になります。前もってグループを作る操作はありません。1 本だけで開始したときも、レーンが 1 本のグループとして始まります。

1. **選ぶ**: レーンの上に一括操作の行が出ます(レーンが 2 本以上のとき)。動かしたいレーンにチェックを入れます。すべて使うなら左端のチェックで一度に選べます
2. **開始**: 各レーンで手順・周回数・開始位置を選び、一括操作の **開始** を押します。選んだレーンが 1 つのグループになり、転送は自動で行われます。開始のずれ(ミリ秒)はログに残ります
3. **停止**: グループの見出しの **停止** か **区切りで停止** を押すと、グループのレーンすべてが停止します。レーンの中の **停止** と **区切りで停止** は、そのレーンだけを停止します(もう片方は動き続けます)。一括操作の行の **停止** と **区切りで停止** は、チェックを入れたレーンだけを停止します

片方だけを停止したレーンは、もう片方が動いている間も、手動操作と開始ができます。停止した後に片方のレーンだけを開始し直すと、そのレーンだけがグループから抜けます。もう片方は前のグループのままで、前回の実行の結果もそのまま残ります。

手順に合流点があるときは、抜ける前に確認します。続きを揃えて動かすつもりでレーンの開始を押すと、合流点で待ち合わせずに 1 台だけ先へ進むためです。一括操作の行でグループの一部のレーンだけを選んで開始したときも同じです。

- もう片方が停止しているときは、「グループ 1P・2P で開始しますか?」と確認します。「1P だけで開始」か「グループで開始」を選びます
- もう片方がまだ動いている間は、「1P だけで開始しますか?」と確認し、「グループで開始」は押せません

2 本以上のグループは枠で囲まれ、見出しに「グループ 1P・2P」と出ます。見出しの **開始**、**区切りで停止**、**停止** は、そのグループのレーンすべてを選んで押したのと同じです。周回の終え方の **▾** は見出しにだけあります(グループのレーンすべてを同じ周回数で終えるためです)。

グループは停止した後も残ります。レーンを別々に使いたいときは、見出しの **グループを解除** を押します。枠が消え、レーンはそれぞれ 1 本で使えるようになります。前回の実行の結果と停止した位置は、レーンごとにそのまま残ります。動いている間は押せません。

装置が自分で停止したら(完了、異常停止、装置の上面のボタン、別のツールからの停止)、残りも停止します(連動停止)。止まり方は、停止した 1 台の止まり方で決まります。画面かコマンドでそのレーンの **停止** か **区切りで停止** を押して停止したときは、そのレーンだけが停止し、残りは停止しません。停止したレーンは、合流点で待つ相手から外れます。表の「停止」と「区切りで停止」は、別のツールからの停止と、装置の上面のボタンの短押しで停止したときです。

| 1 台の止まり方 | 残りの止まり方 |
|---|---|
| 異常停止・停止・装置の上面のボタンの長押し | すぐ停止する |
| 区切りで停止 | それぞれの次の区切りで停止する |
| 完了 | 完了した 1 台と同じ周回数まで実行してから停止する |

完了で停止したときは、周回数が同じか少ないレーンは、自分の最後の回と後処理まで実行して完了します。周回数が無限か多いレーンは、完了した 1 台の周回数の周の終わりで停止し、最後の回と後処理は実行しません。その周をもう過ぎていれば、いまの周の終わりで停止します。揃って動いているレーンでは、完了を読み取るまでの間(1 秒ほど)に、残りが次の周へ入っていることがあります。そのときは、その次の周の終わりで停止します。揃えて終えるときは、どのレーンにも同じ周回数を入れるか、グループの見出しの **▾** で終え方を選びます。

連動停止の後に、ほかのレーンが停止したときも(完了したときを除く)、その止まり方に合わせたほうが早く停止するなら、残りはそれに合わせて停止します。たとえば、区切りで停止に連動して次の区切りへ向かう間に 1 台が異常停止すると、残りはすぐ停止します。周の終わりで停止する予約があるレーンで装置の上面のボタンを短押しすると、そのレーンは次の区切りで停止し、残りも次の区切りで停止します(画面のレーンの **区切りで停止** を押したときは、そのレーンだけが停止します)。

次の区切りや周の終わりで停止する予約があるレーンは、開始時刻の行に「連動停止 1P の完了で」のように原因が出て、タイムラインに止まる先の目印が出ます。

- レーンの「区切りで停止」は「予約を取り消す」に変わり、それを押すと予約を取り消せます
- グループの見出しと一括操作の行(チェックを入れたレーン)では、動いているレーンがどれも予約を持つときだけ「予約を取り消す」に変わり、押すとそれらの予約をすべて取り消します。周回の終え方には触れません(やめるときは ▾ の「周回数を 100 周に戻す」のような項目を選びます)。予約のないレーンが 1 本でも動いていれば「区切りで停止」のままで、押すと予約のないレーンにだけ予約します(予約のあるレーンはそのままです)
- 完了に連動して停止するレーンが、停止する周に入るのを待つ間は、目印はその周に入ってから出ます。終了予定は、待つ間も、その周の終わりで停止する時刻を出します
- 停止する所までの間に選択待ちがあるときは、目印は出ますが、終了予定は選んだ後に出ます(待つ長さで、停止する時刻が変わるためです)

「未検出」は連動停止のトリガーにしません(応答がないだけで、停止したとは限らないため)。

- 戻ったときに停止していれば、そこで残りも、その止まり方に合わせて停止します(完了していれば、完了した 1 台と同じ周回数まで実行してから停止します)
- そのレーンはグループに残り、合流点では相手として待ちます。相手が戻れば揃って進みます。戻らないときは、合流点の「時間切れ」まで待ちます(書いていなければ、人がグループを停止するまで待ちます)
- 未検出のレーンがある間に「停止」か「区切りで停止」を押すと、応答のあるレーンはすぐその止め方で停止し、未検出のレーンには、接続が戻ったときに同じ止め方を送ります。戻る前にそのレーンの割り当てを解除すると、送る予定の止め方は取り消されます。padcue を起動し直しても取り消されません
- 同じ装置を割り当て直したときに、装置がまだその実行を続けていれば、その実行の記録を続けます

進み具合を揃えたいときは、手順に「**合流点**」を置きます。同じ名前の合流点にグループの全員が来るまで待ち、揃ったら進みます。まだ来る可能性のあるレーンがなくなったら、待つのをやめて先へ進みます(相手が先に終わったときなど)。相手が停止して残りも連動停止で停止するときは、合流点を進まずにその場で停止します。もう後の周へ進んでいる相手は待ちません(残りの相手が揃えば進みます)。待ちきれないときのために、合流点には「時間切れ」を書けます。待っている間にレーンの「**待たずに進む**」を押しても、相手を待たずに先へ進めます(時間切れと同じ扱いです)。

画面で選びたいときは、「**分岐**」を置きます。止まって選択肢のボタンが出るので、レーンごとに選びます。人が選ばなくても進むように、選択肢に「時間切れ」を付けることも、画面を見て自動で選ばせることもできます(6 節)。

毎回同じ組み合わせで動かすなら、**プリセット**に残せます。残したいレーンにチェックを入れ、左の「プリセット」の **＋ 新規** で名前を付けます。手順、周回数、開始位置と、どのレーンを使うかが入ります。行を押すと各レーンに入るので、あとは開始を押すだけです。中身を今の設定に替えるときは、行の ⋯ の **上書き保存** を使います。プリセットかレーンが開始位置に使っているラベルを削除して手順を保存するときは、保存してよいかを確認します(そのプリセットとレーンは、開始位置を選択し直すまで開始できなくなります)。

実機なしで 2 台を試すには、`padcue-demo.bat` をダブルクリックします(getting-started.md §0-2)。別のフォルダーや台数で試したいときは、コマンドで同じことができます。

```powershell
cd C:\path\to\padcue
$env:PYTHONPATH = "pctool"
python -m padcue --project デモ3台 init
python -m padcue --project デモ3台 gui --mock 3
```

## 6. 画面を見て自動で選ぶ・スクリプトを実行する

「分岐」で人を待たせず、画面の見た目やコマンドの結果で自動的に選択肢を選べます。映像の判定とスクリプトの実行は PC で動く padcue が行うので、使う間は `padcue.bat` が開いたウィンドウを閉じないでください。ブラウザーの操作画面は閉じても判定は続きます(詳細は [specs/observe-and-decide.md](specs/observe-and-decide.md))。

### 6-1. 条件を作る(画面を基準画像として覚える)

先に、Switch 2 の映像を PC に取り込める状態にしておきます(キャプチャーボードと OBS など。OBS なら仮想カメラを開始しておきます)。映像機器(OBS の仮想カメラ、キャプチャーボード)から映像を取るには ffmpeg が必要です(`winget install Gyan.FFmpeg`)。デスクトップやウィンドウを映像ソースにするときは必要ありません。numpy と OpenCV も入れておきます(`python -m pip install numpy opencv-python`)。入っていないと、1 回の判定に数秒かかることがあり、短い間だけ出る画面を見逃すことがあります。装置の行の「映像」で、その装置の映像ソースを割り当てておくと、条件は「装置に設定している映像」で 1P でも 2P でも使えます。

1. 「条件の編集」タブの **＋ 新規** で名前を付ける
2. 「判定する映像」で映像を選ぶ(「装置に設定している映像」なら、横の「装置」で映す装置も選ぶ。OBS の仮想カメラ、デスクトップ、ウィンドウなどを直接選ぶこともできる)。右にいまの映像が出て、続けて更新されます
3. 判定したい場面をゲームで出し、**いまの映像を基準画像にする**を押す(見えている画像がそのまま左に入ります)。押した後は、その基準画像の小さな絵の「取得中」が消えるまで(4 秒ほど)、場面を変えずに待つ(基準画像を追加するたびに、続く 2 枚をしきい値の目安を求めるために、2 秒ずつ間を空けて取得します)
4. 基準画像の上で**範囲をドラッグ**して、見たい所を囲む(四隅をつまむと大きさを変えられる。囲まなければ画面全体を比べます。複数囲むと、すべての範囲が一致したときに一致になります)。いまの映像の同じ所にも同じ枠が出ます
5. 背景が違うなど、同じ場面に別の見え方があるときは、その画面で **いまの映像を基準画像に追加** を押す(いずれか 1 枚に一致すれば一致になります)
6. 一致してほしくない画面が出ているときに **一致しないはずの画面に追加** を押す(判定には使用せず、しきい値の目安を出すのに使われます)
7. 「一致度」と目盛りを見て**しきい値**を決める(しきい値の目安が出ていれば **適用**。大きいほど厳しく、小さいほどゆるく一致します)
8. **保存** を押す。選んだ映像、範囲、しきい値と一緒に、画像の追加と削除も反映されます。画像の追加と削除も、ほかの設定と同じく元に戻せます。

**確認**: 目当ての画面が出ているときに「一致度」の横が「一致」になり、別の画面では「不一致」になる。

装置の映像の切り出しを変えるなどして、基準画像といまの映像の縦横の比が違うと、正しく比べられないのでメッセージが出ます。そのときは基準画像を取り直します。

### 6-2. 選択肢に付ける(判断を自動にする)

1. 「手順の編集」タブで対象の「**分岐**」ブロックを選ぶ
2. 自動で進めたい選択肢の**選択条件**を「**条件**」にし、6-1 で作った条件を選ぶ(「**スクリプトの結果**」も選べます。コマンドの書き方は、下の「スクリプトの結果の決まり」にあります)
3. **保存** を押す

**確認**: 実行して選択待ちに入ると、条件が満たされたときは人が押さなくても続きが実行され、レーンの状態のバッジが「選択待ち」から「実行中」に変わる。ログにも「条件「…」で自動選択: 「…」」と残る。

選択待ちの間、PC は選択肢を上から順に調べ、最初に成立した選択肢へ進みます。どれも成立しなければ、もう一度調べます。選択肢が条件だけなら、調べ終えるとすぐに次を調べます。1 回にかかる時間は、比べる範囲が狭いほど短くなります。選択条件に「スクリプトの結果」を含むときは、調べ終えてから約 1 秒空けて次を調べ、そのコマンドもそのたびに実行します。このコマンドを待つのは、1 回の判定で合わせて 5 秒までで、5 秒を超えたコマンドは停止します。

「対象の回」がその回に当てはまらない選択肢は、調べる対象に入りません。選択肢は、選択条件が何であっても人が押せます。「時間切れ」の選択肢があれば、その時間でそこへ進みます。

**スクリプトの結果の決まり**: 選択条件を「スクリプトの結果」にすると、コマンドを実行し、終了コードが 0 のときにその選択肢へ進みます。当てはまらないときは、エラー出力に何も書かずに 0 以外で終わるようにします。起動できないとき、1 回の判定で合わせて 5 秒以内に終わらないとき、エラー出力に書いて 0 以外で終わったときは、判定できなかったものとして次の判定へ進みます。理由はレーンに出し、ログに残します。コマンドの出力は表示されません。

右上の **⚙** の「自動で進む待ち」を「非表示」にすると、人が選ばなくても進む待ちの行が出なくなります。待ちのたびに行が出たり消えたりして、下のボタンの位置が動くのを避けたいときに使います。対象は次の 3 つです。

- 選択肢がどれも条件、スクリプトの結果、時間切れのいずれかである分岐
- 合流点
- スクリプトのブロック

手動の選択肢がある分岐と、条件やスクリプトで判定できずに人が選ぶしかなくなった待ちと、待っている相手が未検出の合流点は、設定によらず出ます。スクリプトが終わらずに待ちが続くときは、「表示」に戻すと **待たずに進む** を押せます。設定はこのブラウザーに保存されます。

> 自動で進まないときは、条件のしきい値が厳しすぎるか、範囲がずれています。「条件の編集」タブで対象の条件を開き、いまの映像の一致度を見て、範囲としきい値を見直してください。実行は開始した時点の条件で判定するので、修正した条件は次の開始から使われます。いま待っている分岐は、選択肢を押して進めるか、停止して開始し直してください。

### 6-3. スクリプトを実行する

手順の中に、PC 上で任意のコマンドを実行するブロックを置けます。

1. 「手順の編集」タブで**スクリプト**ブロックを追加する
2. **コマンド**を入力する(例: `python scripts\collect.py`)
3. **完了待ち**を選ぶ。「完了まで待つ」(既定)は、スクリプトが終わるまで装置を止めます。「待たずに次へ進む」は、スクリプトを起動したら装置はすぐ次へ進みます
4. 必要なら**画像を追加**で映像ソースを指定する(実行前に PNG として保存され、環境変数 `PADCUE_CAPTURE_0`、`PADCUE_CAPTURE_1` … でスクリプトへ場所が渡される)
5. **保存** を押す

コマンドは、データのフォルダー(`padcue.bat` と同じ場所の `data\`)でシェル経由で実行されます。自分で書いたスクリプトは、その中の `scripts\` フォルダーに置きます。手順やフレーム表と同じく、git の管理の対象から外れます。結果の保存や画像からの文字の読み取りは、実行するスクリプトの側に書きます。

スクリプトブロックは、コマンドが終わると終了コードに関係なく先へ進みます(終了コードはログに残ります)。起動できなかったときと、5 分たっても終わらないときも、ログに残して先へ進みます。選択条件の「スクリプトの結果」に使うコマンドの決まりは、6-2 の「スクリプトの結果の決まり」にあります。

> スクリプトブロックと、選択条件の「スクリプトの結果」は、PC 上で**任意のコマンドを実行します**。手順は、ほかの人から受け取って使うこともできますが、**信頼できる手順だけ**を動かしてください。

## 7. padcue を新しいバージョンにする

実行を停止し、padcue を終了してから更新します(`padcue.bat` が開いたウィンドウで Ctrl+C を押します。ブラウザーを閉じるだけでは終了しません)。手順やフレーム表などのデータは、padcue のフォルダーの `data\` にあります。

- git で入手したとき: padcue のフォルダーで `git pull` を実行します。`data\` は git の管理の外なので、そのまま残ります
- ZIP で入手したとき: リリースのページ(getting-started.md §1-1)から新しいバージョンの ZIP を取得して別のフォルダーに展開し、前のフォルダーの `data\` を新しいフォルダーへコピーします

新しい padcue で `padcue.bat` を開き、装置の行に「ファームウェアを更新してください」と出たら、3-1 の手順でファームウェアも更新します。出なければ、ファームウェアはそのままで使えます。

| 症状 | 見るところ |
|---|---|
| COM ポートがない | ケーブルがデータ通信対応か確認する。装置が通常動作中なら、側面のリセットボタンを約 2 秒長押しして書き込みモードに入れる |
| つながらない・未検出 | 15 秒ごとに装置を検索し、接続先を更新するので、しばらく待つ。それでも見つからなければ、ルーターの AP 分離を切る |
| Switch が認識しない | getting-started.md §3-2 の「うまくいかないとき」の順に試す(有線通信を ON、bInterval を 8 にする) |
| 認識するが無反応 | 「状態を表示」の「Switch 登録」の行を見る(下の「登録が未完了のとき」) |
| Switch 登録が「⚠ 未完了」 | 本体がこの装置の登録を終えていません。入力が無視されることがあります(接続とジャイロの表示は正常のまま)。下の「登録が未完了のとき」の順に試す |
| 装置が勝手に再起動した | 「状態を表示」の「前回の異常終了」の行に、停止した場所が出ます |
| LED が赤 | 装置の行に出る停止した理由を見て、同じ行の「異常を解除」を押す |
| 実行が途中で停止する | 装置の行に停止した理由が出ていないか(Switch との USB 接続の切断、Switch のスリープ、Switch による装置の認識し直し、実行中のエラー。`python -m padcue logs` では `USB_UMOUNT`・`USB_SUSPEND`・`USB_MOUNT`・`ENGINE_FAULT`) |
| たまに失敗する | 1 フレームの入力があれば 2 フレーム以上にする。または周回数を 1 にして開始をくり返し、成功率を見る |
| 手順が思ったとおりに動かない | 実機の前にタイムラインを見る。ラベルを置いて途中から試す |
| 実行していないのに Switch が操作され続ける | 手動操作をしていた PC がスリープしたときなどは、装置が接続の切れたことに気づくまで(約 25 秒)、最後の手動操作の入力が続きます。すぐ停止するには、装置の上面のボタンを 1.5 秒長押しします。装置の電源を抜いて停止したときは、最後に押していたボタンの状態が Switch 側に残っている可能性があります |
| 画面の表示が古いまま | 「未検出」になっていないか(状態の文字が薄くなります) |

### 登録が未完了のとき

公開されている解析資料によると、本体は、登録の記録がないコントローラーに登録の要求を送り続け、終わるまで入力を無視します。「⚠ 未完了」はこの資料に基づく判定で、この判定と下の対処は、実機では確認していません([design/procon-protocol.md](design/procon-protocol.md) §9)。

「状態を表示」の「Switch 登録」の行が「⚠ 未完了」のときと、接続もジャイロも正常なのに操作だけ反映されないときは、上から順に試します。

1. 本体の「持ちかた/順番を変える」画面を開いたまま、USB を再接続する(装置を挿し直しても同じです)。登録は挿した直後に始まります。終わった合図は次の 3 つです
   - 「状態を表示」の「Switch 登録」の行が「受理済み」になる
   - 操作画面の装置の行から、「Switch への登録が完了していないため、…」のメッセージが **消える**
   - 本体の画面に Pro コントローラーが現れる
2. それでも未完了なら、実物の Pro コントローラーを同じ本体に有線で一度つなぎ、認識させてから、装置に挿し替える

## 付録

### LED の意味

| 色 | 状態 |
|---|---|
| 白 | 起動中 |
| 青 | Wi-Fi 接続中、または**接続が切れている**(起動を終えても青のままなら、Wi-Fi につながっていません) |
| **シアン**(水色) | 待機中(正常な待ち)。Wi-Fi につながっていることも表します |
| **緑(ゆっくり点滅)** | 実行中 |
| 黄 | 分岐の選択待ち、合流点で相手を待っている間、スクリプトの完了を待っている間 |
| **赤(点滅)** | 異常(解除するまで保持) |
| **白(速く点滅)** | 画面で「LED を点滅」を押した装置。5 秒たつと状態の色に戻ります |
| **白(ゆっくり点滅)** | 診断モードか、Wi-Fi の設定待ち。USB を開始していないので、Switch では使えません |
| 紫 | ファームウェア更新中 |

この表は、装置のファームウェアが点ける色です。書き込みモードの緑の点灯は基板の機能で、その間ファームウェアは動いていません(側面のリセットボタンの表を参照)。

### 装置のボタン

上面のボタン(LED と同じ面にある、押せるボタン)は、次のように使います。

| 操作 | 動作 |
|---|---|
| 短押し | 次の区切り(ラベル・周の境・選択待ち)まで動かしてから停止する。グループで動かしているときは、残りのレーンも次の区切りで停止する(画面のレーンの「区切りで停止」は、そのレーンだけを停止する) |
| 1.5 秒長押し | すぐ停止して全入力を離し、操作権を手放す。手動操作も終える |
| 押したまま電源を入れ、LED が白く光ったら離す | **診断モード**。LED が白くゆっくり点滅する。USB を開始しないのでシリアルのログが出続ける。Switch では使えないので、済んだらボタンを押さずに電源を入れ直す |

側面のリセットボタンは、次のように使います。

| 操作 | 動作 |
|---|---|
| 短押し | 再起動 |
| 約 2 秒長押し | 書き込みモード(緑 LED)。ケーブルで書き込み直すときに使う |

### ジャイロの実測記録

1-7 と 1-10 に書いた値と、「ゆらぎを付ける」の既定値(幅 7、2 フレームずつ、60 フレームごと)の根拠です。ジャイロでカメラの向きを変えるゲームで、送る値を変えながら、画面のカメラの動きを目で見て測りました。測ったゲームは 1 本で、補正をしているのが Switch 本体なのかゲームなのかは、確認していません。

- 一定の値を送り続けると途中で回転が止まり、送るのをやめると同じ速さで逆に回って、元の向きへ戻りました。実物のセンサーは、静止していても値が細かく揺れます。完全に一定な値はセンサーのずれと区別がつかず、少しずつ差し引かれているとみられます
- 値の変化が 13 未満だと、静止とみなされます。2000 と 2013 を 2 フレームずつ交互に送ると回り続け、2000 と 2012 では止まりました。10000 と 10013、10000 と 10012 でも境は同じで、境は値の大きさによりません
- 一定の値を送る長さを変えると、送り終えた後の戻りは、70 フレームでは出ず、75〜80 フレームでわずかに出て、90 フレームでははっきり出ました。差し引きは、一定の値が 70〜75 フレーム続いたあたりで始まります
- 値が変わり続けていれば、差し引かれません。2200 と 1800 を 2 フレームずつ交互に送ると、約 13 秒回り続けました
- ゆらぎの幅が 7 なのは、平均を変えない対称な対 ±d のうち、差 2d が 13 以上になる最小の d が 7 だからです(d = 6 では差が 12 で、静止とみなされます)。素の値を続ける長さの 60 フレームは、戻りが出始める長さより短く、60 フレームごとに対を入れる形で回り続けることを確認してあります。ほぼ全期間が素の値のままなので、揺れは画面では分かりません

### コマンド一覧

通常は `padcue.bat` をダブルクリックするだけです。コマンドで使う場合は、`padcue.bat` と同じフォルダーで `$env:PYTHONPATH = "pctool"` を一度実行してから次を使います(コマンドプロンプトなら `set PYTHONPATH=pctool`)。よく使うものを挙げます。すべてのコマンドは `python -m padcue --help` で見られます。

| コマンド | すること |
|---|---|
| `padcue.bat`(ダブルクリック) | 操作画面を開く(通常はこれだけ) |
| `padcue-demo.bat`(ダブルクリック) | `demo\` フォルダーで、模擬装置 2 台と一緒に操作画面を開く(デモ) |
| `python -m padcue gui` | 操作画面を開く(コマンドから) |
| `python -m padcue status` | 状態・USB・到達段階・遅延・送信失敗を表示(装置の行の「状態を表示」と同じ項目) |
| `python -m padcue logs` | 装置のログを取得 |
| `python -m padcue device auto` | `--device` で指定した装置(省略すると 1 台目)を探し、接続先を更新。操作画面は 15 秒ごとにすべての装置で自動で行う |
| `python -m padcue push <手順名>` | 転送だけ(実行しない) |
| `python -m padcue run <手順名> -n 10 -w` | 10 周を実行し、進捗を表示し続ける。Ctrl+C で装置も停止する |
| `python -m padcue run <手順名> --group 1P 2P` | 指定した装置を 1 つのグループとして開始。操作画面のサーバーが必要 |
| `python -m padcue select <番号>` | 選択待ちの選択肢を選ぶ(上から 1 始まり) |
| `python -m padcue lap-end <終え方>` | 実行中に周回数を変える(2-4。`end`・`next`・`now`・`skip`・`revert`)。操作画面のサーバーが必要 |
| `python -m padcue stop [--graceful]` | 停止(`--graceful` は区切りで停止) |
| `python -m padcue stop --cancel` | 区切りでの停止の予約を取り消す |
| `python -m padcue list` | 装置に入っている手順 |
| `python -m padcue export <名前>... [-o <フォルダー>]` | 手順を padcue ファイルにエクスポート。ほかのものを使わない手順 1 件は手順の `.json` になる |
| `python -m padcue import <ファイル> [--yes]` | padcue ファイル、手順の `.json`、フレーム表の `.csv` をインポート。同じ名前で中身の違うものは、番号を付けた別の名前で入れる。スクリプトのコマンドを含むファイルは `--yes` が必要。読めないものは理由を出して外し、残りを入れて、終了コード 1 で終わる |
| `python -m padcue --project <フォルダー> gui --mock <台数>` | 指定したフォルダーで、模擬装置と一緒に操作画面を開く。実機を登録したフォルダーでは使用できない |
| `python -m padcue config <キー> [<値>]` | 設定(`frame_period_ns`・`usb_binterval`・`wifi_ssid`・`wifi_pass`)。値を省略すると聞かれる |
| `python -m padcue clear-error` | 異常停止(赤 LED)を解除 |
| `python -m padcue ota` | ファームウェアを無線で更新 |
| `python -m padcue mock` | 模擬装置だけを起動する |

操作画面のサーバーが必要なコマンドは、`padcue.bat` を開いているときか、`python -m padcue gui --no-open` でサーバーだけを動かしているときに使えます。

装置が 2 台以上あるときは、`python -m padcue --device 2P status` のように `--device` で装置を指定します。省略すると 1 台目になります。ただし、装置を動かす `run`、`select`、`lap-end` は省略できません。並び順で決めると、選んでいない装置が動くからです。`stop` は省略すると、登録したすべての装置を停止します。
