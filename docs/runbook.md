# はじめての一台を動かすまで

**開封から、自分の手順で自動操作するまで**を上から順にやる手順書です。
ソフトウェアは完成しているので、この日にやるのは**組み立てと確認**です。

- 所要: おおむね **2〜3 時間**(うち待ち時間が半分)
- 各ステップの終わりに「**確認**」と「**うまくいかないとき**」があります
- 詰まったら最後の[困ったとき早見表](#困ったとき早見表)へ

---

## 全体の流れ

```text
0. PC の下準備     - 15分  Python と ESP-IDF が動くことを確認
1. 書き込む        - 20分  WiFi 設定 -> ケーブルで1回だけ書き込む
2. PC から見つける - 10分  無線でつながる確認(IP のメモは不要)
3. Switch に挿す   - 20分  本体設定 -> 挿す -> 認識を確認   <- 最大の関門
4. サンプルを動かす- 10分  自動操作が成立することを確認
5. 自分の手順を作る- 40分  ここが本番。作って試して直す
6. 放置運転にする  - 20分  周回数を上げて長時間まわす
```

**3 が通れば勝ちです。** 3 で失敗した場合の逃げ道も用意してあります(3 の「うまく
いかないとき **C**」= 保険モードへの切り替え)。

## 1. マイコンに書き込む

**先に WiFi を設定します。**あとから設定すると書き込みを2回することになります。

### 1-1. ESP-IDF を使える状態にする

Windows では **PowerShell** から使います(Git Bash からは動きません)。
PowerShell を開いて、上から順に貼り付けてください。

```powershell
Remove-Item Env:MSYSTEM -ErrorAction SilentlyContinue
. C:\path\to\esp-idf\export.ps1
cd C:\path\to\padcue\firmware
idf.py --version
```

**確認**: 最後の行がバージョンを答える(`ESP-IDF v5.5.5` など)。
**この PowerShell はこのあとも使うので閉じないでください。**

### 1-2. WiFi の SSID とパスワードを入れる

```powershell
cd ..\pctool
python tools/set_wifi.py
```

SSID とパスワードを聞かれます(パスワードは画面に出ません)。終わったら
`cd ..\firmware` で戻ります。

- **2.4GHz の SSID を使ってください。**5GHz にはつながりません
- 入れた値は `firmware/sdkconfig.defaults.local` に入ります(git には入りません)。
  **ビルド設定(`sdkconfig`)を作り直しても消えません**
- すでに `firmware/sdkconfig` がある状態で変えたときは、
  **`sdkconfig` を消してからビルド**してください(そうしないと古い値が残ります)
- 実機がつながったら、**実機本体にも保存**しておくと万全です:
  `padcue config wifi_ssid <SSID>` と `padcue config wifi_pass <パスワード>`
  (実機の保存領域が最優先で読まれるため、以後ビルド設定に関係なくつながります)

> **なぜ2か所に置くのか**: ビルド設定(`sdkconfig`)を作り直すと WiFi 設定は
> 消えます。そうなると実機がネットワークから見えなくなり、無線では直せません
> (ケーブルで書き込み直すことになります)。`sdkconfig.old` は「1つ前の版」で
> あって「動いていた版」とは限らないので、復旧の頼りにはできません。
> **実機本体にも保存しておけば、ビルド設定が消えてもつながります。**

> **つながらないときの見分け方**: マイコンのシリアルログに理由が日本語で出ます。
> 「パスワードが違う」なら 1-2 をやり直し、「その名前の WiFi が見つからない」なら
> **SSID の綴りと 2.4GHz かどうか**を確認してください。

### 1-3. ケーブルでつないで書き込む

**まだ Switch には挿さないでください。** PC につなぎます。

```powershell
idf.py -p COM5 flash monitor
```

`COM5` の番号は環境ごとに違います。**デバイスマネージャー**を開き
「ポート(COM と LPT)」にある番号に読み替えてください。

**確認**: ログが次の順に出ます。

```text
pademu fw 0.3.0 起動
...
IP取得: 192.168.x.x            <- この IP を控えておくと後で楽(必須ではない)
USB を開始します(ここでシリアルのログは終わります)
```

そのあと **`--- Waiting for the device to reconnect....`** と点が増え続けます。
**これで正常です。終わりません。`Ctrl+]` を押して monitor を閉じてください。**

本体の LED は **白 →(青)→ シアン** と変わります。

> ### ⚠ ここで知っておくこと
>
> **ログ(monitor)は「USB を開始します」で終わります。これは正常です。**
> このマイコンの USB は1つしかなく、USB を「コントローラー」として使い始めた
> 瞬間にシリアル通信(COM ポート)が消えるためです。
> monitor は消えた相手を待ち続けて `Waiting for the device to reconnect...` と
> 点を並べますが、**戻ってくることはありません**。`Ctrl+]` で閉じてください。
>
> - 以後のログは**無線で**見ます: `python -m padcue logs`
> - 2回目以降の書き込みは**無線でできます**(`padcue ota`)。ケーブル不要
> - どうしてもケーブルで書き込みたいときは**書き込みモード**に入れます:
>   **側面のリセットボタンを約2秒長押し**し、緑 LED が点いたら離す → COM ポートが復活

> ### うまくいかないとき
> | 症状 | 対処 |
> |---|---|
> | COM ポートが見えない | ケーブルがデータ通信対応か確認。書き込みモードに入れる(上記) |
> | `Waiting for the device to reconnect...` が続く | **正常**。`Ctrl+]` で閉じる |
> | `IP取得` が出ない(代わりに `WiFi 接続待ちタイムアウト`) | ログに**切断の理由が日本語で出ます**。「パスワードが違う」→ 1-2 をやり直す。「その名前の WiFi が見つからない」→ SSID の綴りと **2.4GHz** かを確認。直したら `sdkconfig` を消してからビルドし直す |
> | `WiFi 資格情報が未設定` と出る | 1-2 の `set_wifi.py` をやり忘れています |
> | 書き込みモード(緑 LED)から戻れない | **ソフトからは抜けられません。USB を抜き挿し**して電源を入れ直してください |
> | LED が光らない | LED は GPIO35 想定です。実機が違えば `firmware/main/app_config.h` を直す |

## 2. PC から無線でつながることを確認する

**IP を調べて覚えておく必要はありません。**
画面の「**探す**」ボタンが LAN から見つけて設定し、以後は個体ID(MAC)で
追跡します(IP が変わっても、探索が同じ個体を見つけ直します)。
マイコンは `pademu-<個体ID下4桁>.local` という名前も名乗ります(名前は
書き込み時のシリアルログに「名前で呼べます: …」と出ます)。

**`padcue.bat` をダブルクリック**して操作画面を開きます。

画面**左の「装置」パネル**に、装置の行があります。行の **▸** を押すと詳細が開き、
接続先・探す・接続がそこに集約されています。

```text
[>] * 1P                          <- 行を押すと詳細が開く(未接続・異常なら自動で開く)
    接続先 [192.168.x.x____] [探す] [接続]
             ^いまの接続先      ^         ^
             (手で書き換え可)  LANから    入力した接続先に
                              見つけて設定  切り替える
```

右の「実行・監視」のレーン上部の**状態チップ**(例: 待機中・未接続)を押しても、
この行が開いて対処の場所へ飛べます。

開いた直後は「**確認中…**」と出ます。数秒待つと結果が出ます。

1. チップが「**待機中**」になれば、それでつながっています。**何もしなくてよいです**
2. 「**未接続**」なら装置パネルの行を開き **探す** を押します(名前を引けない環境では
   **十数秒**かかることがあります)
   - すでにつながっているときに押しても**接続先は変わりません**
     (「いまの接続先でつながっています」と出ます)
   - 0-2 で練習した場合、接続先が模擬デバイス(`127.0.0.1`)に向いたままです。
     **ここで「探す」を押して実機に切り替えます**
3. それでも駄目なときだけ、1-3 で控えた IP を欄に入れて **接続** を押します
   - 欄を**空にして接続はできません**(接続先が消えると何も操作できなくなるため)

**確認**: レーンの状態チップが「待機中」になり、装置パネルの行を開くと下に次が出る。

| 項目            | 期待                                                         |
|-----------------|--------------------------------------------------------------|
| 状態            | 待機中                                                       |
| ファーム        | `0.3.0 (ota_0)`(版は更新のたびに上がります)                  |
| 方式            | `procon / bInterval=1`                                       |
| Switch との接続 | **つながっていません**(まだ Switch に挿していないので正しい) |
| ジャイロ        | **本体からの有効化なし**(Switch に挿すと本体が有効化する)    |

> ### うまくいかないとき
> | 症状 | 対処 |
> |---|---|
> | 「探す」でも見つからない | マイコンの LED がシアンか確認(青のままなら WiFi 未接続)。PC とマイコンが**同じ WiFi** か確認 |
> | 「返事はあるがつながらない」と出る | PC の仮想ネットワーク(VPN・仮想マシン)が答えています。接続先は変わっていないので、実機の IP を手で入れてください |
> | 同じ WiFi なのに見つからない | ルーターの「AP 分離(プライバシーセパレータ)」を切る |
> | IP が変わって面倒 | **気にしなくてよいです。**名前で呼ぶので追随します。変わっても「探す」で拾えます |

**コマンドで済ませたい場合**(GUI を使わずに確認したいとき)

```powershell
cd C:\path\to\padcue
$env:PYTHONPATH = "pctool"
python -m padcue device auto     # 探して接続先を覚える
python -m padcue status          # 状態を表示
```

### あわせて: PC 上で「コントローラーとして名乗れているか」を見る

Switch に挿す前にここを見ておくと、次で失敗したとき**マイコン側か Switch 側か**の
切り分けができます。

- デバイスマネージャーに **`Pro Controller`** という HID デバイスが現れていること
- 現れないなら Switch に挿しても無意味です。先に解決してください

## 3. Switch 2 に挿す

### 3-1. 先に本体設定を変える(**飛ばすと必ず失敗します**)

| # | 設定                                                                       | なぜ                                                                       |
|---|----------------------------------------------------------------------------|----------------------------------------------------------------------------|
| 1 | **設定 → コントローラーと周辺機器 → 「Proコントローラーの有線通信」を ON** | **工場出荷は OFF。** OFF のままだと USB コントローラーは一切認識されません |
| 2 | Joy-Con など他のコントローラーを**全部切断**                               | 繋いだままだと自作機が 2P になり「認識されたのに無反応」に見えます         |
| 3 | 本体 → 自動スリープを「しない」                                            | 長時間の放置運転で寝られると止まります                                     |
| 4 | 通知を OFF、本体の自動更新も OFF                                           | 割り込みで手順がずれます                                                   |

**1 が最頻出の失敗原因です。**必ず確認してください。

### 3-2. ドックの USB ポートに挿す

**ここから先、USB は Switch に挿したままにします。**
マイコンの USB は1つで、それを Switch に使うため、**PC とは無線でやりとりします**
(電源もドックから取ります)。PC 側の操作はすべて WiFi 経由です。

**確認**を上から順に:

1. 本体 LED が**シアン**のまま(= 電源 OK)
2. `python -m padcue status` で `USB: 接続 / 到達段階 0x7fb`
3. Switch の **設定 → コントローラーと周辺機器 → コントローラーの動作チェック** で
   「Proコントローラー」が **1台** 見えている
4. 動作チェック画面でボタンの反応を見る(まだ自動操作はしていないので反応はしません)

**到達段階**は「Switch との初期化がどこまで進んだか」です。失敗の切り分けに使います。

| 到達段階         | 意味                                         | 次にすること                                     |
|------------------|----------------------------------------------|--------------------------------------------------|
| `0x000`          | 何も届いていない                             | ケーブル・ポートを疑う。手順 2 の HID 確認へ戻る |
| `0x001`〜`0x00f` | 途中で止まった                               | `padcue logs` を保存して原因を追う               |
| `0x7fb`          | 正常に初期化完了                             | 次のステップへ                                   |
| `0x400` のまま   | 入力は送っているが本体から問い合わせが来ない | USB を挿し直す(§7-1)                             |

> ### うまくいかないとき(重要な分岐)
>
> #### A. まったく認識されない
> 1. **3-1 の 1(有線通信 ON)を再確認** ← ほぼこれです
> 2. Joy-Con を全部切ったか確認
> 3. USB の問い合わせ間隔を実在のコントローラーと同じにして再試行します:
>    ```powershell
>    idf.py menuconfig      # pademu -> bInterval を 8 にする
>    idf.py build
>    cd ..\pctool
>    python -m padcue ota
>    ```
>    これで動けば原因は「1ms 間隔が受理されない」ことです。
>    精度は少し落ちますが動きます。
>
> #### B. 認識されるが「2P」と出る
> 他のコントローラーが繋がっています。全部切って挿し直してください。
>
> #### C. どうしても認識されない → 保険モードに切り替える
> 単純な有線コントローラー(ホリパッド相当)として名乗る方式に切り替えます。
> **無線で切り替えられます。書き込み直しは不要です。**
>
> ```powershell
> python -m padcue mode hidpad
> ```
> 切り替えたら USB を一度抜き挿しします。戻すときは `python -m padcue mode procon`。
>
> | | プロコン方式 | 保険モード |
> |---|---|---|
> | ボタン・スティック | ○ | ○(スティックは 256 段階に粗くなる) |
> | ジャイロ | ○ | **×** |
>
> **保険モードで動けば、自動操作という目的は達成できます。**

## 4. サンプルを1回動かす

`padcue.bat`(実機)または `padcue-練習.bat`(模擬デバイス)の画面で:

1. 実行・監視のレーンにある **手順** のプルダウンで **サンプル** を選ぶ
2. **タイムライン**で「いつ何を入力するか」を目で確認する(ボタンだけでなく、ステ
   ィック・ジャイロ・加速度も、動かしている区間が帯で出ます)
3. **▶ 1回実行** を押す(周回の欄に何が入っていても1回だけ実行されます)
   - 実行が始まると、レーン見出しの**状態チップ**が「**実行中**」になります。プ
     ルダウンで別の手順を選んでも、チップと進行表示は**実際に動いている手順**を
     指したままです
   - 転送は自動です(マイコンの中身が古ければ勝手に送り直されます)
4. Switch 側で意図どおりに操作されることを確認

止めたいときは **⏹ 今すぐ止める**、または**本体のボタンを1.5秒長押し**。
タイムラインの**暗くなっている範囲が「もう流れたところ」**、
その先端の赤い線が今の位置です(実行中はこれが進みます)。

**◼ 今の周で止める** は「予約」なので、押すとボタンが色付きに変わり、
名前も「↩ 止める予約を取り消す」に変わります
——これが出ていれば効いています。今の周回が終わった時点で止まります。

**ここまで来れば「自動操作ができる」状態です。**

> ### うまくいかないとき
> | 症状 | 対処 |
> |---|---|
> | 実行はされるがゲームが反応しない | 3-1 の 2(他コントローラー切断)を再確認 |
> | 途中で止まる・LED が赤 | `padcue logs` を見る。解除は `padcue clear-error` |
> | ボタンは効くがスティックが効かない | 保険モードになっていないか `padcue status` で確認 |
> | 「実行中」のまま戻らず、実行も停止もできない | まず「**⏹ 今すぐ止める**」。それでも戻らない場合(古いファーム)は**本体のリセット短押し**か USB 挿し直し → 待機中になったらファームを更新する |

## 5. 自分の手順を作る

ここからが本番です。**画面だけで作れます。**ファイルを直接いじる必要はありません。

### 5-1. 考え方(これだけ覚えれば書けます)

手順は「**各フレームでどのボタンが押されているか**」の表です。

- 1 フレーム = 約 1/60 秒
- **「押す」は押して離すまで**を1つのブロックで表します
- **くり返しは、書いた区間をそのまま繰り返します。**押しっぱなしはくり返しの境目
  を勝手に越えません(越えさせたいなら、くり返しの**外**で押す)

### 5-2. 画面で組む

「**手順を編集**」タブ → **＋ 新規** で名前を付けます。似た手順は **複製** から
作ると早いです。**名前を変更**すると、その手順を呼んでいる側の参照も自動で直しま
す(部品も同様)。左の「追加するブロック」を押すと、**選択中のブロックの直後**に入
ります。

| ブロック                    | 意味                                                                                                | よく使う場面                       |
|-----------------------------|-----------------------------------------------------------------------------------------------------|------------------------------------|
| **ボタンを押す**            | 指定フレーム数だけ押して離す                                                                        | ほとんどの操作                     |
| **待つ**                    | 何もしないで待つ                                                                                    | ロード待ち、演出待ち               |
| **押しっぱなし** / **離す** | 押した状態を保つ / やめる                                                                           | ダッシュしながら移動               |
| **スティック**              | 傾きを指定(中心 0、左と下がマイナス)                                                                | 移動                               |
| **ジャイロ**                | 回転の**速さ**(生値)と**長さ**を指定。長さぶん回して自動で止まる(長さ 0 = 次に変えるまで回り続ける) | カメラを回す                       |
| **くり返し**                | 中身を N 回                                                                                         | 周回の中の連続攻撃                 |
| **ラベル**                  | 区切りの名前                                                                                        | **途中から試せるようになる**(重要) |
| **部品**                    | 細かい同時入力を表で(→ 5-6)                                                                         | コンボ                             |
| **待って選ぶ**              | 止まって人が選択肢を選ぶ                                                                            | 結果を見て分岐                     |
| **周回で分岐**              | 偶数周目だけ違う操作                                                                                | 交互に別の敵を狩る                 |
| **別の手順**                | 他の手順を呼ぶ                                                                                      | 共通部分の使い回し                 |

**コツ: 区切りごとに「ラベル」を置いてください。** 後半だけ試せるようになります。

**各ブロックには「メモ」を付けられます**(右の編集欄)。
「押して離す A を 2F  ステージを選ぶ」のように薄く表示されるので、
**ゲーム中で何をする操作なのかが一目で分かります**。変換には一切影響しません。

**ブロックの並べ替え・複製・削除**:

| したいこと       | 操作                                                                                                                            |
|------------------|---------------------------------------------------------------------------------------------------------------------------------|
| 並べ替え         | ブロック左端の **⠿** をドラッグ(**くり返しや分岐の中へも出し入れできます**。落ちる位置は線で出ます)。**Alt+↑/↓** でも動かせます |
| 好きな位置に追加 | 左のパレットから**ドラッグ**して置きたい場所へ(クリックだと選択中の直後に入ります)                                              |
| 複製             | ブロック右端の **⧉**                                                                                                            |
| 削除             | ブロック右端の **×**                                                                                                            |

どれも **Ctrl+Z** で元に戻せます。

**手順そのものの操作**(左の一覧):
名前の変更は **✎**、複製は **⧉**、削除は **🗑**(行にマウスを乗せると出ます)。
**⠿ をドラッグすると一覧の並べ替え**ができ、この並びは「実行・監視」タブと
共通です(よく使う手順を上に置けます)。部品の一覧も同じです。

**一部だけ抜いて試したいとき**: 各ブロックの右端にチェックがあります。
**外すとそのブロックは丸ごと飛ばされます**(その時間だけ待つ、ではありません)。
消さずに残せるので、戻すのもチェックを入れるだけです。
くり返しや分岐で外すと、**中身ごと**飛びます。

**消したいとき**: 各ブロックの右端(チェックの隣)の **×** で削除できます。
間違えて消しても **Ctrl+Z** で戻せます。

### 5-3. 保存して、タイムラインで確かめる

**保存**を押すと自動で変換され、危ない書き方があれば**警告**が出ます。

| 警告                       | 意味                               | どうするか                                                                                                                     |
|----------------------------|------------------------------------|--------------------------------------------------------------------------------------------------------------------------------|
| **1 フレーム**の押下・待機 | まったく拾われないことがある(約6%) | 2 フレーム以上にする。**わざと 1 フレームにしたい**なら、そのブロックの「**短さは意図的**」に印を付けると警告が消えます(→ 5-5) |
| 0 フレームで消える操作     | 押した瞬間に上書きされている       | 順番か長さを直す                                                                                                               |
| 周回の継ぎ目で衝突         | くり返しの最後と最初が矛盾         | 継ぎ目に「待つ」を入れる                                                                                                       |

**「実行・監視」タブに戻り、左の一覧で作った手順を選んでタイムラインを見てくださ
い。** (タブを移っても選択は引き継がれないので、一覧から選び直します)横が時間、
縦が入力(ボタン・スティック・ジャイロ・加速度)です。帯が出るのは**動かしている区
間だけ**です(加速度は静止でも重力ぶんの値が出続けるため、静止値 4096 から変えた
区間だけが帯になります)。**思ったところに印が出ていない=手順が違う**ので、実機で
試す前に気づけます。

### 5-4. 途中から試す(手戻りを減らす最大のコツ)

長い手順を毎回頭から流すと時間を無駄にします。

1. 「実行・監視」タブの **開始ラベル** で、試したいラベルを選ぶ
2. **▶ 1回実行** を押す

選んだ位置から**すぐに**始まります(飛ばした前半ぶんは待ちません)。
押しっぱなしなどの状態も引き継がれるので、途中から始めても入力は正しくなります。

### 5-5. 「たまに失敗する」ときの考え方

**入力の長さは ±1 フレームぶれます。**Switch が入力を読むタイミングと、
こちらが切り替えるタイミングがズレるためです(設計文書 A-1)。

| 指示       | 実際にゲームが見る長さ | 起こること                             |
|------------|------------------------|----------------------------------------|
| 1 フレーム | **0〜2**               | **まったく押されないことがある**(約6%) |
| 2 フレーム | 1〜3                   | 押されはする。長さがぶれる             |
| N フレーム | N−1〜N+1               | 同上                                   |

**「押されない」が起きるのは 1 フレームのときだけ**です。だから警告も
1 フレームのときにしか出しません。

対処は2つです。

1. **2 フレーム以上にする**。「押されない」はこれで無くなります
   (長さが要る操作なら、その前後に余裕を持たせます)
2. **成功するまで繰り返す**。1 フレーム精度が要る検証はこちらです

**わざと 1 フレームにする場合**は、そのブロックの「**短さは意図的**」に印を付け
てください。以後そのブロックでは警告が出なくなります(意図した短さと、書き間違い
を区別するための印です)。

成功率を確かめたいときは、**▶ 1回実行** を何度か流して結果を見比べてください。

### 5-6. 細かい同時入力は「部品」で書く

「A を押しながら 3 フレーム後に B、同時にスティックを左」のような密な入力は、
ブロックを並べるより**表**の方が速くて読みやすいです。

「**部品を編集**」タブ → **＋ 新規** → 1 行 = 1 フレームで埋めます。
**すべてのボタン・スティックの列が最初から並んでいます**(列を足す操作はありません)。

```text
フレーム   A    B    ZL   ... LX
   1      ON                        <- A を押す
   2      ON
   3      ON   ON   ON      -1200   <- A・B・ZL を押しつつスティック左
   4      ON        ON      -1200
   5                                <- 全部離す
```

- **ボタンはクリックで切り替え**ます。**押したままドラッグ**すると連続したセルを
  まとめて塗れます
- 押しているセルだけが色付きの `ON` になります。押していないセルは**空欄**です(`OFF`
  を並べると、どこを押しているのか形で追えなくなるため)
- スティックなどの数値は直接入力します(中心 0、左と下が負)
- **空欄は「離す/0」**です。画面で作った部品は**すべての入力を明示**するので、「書
  いていない入力が直前のまま残る」ことはありません
- 左端の「フレーム」は自動です。行の途中に挿しても番号は振り直されます。`rep`(そ
  の行を何フレーム分くり返すか)を入れると、左端はフレームの範囲になります
- 長い部品は「末尾に **[100]** フレーム 足す」でまとめて増やせます(同じ入力が続
  くだけなら `rep` に回数を入れる方が軽く済みます)
- 数値の欄は右端の**上下ボタン**でも増減できます(普通の数値入力)。**ホバーすると
  入れられる範囲**が出て、範囲外は欄を離れたときに自動で端へ寄せます(何をしたか
  は下に出ます)
- **同じ値を縦に続けたいとき**(スティックを倒したままボタンを押す等)は3通りあり
  ます。いずれも**同じ列の中だけ**にコピーします:

| 操作               | やり方                                                        |
|--------------------|---------------------------------------------------------------|
| 範囲を決めてコピー | セル右下の小さな **■** を上下にドラッグ                       |
| 1つずつ下へ        | セルで **Ctrl+D**(すぐ上の値が入り、次の行へ進む。連打で連続) |
| 塗るように         | **Alt** を押しながらセルを縦にドラッグ                        |
- **保存ボタンと「未保存/保存済み」は表の上に貼り付いています**。行が増えても
  スクロールせずに保存でき、保存し忘れにも気づけます
- ジャイロ・加速度の列は畳めます(上のチェックで開閉。畳んでも保存はされます)
- **行の右端のチェックを外すと、その行を丸ごと飛ばせます**(時間も消費しません)。
  左端のフレーム番号は自動で振り直されます
- 作った部品は、手順の「**部品**」ブロックから選べます

### 5-6b. ジャイロについて

ジャイロは**生値(1フレームあたりの回転速度)をそのまま送るだけ**です。
部品の `GP`/`GY`/`GR` 列に入れれば、そのまま実機へ送られます。**較正は要りません。**

**「30 フレームで 90°回す」のような角度指定はありません。**
たいていのゲームは入力に補正(平滑化・不感帯・加速カーブ)を掛けるので、
「生値 × フレーム数」と画面の回転角が比例せず、角度で書いても当たらないためです。

使い方は他の入力と同じで、**実際に試して合う値を見つけ、その部品を使い回します**。
値を大きくするほど速く回ります(上限 32767)。目安は **生値 1 ≒ 0.07°/秒**で、
**実機で確認済み**です(2000 → 約140°/秒。4秒回して約1.6周を観測)。

軸の対応(実機で確認済み。本体を水平に構えた基準):

| 列 | 動き                                                 | 確認状況                                                                     |
|----|------------------------------------------------------|------------------------------------------------------------------------------|
| GR | **左右(水平)に振る = カメラの水平回転。正 = 左回り** | **実機確認済み**                                                             |
| GY | **上下に振る = カメラの上下。正 = 下向き**           | **実機確認済み**                                                             |
| GP | ひねる/傾ける(ロール)                                | 未測定(現行ゲームでは測れない。左右・上下と同仕様と仮定し、反例が出たら訂正) |

> **上下(GY)の注意**: 水平回転と違い、上下は重力で「正しい向き」が決まる
> 軸です。こちらの加速度は常に「水平に静止」を報告しているため、**回し終える
> と**本体側の重力補正でカメラは水平へ戻されます(実機で確認)。
> 見下ろしを**維持したい**場合は、下向きの信号を(ゆらぎ付きで)**送り
> 続けて**ください — 上下には制限角度があるゲームなら、そこで頭打ちになって
> 安定します(実機で確認)。制限角度のないゲームで維持が必要になったら、
> 傾いた重力を加速度で送る方式を検討するので相談してください

手順のほうでは「**ジャイロ**」ブロックで同じことができます。
**長さ(フレーム)**を入れると、その長さだけ回して**自動で止まります**
(「押して離す」と同じ形。こちらが基本です)。
長さを 0 にすると、次のジャイロブロックまで回り続けます。

**ゆらぎ(既定オン・間欠方式)**: 完全に一定な値を 60F を超えて送り続けると、
Switch 側の**ゼロ点自動較正**に「センサーのずれ」として吸収され、回転が
止まり・終了後に逆回転が起きます(実機で実測)。ジャイロブロックは
これを防ぐため、**素の値を「間隔」フレーム続けるたびに、+幅/−幅 を
「1回の長さ」フレームずつ対で入れて**送ります(既定: 幅 7・1回の長さ 2F・
間隔 60F。「60F 保持 → 2F 変化」の繰り返しで回転が持続することを実機で確認
済みの方式)。

- **合計の回転量は「値 × 長さ」に正確に一致します**(+と−を同じフレーム数
  ずつ対で入れるため補正が要らず、一定連続はどこも 60F 以下になるよう組む)
- **幅 7 の導出**: 実測された「静止」判定の境界は**隣り合う2値の差が 13**
  (値 2000 でも 10000 でも同じ = 絶対閾値)。平均を厳密に保つ対称の対は
  ±d の形で、差 2d ≥ 13 → **d = 7 が最小**(d = 6 は差 12 で吸収される)。
  逸脱を最小にするのは、ゲーム側に未知の非線形補正があっても平均のずれを
  最小にするため。ほぼ全期間が素の値のままで、揺れは知覚できません
- **間隔 0** にすると常時 ± 交互(値が細かく変わるぶんイベント消費が増える)
- 部品は生値をそのまま送ります(ゆらぎが要るなら列に手書きします)

> **加速度(`AX`/`AY`/`AZ` 列)を 0 にしないでください。**
> 加速度センサーは重力も測るので、静止していても `AZ` に 1G(=4096)が出ます。
> 全部 0 は「自由落下中」という実機では起こらない状態で、多くのゲームは
> 重力の向きから基準の姿勢を決めるため、**ジャイロを送っても向きが変わらなく
> なることがあります**。空欄にしておけば自動で 4096 が入るので、
> 傾きを再現したいとき以外は触らなくて構いません。

### 5-7. 手で動かした操作を下書きにする

ゼロから表を書くのが面倒なときは、**自分で操作して記録**できます。

1. 「実行・監視」タブ → **手動操作を開始**(PC のゲームパッド、なければキーボード、
   または**画面のコントローラー図をクリック**)。操作中は**手動操作のカードが緑の
   枠**になり、見出しに「● 操作中」が出ます(終い忘れに気づけるように)
2. **● 記録を開始** → 実際に操作する → **■ 記録を停止**
3. 「**N フレーム記録しました**」と出て「**部品として保存**」ボタンが現れるので、
   押して名前を付ける
4. 「部品を編集」タブで細かく直す

※ 記録できるのは**手動操作で自分が送った入力**だけです(手動操作を始めずに
記録を押すと、その旨を出して始まりません)。

記録は**1秒あたり約30回**の粗さです(1フレーム単位ではありません)。
**下書き**として使い、仕上げは表で直してください。

### 5-7b. 手動操作の入力はどこで効くか

手動操作を開始すると**コントローラーの図**が出ます。図のボタンは
**クリックしている間だけ**押されます(スティックは周囲の矢印 = その方向へ
最大まで倒す、中央の丸 = 押し込み)。マウスなので同時押しは1つまでです。

| 入力                     | 効く範囲                                                                                         |
|--------------------------|--------------------------------------------------------------------------------------------------|
| コントローラー図(マウス) | 「実行・監視」の画面にいる間                                                                     |
| キーボード               | 「実行・監視」の画面で、**入力欄に文字を打っていない**とき(他のタブや入力欄では操作に化けません) |
| ゲームパッド             | GUI のどのタブにいても効く                                                                       |

手動操作は別のタブ(手順を編集など)へ移っても**継続します**(ゲームパッドで
操作しながら手順を眺められます)。ブラウザから**フォーカスが外れる**
(別アプリを前面にする等)と、安全のため**全ボタンを離した状態**を送ります。

装置が2台あるときは、**手動操作を続けたまま「対象」を選び直せます**
(前の装置は全ボタンを離した状態にしてから手を離し、新しい装置へ移ります)。
切り替えている短い間だけコントローラーの図が薄くなり、入力を受け付けません。
※ **記録中は替えられません**(記録は1台の操作を綴ったものなので)。
※ 自動実行している装置は手動操作を受け付けないため、選択肢が灰色になります。

### 5-8. ジャイロが効かないとき(切り分けの順番)

1. **装置パネルの行を開き、「ジャイロ」行を見る**(該当装置の詳細)。
   「本体からの有効化なし」なら、送る値以前に Switch が読んでいません。
   USB を挿し直して(認識からやり直させて)再確認してください。
   ※この行が出ない場合、マイコンのファームが古いままです(先に更新)
2. **手順を作り直して転送し直す**。ファーム更新前に転送した手順には
   古い形式のデータ(加速度 0 = 自由落下)が残っていることがあります。
   実行すれば自動で再転送されます
3. **大きい値で試す**: ジャイロ 左右 **2000**・長さ 60F など。
   小さい値はゲーム側の不感帯に吸われて見えないことがあります
4. **軸を1つずつ試す**: **GR = 水平回転(正 = 左回り)は確認済み**。
   **GY = 上下(正 = 下向き)も確認済み**。GP(ひねりと推定)だけが未確認なので、
   使う前に動かして対応を確かめ、逆に回ったら符号を反転してください
5. **ゲーム側の設定**を確認する(ジャイロ操作 ON、感度)。
   Switch の「設定 → コントローラーとセンサー → ジャイロセンサーの補正」でも
   動作を確かめられます

> **一定値を送り続けると、途中で回転が止まり、送信をやめると同じ速さで
> 元の向きへ戻る**: Switch 側の**ゼロ点自動較正**が原因です(実機実測で確定)。
> 実物のセンサーは静止時も必ずノイズが乗るため、「完全に一定な
> 値」はゼロ点誤差と区別がつかず、徐々に差し引かれます。実測:
>
> - **変化が 13 生値未満**だと「静止」とみなされる(2000⇄2013 の 2F 交互は
>   回り続け、2000⇄2012 は吸収されて停止した。10000⇄10013 / 10012 でも同じ
>   境界 = **値に比例しない絶対閾値**)
> - 一定のまま **約70F** で較正が作動(70F: 戻りなし / 75〜80F: 弱い戻り /
>   90F: 明確な戻り。いずれも目視測定)
> - ゆらぎがあれば吸収されない(2200⇄1800 の 2F 交互で約13秒回り続けた)
>
> **対策はジャイロブロックの「ゆらぎ」(既定オン)**です。ゆらぎ無しで
> 60F 以上一定が続く手順には、保存時に警告が出ます。
> ※数値はいずれも特定ゲームでの測定です。別のゲームで挙動が違ったら
> この節と警告の閾値を見直してください

## 6. 放置運転にする

1回動いたら、周回の数を決めて放置します。

- **周回 0(既定)= 止めるまで無限にくり返す**。「今の周で止める」か
  「今すぐ止める」で終えます
- 回数を決めたいときは数を入れます(その回数で自動的に止まります)
- **1回だけ**なら「▶ 1回実行」(周回の欄は見ません)

**画面の配色**は右上の **⚙** から選べます(選択はこのブラウザに保存されます)。
既定は「自動」で、Windows のライト/ダーク設定に合わせて切り替わります。
色の系統は3つ: **藍**(既定)、**墨**(色を状態表示だけに絞る。日中の長時間
作業向け)、**琥珀**(地と線が暖色。暗い部屋で画面全体の明るさが下がります)。
どの系統でも、**異常・注意・良好の色は同じ**です(系統で変わるのは地・線・
文字と強調の色だけ)。系統を変えても「赤が出ていないか」の見張り方は変わり
ません。

> **操作画面(黒い窓)は Ctrl+C で終了できます。** cmd の仕様で
> 「バッチ ジョブを終了しますか (Y/N)?」と聞かれますが、**どちらを押しても
> そのまま終わります**(ツール自体は Ctrl+C の時点で終了済み)。
> **周回実行の途中で終了・PC がスリープ・WiFi が切れても、実行は実機が
> 自律で最後まで続けます**(そういう設計です)。止めたくなったら
> padcue.bat をもう一度開いて「⏹ 今すぐ止める」、または本体ボタンを
> 1.5秒長押し。※「待って選ぶ」を含む手順だけは、選ぶ人がいないので
> 次の選択待ちで止まったまま待ちます(タイムアウト設定があればそれに従う)

実行ボタンは2つあります: **▶ 1回実行**(周回の欄に関係なく必ず1回)と
**⟳ 周回実行**(周回の欄の回数だけくり返す)。単発の手順を、残っていた
周回数のまま何周も走らせてしまう事故を防ぐための分け方です。

1. **周回**に回したい回数を入れて **⟳ 周回実行**
2. 途中で切りたくなったら **◼ 今の周で止める**(区切りまでやってから止まるのでゲー
   ムの状態が整う)
3. 緊急時は **⏹ 今すぐ止める**、または本体ボタン長押し

**放置前に見ておくもの**(装置パネルの行を開いた詳細)

| 項目                                  | 正常値       | 出たら                                                                                                                                                                   |
|---------------------------------------|--------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| ずれの最大(実測) → **フレームの刻み** | 数百 µs 以下 | 手順を1フレーム進める時計の遅れです。「⚠ 超過」が付いたら、その入力は狙ったフレームからずれて本体に見えています。数値を記録して報告してください                          |
| ずれの最大(実測) → **読み取り待ち**   | 5〜8ms 程度  | 入力が変わってから、その値を USB の送出口へ載せられるまで。Switch が前のデータを取りに来るまでは載せられないので、本体の読み取り間隔ぶんは必ずかかります(この程度は正常) |
| ⚠ 送れなかった入力                    | 出ない       | 出たら入力が落ちています。報告してください                                                                                                                               |
| ⚠ コントローラー登録                  | 出ない       | 出たら本体がこの装置を登録できておらず、**入力が全て無視されます**(§「登録が未完のとき」へ)                                                                              |

**結果を見て分岐したい**場合は「**待って選ぶ**」ブロックを使います。
実行が止まって画面に選択肢のボタンが出るので、見て選べば続きが走ります。
待っている間は時間を刻まないので、**考える時間は精度に影響しません**。

### 6-1. 終わったことを知らせてもらう(通知)

放置運転の間はたいてい別のことをしているので、知らせを出せます。
右上の **⚙** に、**場面**(行)× **知らせ方**(列)の表があります。

| 場面                 | いつ                                   |
|----------------------|----------------------------------------|
| **実行が終わった**   | 指定した周回を走り終えたとき           |
| **異常で止まった**   | 装置が異常を報告して止まったとき       |
| **操作を待っている** | 人が選ばないと進まない駐機に入ったとき |

| 知らせ方           | どうなるか                                                                                                                                                                                                                                                                       |
|--------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **音**             | 場面ごとに音の種類と音量を選べます(「♪」でその場で聴けます)。種類は短い順に **ピッ / ピピッ / ピピピッ / ポーン / チーン / 上がる2音 / 下がる2音 / ピンポン / 上がる3音 / 下がる3音**。ゲームの音に紛れて気づきにくいときは「ピピピッ」が通ります                                |
| **タブで知らせる** | ブラウザのタブ名が「● 実行が終わりました」に変わって点滅し、**タブのアイコンが橙色**になります(ふだんは藍色)。別のタブを見ていても、タブ名が幅で切れていてもアイコンで気づけます。ただし**操作画面の窓が他のアプリの後ろに隠れていると見えません**(その場合は音も入れてください) |

**音とタブはどちらか一方ではありません**。場面ごとに、両方・片方・どちらも
切、を選べます(切れば、その場面では何も起きません)。

> **ブラウザがタブを休止させると、音もタブの知らせも止まります。**
> Chrome / Edge の「メモリセーバー」は、しばらく見ていないタブを休ませます。
> 放置運転で使うなら、設定の「メモリセーバー」で **この画面のアドレスを
> 常にアクティブにするサイトへ追加**してください
> (Chrome: 設定 → パフォーマンス → メモリセーバー → 「常にアクティブに
> しておくサイト」)。

- **自分で「⏹ 今すぐ止める」を押したときは鳴りません**(押した本人が画面を
  見ているため)。「◼ 今の周で止める」は止まるまで待つので鳴ります
- 操作待ちで鳴るのは**人が選ばないと進まない駐機**だけです。連結の自動合流で
  進む「相方待ち」では鳴りません
- 連結して動かしているときは、両方が終わった時点で1回だけ鳴ります
- 音は、そのブラウザで一度どこかを押してからでないと鳴らせません
  (ブラウザの決まり)。実行ボタンを押していれば満たされています

### 6-2. ログの見かた

画面いちばん下の「ログ」に、**実機で起きたことが日時つきで溜まっていきます**
(消さない限り残ります。放置運転のあとで振り返れます)。

| 色     | 意味           | 例                                                                       |
|--------|----------------|--------------------------------------------------------------------------|
| 色なし | ふだんの記録   | 実行を開始 / 実行が最後まで終わりました / 状態: 待機中 → 実行中          |
| **黄** | 気に留めるもの | フレームの刻みが遅れました / 実行を中断しました / 応答を取りこぼしました |
| **赤** | 異常           | 実行が異常終了しました / USB 接続が切れました / WiFi が切れました        |

**黄と赤が出ていないか**だけ見れば十分です。特に「フレームの刻みが遅れました」は
フレーム精度に直接響くので、回数と最大のずれを控えておいてください。

溜まりすぎたら「**ログを消す**」で全部消せます(元に戻せないので確認が出ます)。
「新しい行に追従」のチェックを外すと、読んでいる位置が勝手に動きません。

## 7. 動いたあとにやっておくこと

### 7-1. 無線更新(OTA)が使えることを確認する

以後ケーブルの抜き挿しが不要になります。**挿したまま**試してください。

```powershell
（1-1 の PowerShell で）
cd C:\path\to\padcue\firmware
idf.py build

（別の端末で）
cd C:\path\to\padcue\pctool
python -m padcue ota
```

**確認**: 転送 → 再起動 → 数秒後に `padcue status` のファーム版が変わる。起動に
失敗した場合は**自動で前のファームに戻ります**(`status` に「ロールバックされまし
た」と出る)。

**OTA の再起動後は、Switch が再認識しないことがあります。** `padcue status` の
到達段階が **0x400 のまま**(= 入力は送っているが、本体から問い合わせが来て
いない)なら、**USB を挿し直してください**。それで 0x7fb になります。

- 本体設定の問題でもファームの不具合でもなく、USB の再列挙を本体が拾わない
  だけです。挿し直せば直ります
- **初代 Switch では挿し直しが要ることが多く、Switch 2 ではそのまま戻ることが
  多い**傾向があります。どちらでも対処は同じです
- 見分け方: 到達段階が **0x400**(入力を送っただけ)なら再列挙されていない。
  **0x000** なら電源かケーブルを疑う

### 7-2. フレーム周期を合わせる(長い手順の精度に効く)

初期値は 60.00Hz です。実機が 59.94Hz 相当だと、**長い手順の後半でだけ**ずれます。

**どれくらい流せば分かるか**: 両者の差は約 0.1% です。つまり **1000 フレーム(約
17秒)で1 フレーム**ずれます。数フレームの余裕しかない操作なら 3000〜5000 フレー
ム流せばはっきり失敗するようになります。短い手順では気づけないので、**長い手順で
試してください**。

数千フレームの手順を流して後半がずれるなら、切り替えて比べます。

```powershell
python -m padcue config frame_period_ns 16683333    # 59.94Hz 相当にする
python -m padcue config frame_period_ns 16666667    # 60.00Hz に戻す
```

崩れない方を採用してください。設定は電源を切っても残ります。

### 7-3. 自分の環境で分かったことを控える

どこかに書き留めておくと、次に組むときと、うまくいかなくなったときの
比較対象になります。

- [ ] プロコン方式は動いたか(ダメならどの到達段階で止まったか)
- [ ] bInterval=1 は受理されたか(ダメなら 8 で動いたか)
- [ ] OTA 後に Switch は自動で再認識したか
- [ ] フレーム周期は 60.00 / 59.94 のどちらだったか
- [ ] LED(GPIO35)とボタン(GPIO41)は想定どおりだったか
- [ ] 同じ手順を何回流して、何回成功したか

## 8. 2台目を迎え入れる(2台同時運用)

> **前提**: PC 側とファームの版を2台とも揃えておくこと。PC は登録した個体ID
> (MAC)でしか装置を追跡しないため、2台目が LAN に現れても勝手に繋ぎ替わる
> ことはありません。
> コマンドはすべて **padcue.bat と同じ場所(リポジトリ直下)** で、付録と
> 同じ形(`python -m padcue …`。以下では省略して `padcue …` と表記)で
> 実行します。

1. **有線で書き込む**(§1 と同じ。2台目は必ず有線から。書き込み時の
   シリアルログに「個体ID: xxxxxxxxxxxx」と IP アドレスが表示されるので控える)
2. **WiFi を本体保存にする**(§1 の仕上げと同じ。
   `padcue --host <IP> config wifi_ssid <SSID>` と `wifi_pass`。
   ビルド設定に頼らず NVS に入れる)
3. **すぐ登録する**(どちらでも同じ):
   - 画面から: 左の**装置パネルの「＋ 装置を追加」**。LAN から未登録の
     実機を探して候補に出す(見つからないときは IP 直接指定の欄が出る)
   - コマンドで: `padcue device add <2台目のIP> 2P`
   - どちらも接続して個体IDを確認してから台帳に載せる。古いファームだと
     断られる(先に `padcue --host <IP> ota firmware/build/pademu.bin`)
4. **確認する**: `padcue device list` で 1P/2P と個体IDが並ぶこと。
   `padcue --device 2P status` が返ること。画面なら装置パネルに2行
   並び、**実行・監視のレーンが装置ごとに2本**になる(1台と2台は同型で、
   レーンは常に出ている)
5. どちらのマイコンがどの Switch 用かの対応づけ(自動):
   - マイコンを挿すと Switch 本体が名乗る識別子を記録し、装置の欄に
     「本体 XXXX」と**自動で表示される**(本体ごとに固有・安定であることを
     実機で確認済み)。左ペインの **「Switch 本体」カード**に確認済みの本体が
     並ぶので、✎ で好きな名前(例: リビングのSwitch2)を付けられる。
     名前は本体の識別子に付くので、マイコンを挿し替えてもついていく
   - 補助手段: 手動操作で適当なボタンを押して、反応した本体を見る。
     または本体への物理記名

**装置を交換したとき**(基板が変わると個体IDも変わる):
`padcue device forget <名前>` で控えを解除 → 新しい個体へ接続すると
学習し直す。台帳から外すのは装置の欄の「登録を解除」ボタン
(または `padcue device remove <名前>`)。

**練習(模擬デバイス)との行き来**: `padcue device 127.0.0.1`(または
padcue-練習.bat)は相手が模擬だと分かるとIDの控えを解除して向け替える。
実機へ戻るときは画面の「探す」か `padcue device auto`(学習し直す)。
探索が**勝手に**模擬デバイスへ乗り換えることはない。
> 実機を2台登録した状態で padcue-練習.bat を使うと、**1P だけ**が模擬に
> 向き、2P は実機のままになる。練習中に 2P を触らないよう注意するか、
> 下の §9 の「練習用フォルダ」を使うこと。

## 9. 2台をまとめて動かす(連結)

2台とも登録できたら(§8)、実行・監視は装置ごとのレーン2本になる。
レーンから開始した実行は**互いに無関係**(片方が落ちても相方は続く)。
2台を組で動かしたいときだけ「連結」する。

レーンの上には**上部バー**がある(2台以上のときだけ)。ここには
「2台にまたがること」だけが並ぶ。連結していないときはプリセットの保存と
連結の入口だけで、連結すると連結の語彙が加わる。

1. **連結する**: 上部バーの「⧉ 1P と 2P を連結する」を押すと、まとめて開始・
   両方停止・自動合流の一式が同じバーに現れる。外せば語彙ごと消える
2. **開始**: 各レーンで手順・周回・開始ラベルを選び、上部バーの
   「▶ 1回実行」か「⟳ 周回実行」。転送は自動で、**組の開始した時刻と終了予定**
   (周回を有限にしてあるとき)・**開始ズレ(ms)**が下に出る
   - 連結していないときは、この2つは組ではなく**装置ごとの値**になるので、
     各レーンの実行ボタンの下に1台ずつ出る(バーには出ない)
3. **合流**: 手順に「待って選ぶ」があると、両方そろったとき
   「進む先」を自動で選んで同時に進む(自動合流)。画面で見て選びたい
   1回だけは「次の合流は自分で選ぶ」→「選択肢を両方へ同時に送る」
4. **止める**: 上部バーの「両方を〜止める」。レーンの停止ボタンで
   **片方だけ**止めても相方は止まらない(連動して止まるのは片方の
   **異常**のときだけ)
   - **ファンクションキー**(F9 = 全部止める / F10 = まとめて開始)は
     **既定では効かない**。使うなら右上の ⚙ の「キーボード」で入にする
     (他のソフトの割り当てと取り違えて誤爆しないよう、既定は切)
5. **連動停止が起きたら**: 理由と「⟲ 続きから再開(残り周回)」
   「片方だけ続ける」がその場に出る
6. **プリセット**: 毎朝同じ組み合わせを使うなら、上部バーの「プリセットへ保存」で
   名前を付けて残す。**連結していなくても保存できる**——連結の別も割り当ての
   一部なので、連結していないときに保存したものは一覧に「**単独**」と出て、
   呼び出しても連結しない(連結して保存したものを呼び出せば連結する)。
   呼び出し中は保存が2つに分かれる — 「**上書き保存**」は
   そのプリセットを更新し、「**別名で保存…**」は元を残したまま新しい
   プリセットを作る(以後は新しい方を編集していることになる)。
   呼び出しは、格納庫のプリセット一覧の行にある「呼び出す」。開始は、
   連結のプリセットなら上部バーの ▶ 、単独のプリセットなら各レーンの ▶ 。
   中身(合流の選択肢・装置ごとの手順と周回)を確かめたいときは ▶ で開く。
   呼び出し中の1件は色が付いて開いたままになる
7. **放置の保険**: 手順の「待って選ぶ」ブロックに「待つ上限」と
   「上限に達したら」を設定しておくと、相方が来ないまま永久に待ち続けない

**実機なしで連結を練習する**(模擬デバイス2台。実機の台帳を汚さない)。
付録と同じ準備(`PYTHONPATH` にリポジトリの `pctool` を通した
PowerShell)で、フォルダはどこに作ってもよい:

```powershell
mkdir 練習2台; cd 練習2台
python -m padcue --project . init
# 別々の窓で:
python -m padcue mock --port 5555
python -m padcue mock --port 5556 --id mock2p000000
# 登録して画面を開く:
python -m padcue --project . device add 127.0.0.1:5555 1P
python -m padcue --project . device add 127.0.0.1:5556 2P
python -m padcue --project . gui
```

| 手順が思ったとおりに動かない | 実機の前にタイムラインを見る。ラベルを置いて途中から試す                                                                                             |

### 登録が未完のとき(ペアリング ⚠ 未完/操作だけ効かない)

本体は、登録記録の無いコントローラーに「新規ペアリング」を送り続け、
完了するまで入力を無視します。`padcue status` のペアリング行が
「⚠ 未完」のとき(または接続もジャイロも正常なのに操作だけ効かないとき)、
上から順に:

1. **本体の「持ちかた/順番を変える」画面を開いたまま**、装置を挿し直す
   (ペアリングは挿した直後に走ります。完了の合図は、`padcue status` の
   ペアリング行が「受理済み」になる/操作画面では ⚠ のコントローラー登録
   行が**消える**/本体の画面に Pro コントローラーが現れる、の3つ)
2. 駄目なら **実物の Pro コントローラーを同じ本体に有線で一度つなぎ、
   認識させてから**、装置に挿し替える(装置は実物と同じ識別子を名乗って
   いるため、実物の登録記録に相乗りできます)
3. すぐ動かしたいときの逃げ道: `padcue mode hidpad`(HORI パッド互換。
   ペアリング自体が無い方式。**ジャイロ不可・スティック 256 段階**)
4. それでも駄目なら、フェーズ 0x01/0x02 への応答が本体の期待と合っていない
   可能性が高いので、Raspberry Pi を本体と実物プロコンの間に挟んで USB を
   中継し、**実物のペアリング交換を採取**する(「持ちかた」画面で採る)。
   採れたログを突き合わせて応答バイトを直す(採取例:
   docs/reference/bypass_procon_log.txt)

※ 「フェーズ 0x01/0x02 のまま = 未完」という**判定の規則自体も資料由来の
未検証の仮定**です。もし「⚠ 未完」が出たままなのに操作が普通に効いている
場合は、判定の側が実機と合っていないので、手順 4 の採取ログで実機の
終端フェーズを確かめて判定(CLI/画面の表示条件)を直してください

## 付録

### LED の意味

| 色                   | 状態                                                                                                              |
|----------------------|-------------------------------------------------------------------------------------------------------------------|
| 白                   | 起動中                                                                                                            |
| 青                   | WiFi 接続中、または**接続が切れている**(待機中なのに青のままなら WiFi に入れていません)                           |
| **シアン**(水色)     | 待機中(正常な待ち)。**WiFi につながっている**ことも表します。青と並べて見分ける場面では、画面は「水色」と呼びます |
| **緑(ゆっくり明滅)** | 実行中                                                                                                            |
| 黄                   | 「待って選ぶ」で選択待ち                                                                                          |
| **赤(点滅)**         | 異常(解除するまで保持)                                                                                            |
| 紫                   | ファーム更新中                                                                                                    |

### 本体のボタン(LED と同じ面にある押せるボタン)

| 操作         | 動作                       |
|--------------|----------------------------|
| 短押し       | 今の周を終えてから止まる   |
| 1.5 秒長押し | すぐ止める(全ボタンを離す) |

### コマンド一覧

ふだんは `padcue.bat` をダブルクリックするだけです。
コマンドで使う場合は、`padcue.bat` と同じフォルダで
`$env:PYTHONPATH = "pctool"` を一度実行してから次を使います
(コマンドプロンプトなら `set PYTHONPATH=pctool`)。

| コマンド                                 | すること                                             |
|------------------------------------------|------------------------------------------------------|
| `padcue.bat`(ダブルクリック)             | **操作画面を開く(ふだんはこれだけ)**                 |
| `padcue-練習.bat`(ダブルクリック)        | 模擬デバイス付きで操作画面を開く(練習用)             |
| `python -m padcue gui`                   | 操作画面を開く(コマンドから)                         |
| `python -m padcue status`                | 状態・USB・到達段階・遅延・応答落ち                  |
| `python -m padcue logs`                  | 異常ログを回収                                       |
| `python -m padcue device auto`           | マイコンを探して接続先を覚える(画面の「探す」と同じ) |
| `python -m padcue push <手順名>`         | 転送だけ(実行しない)                                 |
| `python -m padcue run <手順名> -n 10 -w` | 実行(10 周・進捗を表示し続ける)                      |
| `python -m padcue stop [--graceful]`     | 停止(`--graceful` は今の周を終えてから)              |
| `python -m padcue list`                  | マイコンに入っている手順                             |
| `python -m padcue mode procon\|hidpad`   | 転送方式の切り替え(無線で可)                         |
| `python -m padcue config <key> <値>`     | 設定(`frame_period_ns` など)                         |
| `python -m padcue clear-error`           | 異常状態(赤 LED)を解除                               |
| `python -m padcue ota`                   | ファームを無線で更新                                 |
| `python -m padcue mock`                  | 模擬デバイス(実機なしで練習)                         |
