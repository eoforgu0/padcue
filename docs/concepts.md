# 概念

## 0. 位置づけ

利用者が扱う概念と、その関係、実行の意味論を定める。語の短い説明は用語集にあり、一致しないときはこの文書に従う。意味論上の決まりは、方針(principles.md)P7〜P23 を具体化したものである。

## 1. 全体像

```text
                       利用者
                         |
                         |  手順を書く・実行を始める・判断点で選ぶ
                         v
        +------------------------------------------------------+
        | プロジェクト                                         |
        |   手順 / フレーム表 / 条件 / 登録情報 / プリセット   |
        +------------------------------------------------------+
              |
              |  手順を渡して実行を始める
              v
        +------------+   入力   +--------------+
        | 装置       | -------> | Switch       |
        |  (実行)    |          |  (ゲーム)    |
        +------------+          +--------------+
              ^                               |
              | 選ぶ・停止する                | 画面
              |                               v
        +--------------------------+   +------------------+
        | 観測と判断               |<--| 映像ソース       |
        |  条件で選択肢を選ぶ      |   +------------------+
        +--------------------------+
```

- **利用者**は手順を書き、実行を始め、判断点で選び、停止する
- **プロジェクト**は手順・フレーム表・条件・登録情報・プリセットを保存する場所である
- **手順**は、何を、どの順で、どんな状況になったら行うかを書いたもので、装置へ渡される
- **装置**は渡された手順を自律して実行し、Switch へコントローラーの入力を送る
- **Switch** はその入力を受けてゲームを進め、その画面を映像として出力する
- **観測**は画面を 1 枚の画像として取り、条件と比べて、判断点でどの選択肢へ進むかを決める

プロジェクトと、観測と判断は、操作用の PC にある。PC は手順を作り、装置で実行できるデータに変換して渡す(以下、この処理を変換と呼ぶ)。映像の判定とスクリプトの実行も PC が行う。装置は、渡された手順を PC から独立して実行する。

## 2. 時間

**フレーム**: 手順の時間の単位で、padcue が入力を切り替える単位である。長さはフレーム周期で決まり、既定は約 16.7ms である。ゲームや USB の周期には同期しない。手順の中の長さと待ちは、整数のフレーム数で書く。

**フレーム周期**: 1 フレームの長さ(ナノ秒)を表す設定値。Switch 側の周期に合わせて変えられる。

**絶対時刻**: 各入力を送る時刻は、手順の先頭から数えたフレーム数で決める。1 つ前の入力を実際に送った時刻を基準にしないので、送信の遅れが後ろの入力へ積み重ならない。選択待ちの間はこのフレーム数を進めず、待ちが終わったところから続きを数える(5 節)。

**周回**: 手順の中の 1 つのくり返しは、回数を実行時に指定する周回数にできる。これを周回数のくり返しと呼ぶ。周回数のくり返しがなければ、手順全体が周回数のくり返しになる。周回数は、そのくり返しを合計で何回通すかであり、1 以上の数か無限を指定する。そのくり返しを 1 回通すことを 1 周と数える。周回数のくり返しを持てるのは一番上の手順だけである。呼び出した先の手順にあるものは 1 回として扱い、手順を作るときにそのことを知らせる。周回数のくり返しは、分岐の中にも、ほかのくり返しの中にも置けない。

## 3. 手順の構成

### 手順

**定義**: 自動操作の内容そのもの。ブロックの列として書く。

**持つもの**: 名前、ブロックの列、前提条件。

**関係**: ブロックからほかの手順・フレーム表・条件を参照する。

**意味論上の決まり**: 前提条件は、その手順を始める前にゲームがどんな状態であるべきかを書いた文である。実行前に示すだけで、自動ではチェックしない。

### ブロックの種類

| 種類 | 意味 |
|---|---|
| 押して離す | 指定したフレーム数だけボタンを押し、離す |
| 押し続ける | ボタンを押した状態を保つ |
| 離す | 押し続けているボタンを離す |
| スティック | スティックの傾きを生値で指定する |
| ジャイロ | 回転の速さを生値で、長さをフレーム数で指定する |
| 待つ | 入力を変えずに指定したフレーム数を過ごす |
| ラベル | 手順の中に名前の付いた区切りを置く |
| くり返し | 中身を回数ぶんくり返す。回数は数か無限か、実行時の周回数である |
| フレーム表 | フレーム表を展開して、その表(後述)のとおりに入力する |
| 別の手順 | 別の手順の中身を、この位置へそのまま並べたものとして実行する |
| 分岐 | 選択肢のどれかへ進む。「選択条件」の判断が必要な回だけ止まって待つ |
| 合流点 | グループの台が同じ名前で待ち合わせ、揃ったら進む。選択肢を持たない |
| スクリプト | 利用者が用意した任意の処理を呼ぶ |

どのブロックにもメモを付けられ、どのブロックも無効にできる。メモは実行に影響しない。無効にしたブロックの扱いは 4 節に定める。

くり返しは任意の名前を持てる。手順の中の 1 つのくり返しは、回数を実行時の周回数にできる(2 節)。

別の手順は展開である。呼び出し元の続きは、呼び出し先の最後のブロックの直後につなぐ。呼び出し先が分岐で終わるときは、呼び出し元の続きを分岐の後ろの位置に置いたものとして扱い、どの選択肢を通っても、抜けた後にそこへ進む。スクリプトで終わるときも同じである。呼び出し先を抜けた後は、呼び出し先の末尾の入力の状態のまま続く。フレーム表と違い、入る前の状態へは戻さない。展開なので、手順は自分自身を、直接にもほかの手順を介しても呼べない。呼び出しが循環している手順は実行できず、作るときに知らせる。

ジャイロはジャイロのブロックでもフレーム表でも書ける。加速度はフレーム表で書く。

### フレーム表

**定義**: 密度の高い同時入力を、1 行を 1 フレームとする表で書いた、再利用できる操作の断片。

**持つもの**: 名前、行の列。各行は、その表が持つ列の入力を持つ。

**関係**: 手順からフレーム表ブロックで参照する。同じフレーム表を複数の手順から使える。

**意味論上の決まり**:

- 空欄は、ボタンでは離す、数値では 0 を意味する。ただし重力軸の空欄は静止姿勢を意味する。全軸が 0 の状態は自由落下であって、実機にはない状態だからである。重力軸とは、加速度の 3 軸のうち重力がかかる軸で、静止していても一定の値が出る
- フレーム表を抜けたら、入る直前の状態へ戻る。最後の行で押していたボタンやスティックは、手順の続きへ引き継がれない。戻すのに時間は消費しない
- 表は、何も押さないことも含めて、すべての入力を行のとおりに決める。表に書いていない列は空欄と同じである。手順の側で押し続けている入力も、表の間は表のとおりになる

### ラベル

**定義**: 手順の中に名前を付けて置く区切り。区切りの定義は 5 節の停止の項にある。

**持つもの**: 名前。

**関係**: 進捗の単位と記録の位置を兼ね、開始位置にも選べる(5 節)。

外から位置として指されうるブロック(ラベルやくり返しなど。種類は file-format.md §6-1)は、名前とは別の変わらない識別子を持ち、開始位置・プリセット・記録はその識別子で結び付ける。

## 4. 意味論

手順の意味は「各フレームの全入力の状態の並び」で定める。押して離す・押し続けるといったブロックは、その並びを短く書くための記法にすぎない。

- くり返しは、書いた区間の正確な再生である。押し続けている状態は、くり返しの境界を暗黙には越えない。各回の先頭と、くり返しを抜けたところでは、そのくり返しに入る直前の入力の状態に戻る。回をまたいで押し続けたいものは、くり返しの外で押す
- くり返しの 1 回が進める時間は、選択待ちになる選択肢の中身を数えずに決まる。選ばれた選択肢の中身の長さは、以後の入力の時刻をそのぶんずらす。1 回で時間をまったく進めないくり返しは、何回くり返しても手順が進まないので、変換でエラーになる。ただし、中身に選択待ちがあるものは通す。操作をすべて選択肢の中に書いた「毎周、選んでから操作する」形がこれにあたる
- 同じフレームに書いた状態変化は、書いた順に適用し、最後にできた全入力の状態だけを出力する。途中の状態は 0 フレームなので、出力に現れない。くり返しの各回の先頭では、くり返しに入る直前の状態を出し直すので、直前の回の末尾に書いた状態変化が同じフレームに重なると、その変化は現れない
- 値は生値で書く。中心 0 の符号付き整数で、+1 が送信できる最小の差にあたる。ジャイロは角速度、加速度は重力を含む値を、いずれも生値で書く
- 1 フレームだけの入力は、ゲームに読まれないことがある。ゲームが入力を読む時刻は外から分からないため、指示した長さ N に対して、ゲームが見る長さは N-1 から N+1 の幅を持ち、N = 1 では下限が 0 になる。この幅は、装置が入力を切り替える時刻とゲームが読む時刻のずれだけを数えたものである(hardware-design.md §1-2)
- 無効にしたブロックは、なかったものとして扱う。その時間だけ何もしないのではなく、時間も消費しない。くり返しや判断点を無効にすると中身ごとなくなり、ラベルを無効にすると、そのラベルは開始位置にも選べなくなる
- 「選択条件」のない選択肢は待たない。分岐の「選択条件」のない選択肢は、「対象の回」だけで決まり、実行前の変換の時点で決着する。その回には待ちも判定も起きない

## 5. 実行

**開始**: 手順・周回数・開始位置を決めて実行を始める。開始位置は、手順の中の 1 点と、それを囲む各くり返しの何回目かで表す。手順の中の点には、呼び出した先の手順の中の点も含む。ラベルは、そのうち名前の付いた点である。開始位置に選べるのは、手順の先頭、ラベル、停止した位置で、既定は先頭である。周回数は、周回数のくり返しを合計で何回通すかである。停止した位置から始めるときは、その位置の周から周回数までを実行する。異常停止の状態は、「開始」で解除される。

**開始した時点の定義**(coupling.md D12): 実行は、開始した時点の手順、呼び出し先の手順、フレーム表、条件、装置に設定した映像で最後まで動く。実行中に編集した内容は次の開始から反映し、編集があったことを実行の画面に出す。条件の範囲などを誤ったまま開始したときは、停止して修正し、開始し直す。スクリプトのコマンドも開始した時点のものを使うが、コマンドが読むファイルの中身は padcue が固定できない。

**進捗**: いまの位置、つまり最後に通った区切りと、周回数のくり返しの何回目かが分かる。

**停止**: 2 通りある。**区切りで停止**は、次の区切りで停止する。

区切りは 3 種ある。ラベル、周の境、選択待ちになる点(分岐・合流点・スクリプト)である。周の境は、周回数のくり返しの各回の先頭と、くり返しを抜けた直後である。1 台で動かすときの合流点のように、待たずに通る所も区切りである。区切りは、padcue が停止と開始の位置として扱う点である。ゲームの中で停止してよい場所になるように、手順を作る人がラベルを置く。

「区切りで停止」は、この 3 種のうち最初に到達したもので停止する。押した後は、止まる先が決まっていれば表示する。選択肢が 2 つ以上の選択待ちの先は、選ぶまで決まらない。選択待ちの間に押せば、その場で停止する。

もう一方の**停止**は、その場で全入力を離して止まる。どちらでも全入力を離す。

**停止した位置**は最後に通った区切りであり、手順の中の点と、そこを囲むくり返しのそれぞれの何回目かで表す。区切りで停止、停止、物理ボタン、異常停止のどれで停止しても同じである。「停止」を押したときは、最後に通った区切りから停止した時点までの操作を、次に始めたときにもう一度行うことになる。

停止した位置は開始位置に選べる。選択待ちで停止したときは、その選択待ちからやり直す。最後の周の終わり(周回数のくり返しを抜けた所)で停止したときは、くり返しの後ろのブロックから始める。

停止した位置は、その装置の最後の実行について残るので、開始位置に選べるのは、その実行と同じ手順を選んでいる間だけである。装置が別の手順を実行するか、装置の電源を切ると消える。完了したときは停止した位置を残さず、開始位置は先頭である。

**周回を終える**: 実行中に周回数を変えて、予定より早く周回を終えること。周回数のくり返しの後ろにブロックがあれば、それも実行する。変える前の周回数に戻すこともできる。グループでは、全レーンを同じ周回数で終える。

周回数を変えると当てはまる周が変わるのは、周回数のくり返しを指す「最後の回」と「残り n 回」の 2 つだけである。手順がどちらも使っていなければ、終え方は「今の周で終える」の 1 つである。どちらかを使っていれば、終え方は次の 3 つになる(「残り n 回」のときは、「最後の回」を「残りの回」と読み替える)。

- 次の周を最後の回にして終える。最初から周回数をその数にした実行と同じ動きになる
- 今から最後の回にして、今の周で終える。続きへ切り替える前に、最後の回で分かれる分岐を通るときは選べない
- 最後の回を実行せずに、今の周で終える

装置へ送った手順は途中で書き換えられない。そのため、次の選択待ちか周の境で一度停止し、止まった位置から新しい周回数で続きを始める。続きは同じ 1 回の実行として扱い、中身は開始した時点の定義のままである。

**完了**: 手順を最後まで実行して終わること。周回数のくり返しは周回数ぶん通し、その後ろにブロックがあれば、それも実行する。

**選択待ち**: 分岐、合流点、スクリプトのいずれかで止まり、選ばれるか、相手が揃うか、処理が終わるのを待つ状態。待っている間は全入力を離す。「待つ間の入力」を「そのまま」にした分岐か合流点では、直前の状態を出し続ける。待っている間は手順の時間を進めないので、待った長さは、以後の入力どうしの間隔に影響しない。

**全入力を離す**: ボタンをどれも押していない状態にし、スティックを中央へ戻し、ジャイロを 0 にし、加速度を静止姿勢にすること。停止でも、選択待ちの既定でも、区切りで停止するときでも同じである。静止姿勢とは、3 節のフレーム表の項が定める、重力軸に一定の値が出る状態のことである。

**選ぶ**: 選択待ちの装置に、どの選択肢へ進むかを伝えること。待っている分岐では、「手動」の選択肢に限らず、どの選択肢へでも進められる。合流点では相手を待たずに進められ、結果は時間切れと同じである。選ぶ操作と時間切れが重なったときは、装置が先に受けた方で決まり、遅れた方は捨てる。

**未検出**: 操作用の PC から見て、装置の応答がない状態。装置は自律して実行しているので実行は停止しない。表示と通知だけを行う。

## 6. 観測と判断

**判断点**: 手順の中で選択が起きる位置。分岐がこれにあたる。

### 映像ソース

**定義**: いまの状況を 1 枚の画像として取る手段。

**関係**: 映像ソース自身は、どの装置の映像かという情報を持たない。装置の台数にも番号にも依存しないので、同じソースを複数の判断点から使える。

**意味論上の決まり**: 種類は問わない。取った画像の大きさは、比べる直前に同じ大きさへ揃える。しきい値の意味を、取ったときの大きさに依存させないためである。

### 条件

**定義**: 映像ソースから取った画像が、基準画像と一致しているかを判定する述語。

**持つもの**: 名前、判定する映像、基準画像、判定する範囲、しきい値。判定には基準画像が 1 枚以上必要である。判定する映像の既定は「装置に設定している映像」で、映像ソースを指定することもできる。しきい値を決めるために、一致しないはずの画面も持てる。

**関係**: 手順からも装置からも独立して定義・保存し、名前で参照する。どの装置の映像かは、開始した時点のレーンの映像で決まる。レーンは、装置 1 台ぶんの操作の単位である(8 節)。

**意味論上の決まり**: **採点**は、いまの映像が基準画像にどれだけ近いかを一致度(0〜100)で出すこと。範囲が複数あれば最も低い一致度、基準画像が複数あれば最も高い一致度が条件の一致度になり、それがしきい値以上なら一致とする。一致しないはずの画面は判定には使わない。判定する範囲は 0 個以上持てる。なければ判定する映像の全体を比べる。判定する範囲は、判定する映像を基準にした相対の値で表す。

### 分岐

**定義**: 選択肢のどれかへ進む判断点。「選択条件」を持つ選択肢だけが残る回は止まって待ち、ほかの回は待たない。

**持つもの**: 名前、選択肢の並び、待つ間の入力。名前は任意である。待つ間の入力は、「離す」か「そのまま」を選ぶ。各選択肢は、名前、対象の回、選択条件、中身を持つ。

**意味論上の決まり**:

- **対象の回**は回数の絞り込みで、「最初の回」「最後の回」「n 回目」「n 回ごと」「残り n 回」のいずれかである。「対象の回」は、同じ手順の中でその分岐を囲むくり返しの 1 つに、名前とは別の識別子(3 節)で結び付ける。呼び出した先の手順のくり返しも、呼び出し元の手順のくり返しも指定できない。どのくり返しに結び付けるかは選択肢ごとに選び、選べるくり返しは内側から順に並ぶ。後からくり返しを追加しても、結び付けたくり返しは変わらない。結び付けたくり返しがなくなった分岐は、変換できない。「対象の回」を持たない選択肢は回数で絞られない。回数が無限のくり返しでは、「最後の回」と「残り n 回」は成り立たない
- **選択条件**は、「手動」「条件」「スクリプトの結果」「時間切れ」のいずれかである。時間切れは、待ち始めてから一定の時間が過ぎたことを指す。条件とスクリプトの結果は、待つ間くり返し評価する
- 進む先は、回ごとに次の 3 つの規則を順に適用して決める。前の規則で決まれば、後の規則は適用しない。
  1. その回に「対象の回」が当てはまり、かつ「選択条件」のない選択肢があれば、並びの位置に依らず、そのうち一番上のものへ待たずに進む。この行き先は実行前の変換の時点で決まる(4 節)
  2. 1 で決まらず、その回に「選択条件」を持つ選択肢が残るなら、そこで止まり、上から順に最初に成り立ったものへ進む。待ちを打ち切るのは時間切れである
  3. 1 でも 2 でも決まらない回は、「それ以外」へ待たずに進む。「それ以外」の中身が空なら、中身なしで続きへ進む

  ただし、選択肢が 1 本もない分岐は、「それ以外」に中身があっても実行せず、中身なしで続きへ進む。「それ以外」は「対象の回」で絞った結果どの選択肢も残らなかった回の行き先であり、絞り込む対象の選択肢が 1 本もない分岐には、行き先としての意味がないからである
- 「それ以外」は、どの選択肢の「対象の回」も当てはまらない回の行き先であり、待ちが終わらないときの行き先ではない。待ちが終わらないときの行き先は時間切れである。「対象の回」を持たない選択肢はどの回にも残るので、それが 1 本でもある分岐は「それ以外」へ進まない
- どの選択肢も人が選ぶだけなら、選ばれるまで待つ
- 待つ間の入力は、既定では全入力を離す。「そのまま」を選ぶと、直前の状態を出し続ける
- 決まった後、選ばれた選択肢の中身は、分岐の直前の状態から始まる。離していた場合はそこで出し直す。引き継ぎたいものは判断点の前で設定する
- 選択肢の中身を抜けたときは、分岐の直前の状態へ戻る。戻すのに時間は消費しない。「それ以外」の中身も、「対象の回」だけで決まった選択肢の中身も同じである。選択肢ごとに違う状態のまま合流すると、分岐の後ろの位置の状態が一意に決まらなくなるからである
- 待った時間は手順の時間に含めない
- 選択待ちになる選択肢の中には、中身が時間を進めるくり返しのうち、回数が 2 以上(無限を含む)のものを置けない。そうしたくり返しを含む手順も呼べない。待ちから再開した後の時刻は、選んだ選択肢の長さのぶんだけずらして求めるが、くり返しの回数で決まる長さは、このずらす量に含められないからである。くり返しは分岐の外に置く。ただし、回数が 1 のくり返しと、中身の時間がすべて選択待ちの選択肢の中にあるくり返し(毎回選んでから操作する形)は置ける。後者は、回ごとの長さがすべて選択肢の長さとして、ずらす量に含まれる
- 待たずに選ばれる選択肢と「それ以外」の中身は、分岐の位置にそのまま並べるので、くり返しを置ける
- 時間切れは装置が数える。時間切れを付けた待ちは、操作用の PC とつながっていなくても終わる
- ある条件が成り立ったときに人の確認を待ちたいなら、その選択肢の中身を、「手動」だけの分岐にする。そこで選択待ちになり、通知が出る

### スクリプト

**定義**: 手順の中から、利用者が用意した任意の処理を呼ぶブロック。

**持つもの**: 呼ぶ処理、完了を待つかどうか、渡す映像ソースの並び。

**意味論上の決まり**: スクリプトの位置では実行が止まり、選択待ちになる。完了を待つ場合は、処理が終わってから続きへ進む。5 分たっても終わらなければ、処理を停止して続きへ進む。待たない場合は、処理を始めてすぐ続きへ進む。どちらも人の操作は必要ないので、通知は出さない(10 節)。

### 合流点

**定義**: 一緒に始めた台、つまりグループが同じ名前で待ち合わせる点。選択肢を持たない。

**持つもの**: 名前、時間切れ、待つ間の入力。名前で待ち合わせる相手を決めるので、名前が必要である。時間切れは任意である。分岐の時間切れの選択肢と違い、時間切れのときに実行する中身は持たない。待つ間の入力は、「離す」か「そのまま」を選ぶ。

**意味論上の決まり**:

- グループの台がすべて着いたら、それぞれ続きへ進む。PC はすべての台へ続けて知らせるが、入力の時刻を台の間で合わせることまではしない。1 台のグループでは待たずに通過する
- 時間切れは、自分が着いたときから装置が数える。時間切れに達したら、相手を待たずに続きへ進む
- 人が、相手を待たずに進めることもできる。結果は時間切れと同じである。後から着いた相手は、既に過ぎた回の合流点として扱い、待たずに通過する
- グループのレーンの手順で、合流点の名前か、周ごとの個数が一致しなければ、開始する前に知らせて開始しない。個数は、「対象の回」で決まる選択肢を回ごとに解決して数える。選択待ちの選択で個数が変わる合流点は、開始する前に知らせるだけにする。通る順だけが違う手順はこのチェックを通り、着いた装置はそれぞれ自分の合流点で相手を待つ。画面には、それぞれが待っている合流点の名前と相手が出る
- 名前が空の合流点は、作るときに知らせる
- 合流点の対応付けは、名前、周回数のくり返しの何回目か、その回の中で何度目かの 3 つで決まる。「その回の中で何度目か」は、その台が実際に通った順に数える。分岐の選択肢の中にある合流点も、通れば数に入る
- 合流点に着いた台は、その回を越えて後の周へ進んだ相手を待たない。残りの相手が揃えば進み、残りがいなければ待たずに通過する。対応する相手がない合流点も、相手がその回を越えた時点でこれにより通過する

## 7. 装置

**定義**: 手順を受け取り、自律して実行し、Switch へコントローラーの入力を送るもの。

**持つもの**: 装置 ID、名前、状態、操作権。

**関係**: 使う装置を選ぶのは人である。見つけた装置は候補として並ぶだけで、人が選んだものだけが登録される。登録されていることが「この装置を使う」という意思表示であり、登録されていない装置は動かない。同じネットワークに複数台あるとき、どれが動くのかを人が知らないまま実行できてはならない。

- 登録情報は 1 台ごとに名前と装置 ID を持つ。既定の名前は、登録した順の「1P」「2P」である。装置 ID が空の行は「未割り当て」で、見つかった装置を後から割り当てられる。登録を削除するのも人である
- 同一性は装置 ID で判断し、名前は表示のためだけに使う。名前はいつでも変えられ、変えても記録や割り当ての参照は切れない
- 模擬装置と実機は区別して表示する

**意味論上の決まり**:

- 状態は「待機中」「実行中」「選択待ち」「異常停止」のいずれかである。異常停止の状態は、「開始」か「異常を解除」で解除される。装置が「開始」を受け付けなかったときも異常停止として扱い、理由を記録に残す
- 装置は装置 ID で見つけてつなぐ。IP アドレスは変わるので探索で追跡するが、追跡するのは装置 ID が一致するものだけである。接続した装置の ID が登録情報と一致しなければ、その装置は操作しない
- **操作権**は 1 装置に 1 つで、実行の開始や手動操作のように装置を動かす要求と、手順の転送や設定の変更のように装置の中身や状態を変える要求に必要である。要求ごとの区別は comm-protocol.md にある
  - 停止と状態の読み出しは、操作権がなくても常にできる
  - 所有者は、padcue を置いたフォルダーごとに作る識別子で区別する。同じフォルダーの操作画面とコマンドは、同じ所有者として扱う
  - 操作権は、一定時間通信がないと失効する。警告を出したうえで強制的に取ることもでき、装置の物理ボタンでも解除できる。強制的に取っても実行は続く
  - 操作権は認証ではない。実行中の装置を、自分の別のツールが誤って操作しないようにするためのものである
- 装置には物理ボタンがある。長押しは「停止」と、操作権と手動操作の解除にあたり、短押しは「区切りで停止」にあたる。操作用の PC とつながっていなくても停止できる
- 装置のファームウェアは後から更新できる

## 8. 複数台

**レーン**: 装置 1 台ぶんの操作の単位。装置と、そのレーンの映像を持つ。映像は、映像ソースと、任意の切り出し範囲で決まる。手順・周回数・開始位置の指定、開始と停止、状態、進捗がこの中で完結する(レーンの停止は、グループに属していてもそのレーンだけを停止する。2 本以上のグループでは、周回の終え方はグループの見出しに置く)。台数に関わらず常にこの形であり、1 台なら 1 本になる。レーンは相手の台の情報を持たず、接続や登録も含まない。複数台にまたがる操作はグループの側だけが持つ。

**グループ**: 一緒に始めたレーンの集まり。一括操作で開始するとグループになり、グループだけが合流点で待ち合わせ、連動停止する。グループの見出しの「停止」と「区切りで停止」はグループの全レーンを、レーンの「停止」と「区切りで停止」はそのレーンだけを停止する(手順の途中で役割を終えたレーンを停止し、残りを進めるためである)。グループを作り直すには先に停止する。レーン単位の開始は 1 台のグループになる(2 台以上のグループにいたレーンの一部だけを、合流点のある手順で開始するときは、画面がグループで開始するかを確認する)。

レーンは最後に開始されたグループにだけ属し、停止してもグループは消えない。レーンが別のグループで開始されると、そのレーンは前のグループから抜け、前のグループは残りのレーンで続く。レーンが残らなくなったグループは消える。装置の登録を削除したときも、その装置のレーンはグループから抜ける。

停止しているグループは、人が解除できる。解除すると、レーンはそれぞれ 1 台のグループになり、前回の結果と停止した位置はレーンごとに残る。グループは実行記録に残し、操作用の PC を再起動しても残る。

- **連動停止**は、グループの 1 台が停止したときに残りも停止させること。止まり方で残りの止め方が決まる
  - 異常停止、装置のボタンの長押し、別のツールからの「停止」で停止すると、残りもその場で停止する
  - 装置のボタンの短押しか別のツールからの「区切りで停止」で停止すると、残りは各自の次の区切りで停止する
  - 完了で停止すると、残りは完了した 1 台と同じ周回数まで実行してから停止する(周回数が同じか少ないレーンは自分で完了する)
  - 連動停止の後にほかの 1 台が停止したときも、その止まり方のほうが早く停止するレーンは、その止まり方に合わせて止め直す(早いのは、その場で、次の区切りで、周の終わりでの順)
  - 人が操作画面かコマンドでレーンを指して押した「停止」「区切りで停止」で停止したレーンは、連動停止のトリガーにしない(そのレーンだけを停止するために押したからである)。止め方を押したレーンでは、装置のボタンの短押しと別のツールからの停止も、押した止め方と区別できないので、トリガーにしない
  - 連動停止で停止させたレーンと、自分で完了したレーンも、連動停止のトリガーにしない。応答がないだけの「未検出」状態では停止させない

  合流点で相手を待つ台は、グループの中の自分以外の台がどれも「実行中」でも「選択待ち」でもなくなった時点で、待たずに通過する。未検出の台は、最後に読めた状態で数える(動いていた台は、戻るまで待つ)
- 一部のレーンだけを途中から始めたときは、相手が既に過ぎた回の合流点を待たずに通過する

**プリセット**: グループのひな形。どのレーンでどの手順を、何回、どの開始位置から始めるかに名前を付けて残したもの。一緒に始めるかどうかは持たない。それは呼び出したときの操作で決まるからである。装置は装置 ID で保存するので、装置を改名しても参照は切れない。

## 9. 手動操作

**定義**: 人の入力をそのまま装置へ通し、装置の出力として Switch へ送ること。

**関係**: 通した入力は記録して、手順やフレーム表の下書きに使える。

**意味論上の決まり**: 対象の装置を選んで、同時に 1 台だけ操作する。

## 10. 記録と通知

**実行記録**: 実行中に起きたことを、あとから振り返れる形で残す。装置が記録するのは、異常と、異常を調べる手がかりになる主なイベント(起動、実行の開始と終わり、状態の変化)である。異常と実行の終わりには、最後に通った区切りも残す。正常時の全フレームは記録しない。記録の負荷が実行の時間の正しさを損なわないようにするためである。グループの開始と終わり、周の区切り、判断の結果は、操作用の PC が記録する。停止した位置(5 節)は、装置がいま覚えている最後に通った区切りから出す。

**通知**: 実行の完了、異常停止、選択待ちへの到達、実行中の装置が未検出になったことの 4 つを、音、タブの表示、Windows の通知で知らせる。実行している間、画面を見ているとは限らないためである。

選択待ちを知らせるのは、人が選ばないと進まない待ちに入ったときである。残る選択肢が「手動」だけの待ちがこれにあたる。条件で進む選択肢がすべて判定できず、ほかに自動で進む道もない待ちも、人が選ぶしかないので知らせる。条件・スクリプト・時間切れ・相手の到着で終わる待ちと、合流点は知らせない。

グループの完了と異常停止は、グループごとに 1 通にまとめる。完了と知らせるのは、どれかのレーンが完了し、ほかのレーンが完了か区切りで停止した(装置のボタンの短押しや連動停止で、区切りで停止した)ときである。画面のタブの「完了」も同じ決め方である。

- 利用者が操作画面かコマンドでレーンを指して「停止」か「区切りで停止」で停止したレーンは、この判定から外す。手順の途中で役割を終えたレーンを停止し、残りを最後まで進めることがあるからである。外したレーンがあれば、通知は「1P が完了しました」のように、完了したレーンの名前で表す
- 全レーンを利用者が停止したときは、完了したレーンがないので知らせない
- 装置のボタンの長押しや別のツールからの「停止」で停止したレーンがあれば、そのレーンは予定の途中で停止しているので、完了とは知らせない
- 区切りで停止したレーンだけのときも、完了ではないので知らせない

## 11. プロジェクト

**定義**: 手順・フレーム表・条件・登録情報・プリセットと、一覧の表示順、手順のフォルダー分けと非表示を保存する場所。

**関係**: 実行に必要なものは、装置そのものを除いてすべてこの中にある。

**意味論上の決まり**: 装置がなくても、手順を作り、変換し、試せるデモ用の模擬装置を持つ。PC からの操作と実行の進み方は、実機と同じ経路で確認できる。Switch の上での動きと入力の時刻は、実機で確認する。
