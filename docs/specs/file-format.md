# 手順の保存形式

この文書が、手順の保存形式の正式な定義である。実装(`pctool/padcue/procfmt.py` と `pctool/padcue/frametable.py`)は、この文書に合わせる。

扱う概念の定義は concepts.md、方針は principles.md、要件は requirements.md にある。この文書は、それらをディスク上の形にしたものである。概念の語と欄の名前の対応は 12 節にまとめてある。

## 1. 方針

- 概念のブロックをそのまま書ける形にする。欄の名前は英字にする。
- 規則は、なるべく形で表す。形の上で書けない誤りは、チェックしなくて済む。「選択条件」を 1 つの欄にすること、「それ以外」を選択肢の並びの外に置くことは、この方針から導いている。
- 外から位置として指されるブロックだけが識別子を持つ。入力のブロックは持たない。手で書く量を減らすためである。
- ファイルどうしの参照は名前で書く。単体で受け取った 1 つのファイルがそのまま読め、手で書けることを、識別子で結び付ける強さより優先する。
- PC ごとに違うもの(装置、レーンの映像、映像ソースの実体)は、手順にも条件にも書かない。映像ソースは名前で指すだけにする。
- 読み込みで拒否するのは、値の形の誤りに限る。形は正しいが意味が成り立たないものは読み込みを通し、編集画面と変換で知らせる(8 節)。

## 2. 保存場所

```text
<プロジェクト>/
  procedures/<名前>.json                手順
  frametables/<名前>.csv                フレーム表
  conditions/<名前>/condition.json      条件
  conditions/<名前>/images/*.png        条件の画像
```

プリセット(`presets/<名前>.json`)の形は coupling.md D6 が定める。プロジェクトのフォルダーには、ほかに PC が書くものが置かれる。利用者が書くものではないので、この文書の対象にしない。

| 保存場所 | 中身 | 形を定める所 |
|---|---|---|
| `padcue.json` | 登録情報、本体の名前、Windows の通知を出す場面 | coupling.md D1 |
| `order.json` | 一覧の並び順、手順のフォルダー、非表示 | `project.py` |
| `sent/<id>.json`、`<id>.bin` | 送った手順のコピーと、送ったバイト列 | coupling.md D5 |
| `sent/sources/<定義の id>/` | 実行を開始した時点の手順、フレーム表、条件 | coupling.md D12 |
| `logs.jsonl`、`logs-*.jsonl` | ログ。書き込み中のものと、古い世代 | coupling.md D5 |
| `runstate.json` | 動いているグループの記録と、開始を拒否されたレーンの理由(サーバーを起動し直しても続ける) | `coupler.py` |
| `build/<名前>.bin` | 変換の結果を書き出したもの。転送には使わない | `project.py` |
| `gui_server.json` | 動いている操作画面のサーバーの目印 | coupling.md D10 |
| `<ファイル名>.<プロセスの番号>.<スレッドの番号>.tmp` | ファイルを書く間だけ、置き換え先と同じフォルダーに置く一時ファイル。書いている途中に強制終了されると残る。操作画面は、起動のときに、置いてから 1 分たったものを消す | `files.py` |

- 名前はファイル名そのものである。条件はフォルダー名である。ファイルの中に名前は書かない。同じ事実を 2 か所に持つとずれるからである。改名はファイル名の変更であり、ほかのファイルの中の参照は編集画面が書き換える。
- 改名のときに書き換えるのは、手順の中の `ref` と、プリセットのレーンの手順の名前 `proc`(6-2)である。実行の記録とログに残った手順の名前は書き換えない。プリセットは次に開始するためのグループのひな形なので、書き換えないと呼び出せなくなる。実行の記録は、その名前の手順をその時刻に実行したという過去の事実であり、後から名前を変えても変わらない。改名した手順の記録は、記録に残った古い名前のまま読む。
- 名前に使える文字はファイル名の制限に従う。120 文字まで、`/ \ : * ? " < > |` と `..` と、改行やタブなどの制御文字は使えず、先頭の `.`、末尾の `.`、先頭と末尾の空白、Windows の予約語(`CON` や `COM1` など。`NUL.txt` のように拡張子を付けた形も含む)も使えない。この規則は、ファイル名だけでなく、ファイルの中で名前を書く欄にも同じように適用する。`ref` の値がこれにあたり、読み込みでチェックする(8-1)。
- 末尾の `.` と空白を拒否するのは、Windows がファイル名とフォルダー名の末尾の `.` と空白を除くからである。通すと、条件「C.」は条件「C」のフォルダーに書かれ、名前の照合では別の名前なのに、元からある条件を上書きする。規則に合わない名前は、書き換えて通さずに拒否する。書き換えると、渡された綴りと書き込むファイルが一致しない。画面で名前を入力する欄は、入力の前後の空白を取り除いてから使う。
- フォルダーに規則に合わない名前のファイルがあっても、一覧には出さない。macOS が USB メモリや共有フォルダーへコピーするときに作る `._<名前>.json` がこれにあたる。どの読み書きも名前を規則で確認してから開くので、一覧に出しても開けず、エクスポートも削除もできない。
- PC の中だけで使う名前(装置の名前、本体の名前、フォルダーの名前)には、長さの上限 120 文字と制御文字の禁止だけを適用し、ほかの文字のチェックは適用しない。これらはファイル名にならないので文字のチェックは必要ないが、手順の名前と同じ一覧に並ぶので、長さは統一する。

  なお、名前から作るパスで最も長いのは、条件の画像を書く間だけ置く一時ファイル `conditions/<名前>/images/3f2a9c0d1b7e4a55.a1.png.<プロセスの番号>.<スレッドの番号>.tmp` で、名前が 120 文字、番号がどちらも 5 桁なら、プロジェクトのフォルダーから数えて 178 文字になる。このため、プロジェクトのフォルダーのパスが 80 文字を超えると、この規則で作った名前でも Windows のパスの長さの上限(終端の文字を含めて 260)を超えることがある。番号の桁が多ければ、もっと短いフォルダーでも超える。名前の長さは文字の数で数えるが、Windows はパスの長さを UTF-16 の単位で数え、絵文字のような文字は 1 文字を 2 単位と数える。そうした文字を含む名前では、もっと短いフォルダーでも上限を超えることがある。
- 名前の同一性は、Unicode の NFC に正規化したうえで、大文字と小文字を区別せずに(Python の casefold で)判断する。保存するファイル名は、受け取った綴りのままである(上の項のとおり、名前は書き換えない)。名前はファイル名そのものであり、Windows のファイルシステムは大文字と小文字を区別しないので、区別すると「Retry」と「retry」を同じフォルダーに置けない。macOS は NFD のファイル名を作るので、正規化しないと同じ名前が別のものとして二重に入る。この規則は、同じ名前があるかの判断と、インポートの照合(10-4)の両方で使う。
- 映像ソースの名前には、同一性の判断だけを同じ規則で適用する(前後の空白も無視する)。長さと使える文字のチェックは適用しない。映像ソースの名前は利用者が付けるものではなく、DirectShow のデバイス名やウィンドウのタイトルという、PC 側の名前だからである。この判断を使うのは、条件の「判定する映像」とスクリプトの `capture` が指す先を探すときと、開始の前のチェック(8-3)である。
- 文字コードは UTF-8 である。利用者が手で編集するファイル(手順、条件、プリセット、`padcue.json`、`order.json`、フレーム表)は、先頭の BOM を外して読む。エディターによっては BOM を付けて保存する。JSON の規格(RFC 8259)も、BOM を無視してよいとしている。PC が書くときは BOM を付けない。
- 条件を名前ごとのフォルダーにするのは、画像を複数持つからである。フォルダー 1 つが条件 1 件にあたり、`condition.json` が画像をそのフォルダーの中の相対の位置で指す。フォルダーの中の形(`condition.json` の欄と、`images/` の画像の名前)は 9-1 で定める。

## 3. ファイルの先頭の共通の欄

手順と条件と padcue ファイルの構成情報は、次の 2 つの欄で始まる。フレーム表の CSV は持たない。

| 欄 | 値の形 | 必須 |
|---|---|---|
| `kind` | `"procedure"`、`"condition"`、`"pack"` のどれか | 必須 |
| `format` | 整数。手順、条件、構成情報のどれも 1 | 必須 |

`kind` はファイルの種類であり、順に手順、条件、padcue ファイルの構成情報(10-1)である。先頭に書いてあるので、単体で受け取っても種類が分かる。`format` はこの形式のバージョンである。手順はこれに次が続く。

| 欄 | 値の形 | 既定 | 必須 |
|---|---|---|---|
| `precondition` | 文字列(前提条件) | `""` | 任意 |
| `body` | ブロックの配列 | なし | 必須 |

ツールが読むのは、`format` がツールの読み書きするバージョン(読めるバージョン)と同じファイルだけである(P25)。読めるバージョンより新しいファイルは「この手順は新しいバージョンの padcue で作成されています。padcue を更新してください」と拒否する。ほかの利用者と手順をやり取りすると、ツールのバージョンが一致しないことは起き、そのとき新しいバージョンのファイルを読めないことは避けられない。そこで、利用者が次に何をすればよいかを文で示す。それ以外(`format` がない、整数でない、読めるバージョンより小さい)は、ほかの欄の誤りと同じく、形式の誤りとして拒否する(8-1)。

padcue ファイルの構成情報(`pack.json`)も自分の `format` を持ち、同じ規則に従う。バージョンは手順や条件とは別に数える。読めないバージョンの構成情報は開かず、中の 1 件もインポートしない(10-1)。

フレーム表の CSV は `kind` も `format` も持たない。表計算でそのまま開ける表であることを優先するからである(P13、R15)。バージョンを書くには、すべての行に同じ値が並ぶ列を追加するか、ヘッダーに列ではない目印を置くことになり、どちらもその形を壊す。そのかわり、既にある列の意味と、空欄と書かなかった列の扱い(9-2)を変えると、既存のファイルを別の意味に読むことになる。列を追加すること自体は、未知のヘッダーの列を拒否するチェックで古いツールでも見つかる。列を増やす必要が出たときは、そのときにバージョンの持ち方から改めて決める。

知らない欄を読み込みで拒否すること(8-1)と、識別子を 6 種のブロックだけに持たせること(6-1)も、同じ「形式を厳しく保つ」規則である。前者の根拠は P28(予見できる失敗は作るときに知らせる)で、バージョンごとに既知の欄の集合が決まることが前提である。後者の根拠は P23(同一性は名前に頼らない)と、停止した位置が合流点とスクリプトを指すことである。

## 4. ブロック

ブロックは `{"type": ...}` のオブジェクトである。13 種ある。

### 4-1 どのブロックも持てる欄

| 欄 | 値の形 | 既定 | 必須 |
|---|---|---|---|
| `type` | 4-2 の一覧のどれか | なし | 必須 |
| `id` | 識別子(6 節) | なし | 6 種のブロックで必須 |
| `note` | 文字列(メモ) | `""` | 任意 |
| `disabled` | 真偽(真なら無効) | `false` | 任意 |
| `allow` | 文字列の配列(警告を承知だという指定) | `[]` | 任意 |

`disabled` が真のブロックを、無効にしたブロックと呼ぶ。無効にしたブロックは中身ごとなかったものとして扱い、時間も消費しない。編集画面の各ブロックの「有効」のチェックを外すと、この欄が真になる。この扱いが識別子の参照にどう及ぶかは 4-4 に定める。

`allow` に書けるのは、変換の警告のうち、意図して書くことがあるものの名前である。いま使える値は次の 2 つで、一覧にない値は読み込みで拒否する(8-1)。値をチェックしないと、綴りを間違えた値が黙って捨てられ、消したはずの警告が出続ける。

| 値 | 出なくなる警告 |
|---|---|
| `gyro-const` | ジャイロが一定の値のまま長く続く(8-3) |
| `branch-reset` | 選択肢が入力の状態を変えたまま合流する(8-3) |

| 種類 | `type` | 欄 | 値の形 | 既定 | 必須 |
|---|---|---|---|---|---|
| 押して離す | `press` | `buttons` | ボタン名の配列(1 つ以上) | なし | 必須 |
|  |  | `frames` | 整数 1..5184000 | なし | 必須 |

| 離す | `release` | `buttons` | ボタン名の配列(1 つ以上) | なし | 必須 |
| スティック | `stick` | `side` | `"L"` か `"R"` | なし | 必須 |

| 分岐 | `branch` | 5 節 |  |  |  |

`ref` はどの種類でも「別のファイルの名前」を意味し、値は 2 節の名前の規則でチェックする(8-1)。ボタン名は英字で書く(A、B、X、Y、L、R、ZL、ZR、PLUS、MINUS、HOME、CAPTURE、LS、RS、DU、DD、DL、DR)。A から ZR までは実物のコントローラーに書いてある文字で、ほかのボタンも英字の略号に統一した。

長さを表す欄(`frames` と `timeout_frames`)と `count` の上限は、どれも 5184000 とする。5184000 は 60fps で 24 時間である。装置の `frames` の欄は u32 なので約 828 日まで表せるが、そこまで許さないのは、桁を打ち間違えたときに気づけるようにするためである。`count` を同じ値に合わせたのは、上限を設ける目的が長さを表す欄と同じだからである。上限を書かないと、展開した後の総フレーム数が u32 を超えるかどうかだけが上限になる。

値域の外の値は、8-1 のとおり読み込みで拒否する。編集画面は、入力欄を離れた時点で、範囲の外の値を上限か下限に置き換える。手順とフレーム表の編集画面で、値域の外の入力への扱いを統一するためである。

### 4-3 くり返しの回数

回数は `count` と `laps` の 2 つの欄で表す。`laps` が真なら回数は周回数であり、実行のときに指定する。`count` の値は `laps` が真でも消えず、周回数が別のくり返しへ移ればその値に戻る。

`laps` が真のくり返しは 1 つの手順に 1 つまでである。呼び出し先の手順にあるものは 1 回として変換し、呼び出しのブロックに警告を出すので、ファイル 1 つの中の規則で足りる。

`laps` が真のくり返しは、選択肢の中身(`arms` の `body` と `otherwise`)にも、ほかのくり返しの中にも置けない。その 1 つが手順全体の周回を担当することが成り立たなくなるからである。選択肢の中では、選ばれない回に周を数えない。ほかのくり返しの中では、外のくり返しの 2 回目からも周を 1 から数え直し、何周目かを装置の状態から出せなくなる。置く位置の誤りは、編集の途中でくり返しを動かせばよく起きるので、読み込みは通し、作るときに知らせて変換が拒否する(8-2)。8-1 のチェックは数だけを見て、置く位置は見ない。

選択肢の中に置けるものと置けないものの判断は、別の手順を展開した後のツリーに対して行う。呼び出し先の手順にあるくり返しを見落とさないためである。4-4 が無効にしたブロックの扱いを「無効にしたブロックを取り除いた木」で定めているのと同じ書き方であり、この 1 か所で書けば、選択肢の中で 2 回以上くり返すくり返し(8-2)にも `laps` が真のくり返しにも同じように適用される。

### 4-4 無効にしたブロックと識別子の参照

無効にしたブロックは中身ごとなかったものとして扱う。この扱いは、識別子の参照にも同じように及ぶ。数えるときだけの例外を、2 つ目の項目に書く。

- 「対象の回」が無効にしたくり返しを指すときは、変換は指す先がないものとして扱って拒否する。その分岐がくり返しの中にあれば分岐も一緒になくなるので、この形は分岐が外にあるときにだけ起きる。編集画面はバッジを異常の色にする。拒否する文には、そのくり返しの名前と、無効になっていることを書く(無効にしたブロックの中にあるくり返しも同じである)。編集画面では取り消し線つきで見えているので、「見つかりません」とは書かない。有効に戻すだけでは分岐を囲まないので、分岐を中へ戻すことも書く。
- `laps` が真のくり返しの数(8-1)と識別子の重複(8-1)は、`disabled` を見ずに数える。手で書いたファイルで片方を無効にしておき、編集画面で有効に戻した瞬間にファイルが読めなくなる、ということを避けるためである。
- 変換は、無効にしたブロックを取り除いた木を入力にする。`laps` が真のくり返しがそれで 1 つもなくなれば、手順全体が周回数のくり返しになるので、`"@whole"` は指す先を持つ。
- 無効にした合流点は、グループの相手のレーンと合流点の名前を照合するときの集合に入れない。装置に AWAIT を出さないので、グループの相手のレーンが待つことはない。
- 停止した位置(6-2)が使う識別子(`path` と `block`)が、無効にしたブロックを取り除いた木に 1 つでもなければ、その位置から始める手順を作れない。開始位置の「停止した位置」を選べない状態にして、「停止した位置(見つかりません)」と出す。`turns` の回番号が、`path` と `block` から決まる囲むくり返しの数より多いときと、そのくり返しの回数を超えるときと、回番号が停止させたときと別のくり返しを指すようになったとき(`loops` が今の手順と合わない。6-2)も同じである。

値の形のチェックそのものは、無効にしたブロックには及ばない。読み込みが、中身を解釈する前に無効にしたブロックを取り除くからである。このため、`laps` の数と識別子の重複のチェックに当たらない形の誤りは、そのブロックを有効に戻したときに初めて読み込みで拒否される。無効にしたブロックまで形をチェックすると、無効にしたフレーム表のブロックの参照先がないだけで手順全体が読めなくなる(フレーム表の参照先は読み込みで確認する。6-3)。

## 5. 分岐と選択肢

```json
{
  "type": "branch",
  "id": "br-1",
  "name": "開始画面",
  "wait_input": "keep",
  "arms": [
    {"name": "1 周目",
     "when": {"loop": "lp-1", "kind": "first"},
     "body": []},
    {"name": "完了画面が出た",
     "what": {"kind": "condition", "ref": "完了画面"},
     "body": []}
  ],
  "otherwise": []
}
```

| 欄 | 値の形 | 既定 | 必須 |
|---|---|---|---|
| `name` | 文字列 | `""` | 任意 |
| `wait_input` | `"release"` か `"keep"` | `"release"` | 任意 |
| `arms` | 選択肢の配列。0 本でもよい | なし | 必須 |
| `otherwise` | ブロックの配列(「それ以外」の中身) | `[]` | 任意 |

`wait_input` は待つ間の入力である。`"release"` は待つ間に全入力を離し、`"keep"` は直前の状態を出し続ける。離すときは、変換器が選択待ちの直前に全入力を離した STATE を置く(binary-format.md「AWAIT レコード」)。合流点の `wait_input` も同じである。

選択肢が持つのは次の 4 つである。

| 欄 | 値の形 | 既定 | 必須 |
|---|---|---|---|
| `name` | 文字列。空でよい | `""` | 任意 |
| `when` | 「対象の回」。書かなければ回で絞らない | なし | 任意 |
| `what` | 「選択条件」。書かなければ待たない | なし | 任意 |
| `body` | ブロックの配列 | `[]` | 任意 |

### 5-1 「対象の回」

| 欄 | 値の形 | 必須 |
|---|---|---|
| `loop` | くり返しの識別子、または `"@whole"` | 必須 |
| `kind` | `"first"` `"last"` `"nth"` `"every"` `"remaining"` のどれか | 必須 |
| `n` | 整数 1 以上(編集画面は 5184000 を超える値を 5184000 に置き換える) | `nth`、`every`、`remaining` のとき必須 |

`kind` は順に、最初の回、最後の回、n 回目、n 回ごと、残り n 回である。

`loop` は必ず書く。「一番内側の囲むくり返し」を既定にして省略できる形にはしない。省略すると、読み込むたびにその時の入れ子から指す先を改めて決めることになり、後からくり返しを追加しても指す先は動かないという性質が成り立たなくなるからである。編集画面は、選んだ時点で一番内側のくり返しの識別子を既定として書き込む。

`"@whole"` は「手順全体」を指す。周回数のくり返しがない手順でも変換器が手順全体を SETCNT と DJNZ で囲むので、これは本当にくり返し 1 つぶんの意味を持つ。無効にしていない `laps` が真のくり返しがある手順では(4-4)、そのくり返しが周回数を担当し、手順全体は囲まれない。そのときの `"@whole"` は指す先がない扱いになり、変換を拒否する。読み込みは通す。

`"@whole"` を指す分岐がある手順を別の手順として呼んだときは、`laps` が真のくり返しを呼んだときと同じ扱いにする。呼び出し先の「手順全体」は 1 回として変換し、最初の回と最後の回はどちらも 1 回目になる。呼び出しのブロックには警告を出す。

`loop` に指定できるのは、同じ手順のファイルの中にあって、その分岐を囲むくり返しだけである。呼び出し元のくり返しは指定できない。理由は 2 つある。1 つ目は、呼び出し元の文脈が呼び出し先の意味を決める点が引数と同じであり、引数はこの形式には入れていないことである。2 つ目は、識別子は 1 つのファイルの中でしか一意でないので(6-1)、経路つきにすると、その「対象の回」を書いた手順は、その経路を通る呼び出しからしか変換できないことである。同じ手順を 2 か所から呼ぶ形でも、その手順を選んで単独で開始する形でも、変換を拒否されることになる。

呼び出し元の回数で呼び出し先の動きを変えたいときは、呼び出し元の側に分岐を置いて呼び分ける。切り出した中の分岐そのものを呼び出し元へ移すことになるので、共通の操作を別の手順へ切り出す単位は、そのぶん粗くなる。

指す先がない形(その識別子のくり返しがない形)と、その分岐を囲んでいない形は、読み込みでは通し、8-2 で知らせる。くり返しを削除すればよく現れるからである。

### 5-2 「選択条件」

| `kind` | 追加の欄 | 意味 |
|---|---|---|
| `"manual"` | なし | 手動 |
| `"condition"` | `ref`(条件の名前。2 節) | 条件 |
| `"script"` | `cmd`(空不可。改行と制御文字は不可)、`capture`(映像ソースの名前の配列。既定は `[]`) | スクリプトの結果 |
| `"timeout"` | `frames`(整数 1..5184000) | 時間切れ |

`what` を書かなければ「選択条件」は空で、その選択肢は待たない。1 つの欄なので、2 つ書くことがそもそもできない。1 つに限るのは、概念の定義による。concepts.md が「「選択条件」は、「手動」「条件」「スクリプトの結果」「時間切れ」のいずれかである」と定めており、1 つの欄にしたのは、その定義を形で表すためである。

分岐は時間切れの欄を持たない。時間切れは選択肢の「選択条件」であり、1 つの分岐に何本でも書ける。装置に渡せるのは最短の 1 本だけなので、残りは変換のときに知らせる。

その回に選ばれうる選択肢に「選択条件」のないものがあれば、その回は待たずにそれへ進む(「選択条件」を持つ選択肢は選ばれないので、変換が警告する)。「対象の回」を持たない選択肢はどの回にも選ばれうるので、それが「選択条件」を持たなければ、その分岐はどの回も待たない。「選択条件」を持つ選択肢が 1 本もない分岐も待たない。

待たない分岐でも `wait_input` の欄は消さない。画面では入力欄が無効になるだけで、選択肢や「選択条件」を追加すればまた有効になるからである。変換のときは使わない。

置いた直後の分岐は次のように書ける。

```json
{"type": "branch", "id": "br-2", "arms": [{"what": {"kind": "manual"}}]}
```

## 6. 識別子と参照

### 6-1 識別子を持つブロック

識別子を持つのは、ラベル、くり返し、分岐、合流点、スクリプト、別の手順の 6 種である。規則は 1 つで言える。外から位置として指されうるブロックが持つ。

- 区切りになるのは、ラベル、分岐、合流点、スクリプトである。変換器は AWAIT にマークを置き、スクリプトのブロックも AWAIT になる。`wait` が偽のスクリプトも AWAIT にするので、`wait` の値によって区切りになったりならなかったりすることはない。違うのは PC が SELECT を送る時点だけで、`wait` が真なら処理が終わってから送り、偽なら始めた時点で送る。
- 周の境を作るのはくり返しである。
- 呼び出しの経路を作るのは別の手順である。同じ手順を 2 か所から呼ぶと同じラベルが 2 つできるので、どちらの呼び出しかを示すために必要である。

押して離す、待つ、スティックのような入力のブロックは識別子を持たない。指す対象にならないからである。書いてあれば未知の欄として拒否する。

- 使える文字は英数字と `_` と `-` で、長さは 1 から 32 文字である。
- 編集画面が作るときは、種類の 2 文字と英数字 6 文字の乱数にする(`lb-a3f9c1` など)。同じファイルの中で重複しないことを確認してから書く。手で書くときは `lap` のような読める文字列でよい。
- `@` で始まる識別子は予約であり、利用者は付けられない。いまは `@whole` の 1 つだけを使う。
- 一意なのは 1 つのファイルの中だけである。別の手順に同じ値があってよい。位置は「呼び出しの経路と識別子」の組で表すので混ざらない。インポートのときに振り直さなくてよいのは、この性質による。
- 識別子は一度付けたら変えない。名前を変えても、くり返しで包んでも、並べ替えても同じ値のままにする。だから「対象の回」の指す先が動かない。

### 6-2 位置を指す(開始位置、停止した位置、プリセット、実行の記録)

実装では、変換の成果物が「区切りの表」を持つ。項目は、レコード番号、種類(ラベル、周の境、分岐、合流点、スクリプト)、名前、ブロックの識別子、呼び出しの経路、その位置を囲むくり返しのブロックの識別子(外側から順)と、それぞれが何回目かを求める対応表の項目、手順の先頭から数えたフレーム数である。手順全体を囲むくり返し(周回数のくり返しを書いていない手順で、変換器が置くもの)の識別子は空の文字列である。装置が返す「最後に通った区切り」はレコード番号なので、利用者に見せる言葉へ戻すのにも、その位置から始め直すのにもこの表を使う。

フレーム数は、実行の様子を図の上に出すためのものである。図は手順の全体を描くのに、装置が受け取った手順は開始位置から始まり周回数のぶんだけくり返すので、レコード番号は両者で対応しない。そこで、ブロックの識別子と呼び出しの経路で区切りを照合し、図の側のフレーム数を読む。同じ組み合わせの区切りが並ぶとき(周の境はどの周でも同じくり返しのブロックを持ち、「対象の回」の展開は同じブロックを複数回の区切りにする)は、同じ組み合わせの中の何番目かも合わせる。

位置は手順のファイルには書かない。開始の指示、プリセット、停止した位置、実行の記録が持ち、形は 1 つに統一する。

```json
{"name": "13 周目の「確認の前」", "path": ["cl-2"], "block": "lb-5", "turns": [13],
 "loops": ["lp-1"]}
```

11 節の「周回の手順」の `lp-1` の 13 周目に、`cl-2` が呼ぶ手順「やり直し」の中のラベル `lb-5` で停止した位置を、そこから始める開始の指示に含めた形である(「やり直し」はくり返しを持たないとする)。

| 欄 | 値の形 | 意味 |
|---|---|---|
| `path` | 「別の手順」の識別子の配列。既定は `[]` | 呼び出しの経路。外側から順 |
| `block` | ブロックの識別子。空の文字列は手順の先頭 | 木の中の点 |
| `turns` | 1 以上の整数の配列。既定は `[]` | 位置を囲む各くり返しの何回目か。外側から順 |
| `after` | 真偽値。既定は `false` | 真なら、`block` のブロックを終えた直後を指す |
| `loops` | くり返しの識別子の配列 | `turns` のそれぞれの回番号が、どのくり返しの回か。停止した位置だけが持つ |
| `waited` | 0 以上の整数。既定は `0` | 位置の選択待ちで既に待ったフレーム数。周回を終えるために、待ちの途中から続けるときだけ持つ |
| `name` | 文字列 | 見せるための名前。位置の照合には使わない |

- 開始位置が「先頭」のときは、位置ではなく `null` を書く。`path` と `block` が空で、`turns` がすべて 1 の位置も先頭と同じに扱う。
- 手順の名前は位置に含めない。位置と並べて持つ(開始の指示の `name`、プリセットのレーンの `proc`、停止した位置の `proc`)。
- 位置の照合は `path` と `block` で行う。同じ名前のラベルは呼び出しツリーの中に複数あり得るので、`name` では行わない。`name` は、ラベルの名前か「5 周目の先頭」のような呼び方である。
- `turns` は、`path` と `block` から木をたどって決まる囲むくり返しの並びに、外側から順に当てる。書かなかったぶんは 1 回目とみなす。周回数のくり返しを書いていない手順では、手順全体を囲むくり返しが一番外側に入る。囲むくり返しより多く書いた位置と、そのくり返しの回数を超える値は、変換が拒否する。
- `turns` は回番号だけを並べる。停止した位置は、回番号がどのくり返しの回かを `loops`(くり返しの識別子の配列。手順全体を囲むくり返しは空の文字列)にも持つ。周の境ならそのくり返し自身、ラベルや選択待ちならそれを囲むくり返しのすべてである。停止させた後で囲むくり返しを追加したり外したり、「周回数のくり返し」の指定を外したりすると、`turns` は同じ値のまま別のくり返しの回を指してしまう。そこで開始の前に、`loops` を今の手順の区切りの表と照合し、違えば始めない。開始位置の一覧から選んだ位置は `loops` を持たない(`turns` が空なので、混同する回番号がない)。
- `block` がくり返しを指す位置は、そのくり返しの、`turns` の最後の値の回の先頭を指す。周の境で停止した位置はこの形になる。手順全体を囲むくり返しの周の先頭は、`block` を空にして `turns` だけで書く。`{"block": "", "turns": [5]}` は 5 周目の先頭である。
- `waited` は、位置の選択待ちの時間切れを、その分だけ短くする。実行中に周回数を変えるために待ちの途中で停止させて続きから始め直すとき、待ちの長さを延ばさないためである。

位置を持つ所と、そこに入る位置は次のとおりである。

| 持つ所 | 入る位置 | 保存場所 |
|---|---|---|
| 変換器の開始位置の一覧 | 先頭と、名前の付いたラベルのすべて(実行されない「それ以外」の中のものを除く。7 節)。`turns` は `[]` | 変換の成果物 |
| 開始の指示(`/api/run` の `start`) | 開始位置の一覧の項目か、停止した位置。先頭なら書かない | 送るだけ |
| プリセットのレーンの `start` | 先頭(`null`)か、開始位置の一覧のラベル | `presets/<名前>.json`(coupling.md D6) |
| 停止した位置(`/api/state` の `stopped_at`) | 最後に通った区切りから作った位置(coupling.md §6)。`turns` に囲むくり返しのそれぞれの回番号を並べ、`loops` を付ける(`after` の位置を除く) | 持たない。そのつど求める |
| 実行の記録 | 開始した位置に、種類(`kind` が `head`・`lap`・`label`・`wait`)を付けたもの | `runstate.json` |

ログ(`logs.jsonl`)の開始の行には、位置の `name` だけを残す。

- 開始位置の一覧の項目には、そこから始めたときに周回数が反映されるか(`uses_laps`、真偽値)も付ける。周回数のくり返しより後ろのラベルから始めると、続く手順にはもうくり返しがないので、画面は周回数の欄を無効にする。周回数のくり返し(書いていなければ手順全体)の中に、分岐を通らずに行き当たる無限のくり返しがある手順は、2 周目に到達しないので、どの位置も偽にする。欄の title には、指定できない理由を出す。分岐の中の無限のくり返しは、その選択肢へ進む回だけのことなので、偽にはしない(その周で行き当たれば、変換が警告する。8-3)。
- プリセットが保存できるのは「先頭」とラベルだけである。「停止した位置」は前回の実行に結びついた一度きりの位置なので、次に開始するためのひな形には入れない。
- 手順の改名では、プリセットのレーンの `proc` を書き換える。実行の記録とログに残った手順の名前は書き換えない(2 節)。
- プリセットの位置が指す識別子が、いまの手順になくても、呼び出しは拒否しない。ラベルを削除したり、そのラベルを含む呼び出しを削除したりすればよく起きる。プリセットは次に開始するためのグループのひな形であり、呼び出せなくなるとグループを作り直せなくなるからである。そのレーンの開始位置の欄は「2 周目から(見つかりません)」になり、開始できない。レーンで選んでいたラベルを削除したときと同じ扱いで、黙って先頭にはしない(先頭から実行してしまう)。

  プリセットの手順そのものがないときも同じで、手順の欄が「周回の手順(見つかりません)」になる。位置が見つからないことを理由に、プリセットのファイルを書き換えることはしない。

  ただし、手順を保存するとプリセットの位置が見つからなくなるとき(ラベルか、そこへの呼び出しを削除したか無効にしたときと、呼び出す手順を替えたとき)は、画面が保存してよいかを確認する(`/api/procedure/lost_starts` が、保存する中身で位置を探し直して返す)。レーンが開始位置に選んでいる位置も、画面が送って同じく確かめる。既に見つからない位置について、保存のたびには聞かない。
- 停止した位置から始め直せるのは、ラベル、周の境、選択待ち(分岐、合流点、スクリプト)のどれかで停止したときである。選択待ちから始めると、その選択待ちからやり直す。回番号は、位置を囲むくり返しのそれぞれについて、装置の状態から出す(下の対応表)。最後の周の終わり(周回数のくり返しを抜けた所)で停止した位置は、周回数のくり返しの直後(`after`)を指し、そこから始めると、くり返しの後ろのブロックを実行する。`after` で表すのは、ほかの 2 つの表し方に次の問題があるからである。周の境と同じく回番号(`turns`)で表すと、周回数を変えて始めたときに別の位置になる。周の先頭から始めると、終えた周をもう一度実行してしまう。停止させた後に手順を修正して位置がなくなったときは、「停止した位置(見つかりません)」になって開始できない。

装置が返すのはレコード番号と各カウンターの値だけなので、変換は、レコード番号を区切りへ戻す区切りの表と、カウンターの値をくり返しの何回目かへ戻す対応表を一緒に出す。対応表は 2 つある。周回数のくり返しの何周目かを出すものと、区切りを囲むくり返しのそれぞれの何回目かを出すものである。「対象の回」の展開で複製した区間は、それぞれ別の項目になる。位置から始めた実行は、位置を囲むくり返しの途中の回をくり返しの外へ展開するので、その中の区切りには、回番号をそのまま持つ項目を当てる。停止した位置の表示にも、続きの手順を作るときの入力にも、この向きの対応を使う。装置が返すカウンターの並べ方は装置と PC の間の仕様である。

プリセットの形式は coupling.md の D6 に、実行の記録は coupling.md §6 に書く。ラベル、くり返し、分岐、合流点、スクリプト、別の手順は、名前とは別の変わらない識別子を持つ(P23)。

### 6-3 ファイルどうしの参照

別の手順は `{"type": "call", "ref": "やり直し"}`、フレーム表は `{"type": "frametable", "ref": "連続入力"}`、条件は `{"what": {"kind": "condition", "ref": "完了画面"}}` と、どれも名前で書く。

名前で書く理由は 3 つある。1 つ目は、単体で受け取った 1 つのファイルがそのまま読めることである。識別子で結び付けると、手順だけを渡されたときに参照が何も指さない文字列になる。2 つ目は、手で書けることである。3 つ目は、改名のときに参照を書き換える仕組みが既にあり、インポートの改名も同じ仕組みで済むことである。

条件の参照は、読み込みでも変換でも存在を確認しない。条件は手順より後に作れるからである。開始の前にチェックし、なければ知らせる(8-3)。別の手順の参照は、読み込みでは確認せず、変換のときに確認する。フレーム表だけは、読み込みのときに確認する。読み込みが列の並びと行数までを取り出すからである。このため、参照するフレーム表がない手順は開けない。書きかけのファイルを必ず開けるという 8 節の規則の、ただ 1 つの例外である。

別の手順の呼び出しは循環してはならない。A が B を呼び、B が A を呼ぶ形も、手順が自分自身を呼ぶ形も同じである。「別の手順」は展開なので、循環があると変換も、依存関係をたどる処理(10-2)も終わらない。読み込みは通し、変換が拒否する(8-2)。読み込みで拒否しないのは、ファイルの中に自分の名前が書かれていないからである(2 節)。自分自身を呼ぶ形さえも、ファイル名との関係でしか分からない。

## 7. 「それ以外」の中身の保存場所

分岐の `otherwise` という欄に、ブロックの配列として持つ。選択肢の並び(`arms`)には入れない。理由は 4 つある。

1. 選択肢の並びに入れると、「対象の回」も「選択条件」も持たない選択肢と区別が付かない。その形は利用者が書ける正しい選択肢であり、どの回でも待たずに選ばれるものを意味する。同じ配列に入れると、どちらの意味なのかがデータから読めなくなる。
2. 「それ以外」は利用者が置く行ではない。選択肢の並びに入れると、並べ替えや削除の対象になってしまう。
3. 「それ以外」は、選ばれうる回がなくなれば行が消える。欄にしておけば、行が消えている間も中身がファイルに残り、条件が揃えば同じ中身のまま戻る。くり返しの `count` を、周回数を選んでも消さないのと同じ考え方である。
4. 選択肢の数の数え方が曖昧にならない。「それ以外」は待たないので、装置の上限 10 本に数えない。数えるのは、選択待ちになる回に「対象の回」で絞った後に残る `arms` だけである。「選択条件」を持たない選択肢が残る回は待たずに進むので、数えない。

中身が空なら「その回は続きへ進む」の意味になる。既定が空なので書かなくてよい。

「それ以外」が選ばれうるのは、選択肢が 1 本以上あり、どれも「対象の回」を持つ分岐だけである。「対象の回」を持たない選択肢はどの回にも残るので、1 本でもあれば、その回は「選択条件」がなければその選択肢へ、あれば選択待ちへ進み、「それ以外」へは進まない。編集画面が「それ以外」の行を出すのも、この分岐だけである。

行が消えている分岐(選ばれうる回がない分岐)の `otherwise` に中身があるときは、読み込みは通し、変換では使わず、作るときに「「それ以外」に中身がありますが、この分岐で「それ以外」が選択される回はありません」と知らせる。黙って捨てると、書いた入力がどこにも現れない。その中のラベルは開始位置の一覧に出さない。開始位置に指定されたときは、手順の中にない位置として変換が拒否する(8-2)。そこから始めると、手順が一度も実行しない中身を実行することになるからである。

選択肢が 0 本の分岐も、この扱いに含む。選択肢が 0 本の分岐は、行が消えている分岐にあたるので、`otherwise` の中身は変換では使わず、中身があれば作るときに知らせる。分岐を一時的に空にして中身を残す編集はよく起きるので、この差は実際に出る。この分岐は AWAIT を出さないので、区切りにもならない。

## 8. 読み込みと変換のチェック

チェックを 2 つに分ける。値の形の誤りは読み込みで拒否する。JSON として読めるか、文字コード、欄の名前、ブロックの種類、必須の欄、値の型と値域、決まった値、識別子の形と重複、名前の形(2 節)がこれにあたる。形は正しいが意味が成り立たないものは読み込みを通し、編集画面と変換で知らせる。指す先がない「対象の回」のように、編集の途中でよく起きるものだからである。書きかけのファイルを必ず開けるようにするためであり、1 つのファイルが壊れていてもほかの手順は開ける。一覧には「エラー」として出し、開くと理由を出す。

8-2 と 8-3 は、手順の形から決まる拒否と警告のうち、読み込みを通した後に出るものの一覧である。変換が出すものと、開始の前のチェックが出すものを、行ごとに書き分けてある。手順の形から決まるものは、ここに書いたものですべてである。開始の前のチェックは、このほかに、装置とレーンの組み合わせについても拒否と警告を出す(coupling.md D8)。「編集画面が知らせる」と書いたものも、変換か開始の前のチェックが同じチェックを行って結果を返し、開始のときに画面と実行記録に出す。手で書いた手順と、単体のファイルとしてインポートした手順は、編集画面を通らずに開始できるからである。例外は 1 フレームの入力の注意で、手順を書いている人に向けたものなので、編集画面だけが出す(8-3)。

8-2 と 8-3 のメッセージは、ブロックの番号(「3 番目のブロック」)で場所を示す。番号は手順のファイルの中のブロックを上から 1、2、…と数えたもので、無効にしたブロックとその中のブロックも数える。入れ子は外のブロックの次に中身を数え、分岐の中は選択肢の順に、最後に「それ以外」を数える。編集画面の列に見えている順と同じである。

警告は、変換した手順(編集画面では開いている手順、実行の画面では開始した手順)の中の番号で示すので、コマンドの文、編集画面、実行の画面の「N 番目」は同じブロックを指す。呼び出し先の中の警告は、その手順の画面では指せないので、そこへ入っていく呼び出しのブロックの番号で「3 番目(別の手順)」と示す。変換の失敗は、失敗したブロックのあるファイルの名前を付けて、そのファイルの中の番号で示す。呼び出し先の中の失敗は、呼び出し先のファイルとその中の番号になり、編集画面はそこへ入っていく呼び出しのブロックを指す。8-1 の読み込みの失敗は、番号ではなくファイルの中のパスで示す(下の表の後)。

### 8-1 読み込みで拒否する形

| 拒否する形 | 知らせ方の例 |
|---|---|
| JSON として読めない | ファイルが壊れています。12 行目 3 文字目から読み込めません。 |
| 文字コードが UTF-8 でない | 文字コードが UTF-8 ではありません |
| 入れ子(オブジェクトと配列)が 256 段を超える | 入れ子が深すぎます。ブロックの入れ子を浅くしてください。 |
| `kind` が違う、またはない | 手順ファイルを指定してください |
| `format` が読めるバージョンより新しい | この手順は新しいバージョンの padcue で作成されています。padcue を更新してください。 |
| `format` が読めるバージョンでない(上の行を除く) | format は 1 である必要があります: "1" |
| 未知の `type` | サポートされていないブロックの種類です: "button_hold"。使用できるのは "press"、"hold"、"release"、... です。 |
| 未知の欄 | 使用できない項目です: cond。使用できるのは allow、disabled、frames、note、type です。 |
| 必須の欄がない | 長さ(frames)がありません |
| 値の型が違う、値域の外 | frames は 1 から 5184000 までの整数である必要があります: 0 |
| 決まった値のどれでもない | wait_input は "release"、"keep" のいずれかである必要があります: "hold" |
| 未知のボタン名 | 使用できないボタン名です: "Z"。使用できるのは "A"、"B"、"X"、... です。 |
| 識別子に使用できない文字 | 識別子に使用できるのは英数字と _ と - です |
| 識別子が 33 文字以上 | 識別子は 1 から 32 文字である必要があります |
| 識別子が `@` で始まる | @ で始まる識別子は使用できません |
| 識別子が必要なブロックに `id` がない | id がありません。ラベルには id が必要です(例: "id": "lb-1")。 |
| 同じファイルの中で識別子が重複 | 識別子 lp-1 が 2 か所にあります |
| 参照するフレーム表がないか読めない | フレーム表「連続入力」が見つかりません。別のフレーム表を選択してください。 |
| `ref` が名前の規則に合わない | 名前に「/」は使用できません。使用できない文字は ... です。 |
| `count` が 0 以下 | count は 1 以上である必要があります。無限にするときは "infinite" を指定してください。 |
| `count` が数でも `"infinite"` でもない | count は 1 以上の整数か "infinite" である必要があります: "たくさん" |
| `laps` が真のくり返しが 2 つ以上 | 周回数を指定できるくり返しは手順の中で 1 つだけです |
| `timeout` の `frames` が 1 未満 | 時間切れは 1 フレーム以上である必要があります |
| `what` が null | what には kind が必要です。待たない選択肢では what を省略します。 |
| `what.kind` が一覧にない | サポートされていない kind の値です: "cond"。使用できるのは "manual"、"condition"、"script"、"timeout" です。 |
| `when.kind` が一覧にない | サポートされていない kind の値です: "middle"。使用できるのは "first"、"last"、... です。 |
| `when` に `n` が必要なのにない | kind が "nth" のときは、1 以上の整数の n が必要です |
| `when` の `n` が必要ない `kind` に付いている | kind が "first" のときは n を使用できません |
| `when.loop` がくり返し以外の識別子を指す | 「対象の回」に指定できるのはくり返しだけです: lb-1 はラベルです |
| `allow` に一覧にない値がある | サポートされていない allow の値です: "gyro_const"。使用できるのは "gyro-const"、"branch-reset" です。 |

決まった値のどれでもないときは、受け付ける値をそのまま並べて知らせる。全角の空白や似た字の打ち間違いは、値を見比べないと分からないからである。

`ref` を名前の規則でチェックするのは、この値の型が「名前」であり、変換とインポートがその値をそのままファイルの場所として使うからである(2 節)。手で書いた `{"type": "call", "ref": "../x"}` をここで拒否しないと、保存先の外を指す参照が読み込みを通ってしまう。

`what` を null にする形を拒否するのは、待たない選択肢を「`what` を書かない」形で表すからである(5-2)。null も許すと、同じ意味を 2 通りで書けることになり、ツールごとにどちらを書くかが分かれる。

`when.loop` がくり返し以外の識別子を指す形をここで拒否するのは、`loop` の値が「くり返しの識別子」という型だからである。「対象の回」に指定できるのは同じファイルの中のくり返しだけなので(5-1)、このチェックは 1 つのファイルを読むだけで行える。編集画面は囲むくり返しの一覧からしか選ばせないので、この形は手で書いたときにしか現れない。指す先がない形と囲んでいない形は、くり返しを削除すればよく現れるので 8-2 に置く。

`laps` が真のくり返しの数と識別子の重複は、`disabled` を見ずに数える(4-4)。

入れ子の深さに上限を設けるのは、読み込み、変換、インポートが、どれも入れ子をたどって処理するからである。上限がないと、手で書いた深い入れ子の手順 1 本で、処理が途中で異常終了する。256 段は、分岐だけなら約 60 段、くり返しだけなら約 120 段の入れ子にあたる。くり返しは装置のカウンターの数で 32 段までなので(8-2)、実行できる手順はこの上限よりずっと浅い。

場所は、ファイル名と、ファイルの中のパスと、そのブロックの識別子で伝える。パスは `body[12].arms[1].body[0]` のように書く。手で開いたときにそのまま探せる形にする。

### 8-2 読み込みは通し、変換か開始で拒否する形

| 形 | どこで拒否か |
|---|---|
| 「対象の回」の指す先がない、またはその分岐を囲んでいない | 編集画面が異常の色にし、その分岐を変換するときに拒否 |
| `laps` が真のくり返しがあるのに `"@whole"` を指す | その分岐を変換するときに拒否 |
| 選択待ちになる回に、「対象の回」で絞った後の選択肢が 11 本以上残る | 編集画面がチェックし、変換が拒否 |
| 別の手順の呼び出しが循環している(自分自身を呼ぶものを含む) | 編集画面が異常の色にし、変換が拒否 |
| 選択肢の中に `laps` が真のくり返しがある | 編集画面が知らせ、変換が拒否 |
| ほかのくり返しの中に `laps` が真のくり返しがある | 編集画面が知らせ、変換が拒否 |
| くり返し(周回数のくり返しを書いていない手順では手順全体)の 1 回が時間を進めない | 変換が拒否 |
| くり返しの入れ子が深く、同時に使うカウンターが 32 本を超える | 変換が拒否 |
| 「対象の回」の展開で区間が 3070 本を超える | 変換が拒否 |
| 展開後の総フレーム数か、1 回の時刻の進みか、レコードの時刻が u32 を超える | 変換が拒否 |
| 別の手順の参照先がないか、読めない | 変換が拒否 |
| 装置に入るレコード数が 3071 を超える | 変換が拒否する。編集画面は割合を示す |
| レーン間で、合流点の名前か、周ごとの個数が一致しない | 開始の前のチェックが拒否 |
| レーン間で、周回数のくり返しの外の合流点が一致しない | 開始の前のチェックが拒否 |
| 選択待ちになる選択肢の中に、中身が時間を進めるくり返しのうち、回数が 2 以上(無限を含む)のものがある | 変換が拒否 |
| 選択待ちになる選択肢の中から、そうしたくり返しを含む手順を呼ぶ | 変換が拒否 |
| 周回数のくり返しを、変換で一度も通らない場所に置いている | 変換が拒否 |
| 開始位置より前に無限のくり返しがある | 変換が拒否 |
| 開始位置の回番号が、囲むくり返しの数より多いか、そのくり返しの回数を超える | 変換が拒否 |
| 開始位置のブロックか呼び出しの経路が、手順の中にない | 変換が拒否 |
| ゆらぎを付けたジャイロの `frames` を `sway_period` で割った商が 100000 を超える | 変換が拒否 |

参照の先がないことを読み込みで拒否しないのは、参照の先を作る前に手順を保存できなくなるからである。フレーム表の参照先だけは、読み込みで拒否する(6-3)。

条件と映像ソースの参照先がない形だけは、どこでも拒否しない(8-3)。参照先が見つからない選択肢が自動で選ばれなくなるだけで、選択肢は「選択条件」が何であっても人が選べるので、手順が止まったままにはならない。拒否すると、ほかの利用者から受け取った手順が、条件をインポートするまで 1 回も動かせなくなる(10-3)。

「変換が拒否する」と書いたものは、編集画面でも知らせるが、変換でもチェックする。手で書いた手順と、単体のファイルとしてインポートした手順は、編集画面を通らずに開始できるからである。

拒否する理由は次のとおりである。

- 選択待ちの選択肢が 11 本以上になる回があるもの、選択肢の中に `laps` が真のくり返しがあるもの、呼び出しが循環しているものは、どれも装置の形に変換できない。警告では開始を止められないので、拒否にする
- 1 回が時間を進めないくり返しは、装置が同じ予定時刻の DJNZ をくり返し実行し続けることになる
- カウンターが 32 本を超えるものは、装置が実行できない。入れ子に入るときは SETCNT が、出るときは DJNZ が時刻を進めずに続き、装置は 1 回のアラームで時刻を進めないレコードを 64 件までしか適用しないからである(binary-format.md「整合性検証」)。半分の 32 にして、同じ時刻に並ぶほかのレコードの分を残す
- 総フレーム数か 1 回の時刻の進みが u32 を超えるものは、装置のレコードに書けない
- 周回数のくり返しを無限のくり返しの後ろに置くと、周回を数えるカウンターも周の境もない手順になり、周回数が警告なしに消える
- ゆらぎの上限は、変換が作る入力の切り替えの数を抑えるためのもので、超える長さは装置に入るレコード数(3071)にも収まらない

中身に選択待ちがあるくり返しは、時間を進めなくても通す。くり返しの 1 回が進める時間は選択待ちになる選択肢の中身を数えずに決まるので、操作をすべて選択肢の中に書いた「毎周、選んでから操作する」形は 1 回の長さが 0 になるが、これはよく書く形である。判断は、変換した 1 回の中身に、時間を進めるレコードも AWAIT も 1 つもないかどうかで行う。「対象の回」で区間に分かれたくり返しでは、区間ごとにこの判断を行う。中身がまるごと「対象の回」の付いた選択肢の中にある手順では、当てはまらない回の区間が空になるので、その区間が 2 回以上にわたると拒否される。くり返しの中に、分岐の外の待ちか操作を 1 つ置けば通る。

「対象の回」の展開で区間が 3070 本を超えるものを拒否するのは、区間 1 本につき先頭のレコードが少なくとも 1 つ必要で、終わりの END も 1 つ必要なので、どう詰めても装置に入らないからである。

区間の数は数え上げる前に見積もる。「1000000007 回ごと」のように大きな周期を書くと、1 回ずつ見ていては数え上げるだけで終わらなくなるからである。区間の境界になるのは「n 回ごと」に当てはまる回とその次の回だけなので、見積もりは、その範囲の中の当てはまる回 1 つにつき 2 本に、最初の 1 本を足した数とする(範囲の回の数を超えることはない)。

周期が大きいほど当てはまる回はまばらになり、区間は少なくなる。「5000 回ごと」を 100000 回のくり返しに書いた形は 1 周期が 2 本にしか分かれないので、拒否されない。数え上げも当てはまる回だけをたどるので、見積もりを通ったものは同じ大きさで終わる。

装置に入るレコード数の上限は 3071 件である。装置が 1 つの手順データを受け取る大きさは 96KiB(98304 バイト)で、ヘッダーが 18 バイト、レコードが 32 バイト固定なので、(98304 - 18) / 32 の商である。3072 件では 98322 バイトになって収まらない。超えたものは変換が拒否する。警告にすると、装置へ転送する段になって初めて失敗する。

レコード数は、変換の成果物が手順ごとの件数として持つ。編集画面は、通常は出さず、上限の半分を超えた手順を開いたときだけ「装置の容量の N% を使用」と出す。通常は知らなくてよい数で、超える前に気づければ足りるからである。

「対象の回」の展開は 1 つのくり返しを区間の数だけ並べるのに、編集画面には元のくり返しが 1 つ見えるだけである。そのため、拒否するときの文には減らし方を並べる。くり返しの回数を減らすことと、同じくり返しに割り切れない「n 回ごと」を並べないことである(そのブロックを別の手順へ切り出してもレコード数は減らない)。

拒否する文が指すのは、レコード数を最も多く使っているブロックである。呼び出し先の手順の中のブロックは開いている手順の画面では指せないので、そこへ入っていく呼び出しのブロックを指し、呼び出し先の手順の名前とレコード数を示す。

選択待ちになる選択肢の中では、中身が時間を進めるくり返しのうち、回数が 2 以上のものを変換が拒否する。無限のものも同じで、そうしたくり返しを含む手順を選択肢の中から呼ぶことも拒否する。選択肢ごとの長さの違いは、選択待ちの後の時刻をずらして運ぶ(binary-format.md の ARMJOIN)。くり返しの回数で決まる長さは、このずらす量に含められないからである。回数が 1 のくり返しと、「対象の回」で 1 回ずつの区間に分かれるくり返しは、展開されて数えるものが残らないので、拒否しない。中身の時間がすべて選択待ちの選択肢の中にあるくり返し(毎回選んでから操作する形)も拒否しない。中身が時間を進めないので、回ごとの長さはすべて選択肢の長さとして、このずらす量に含まれるからである。待たずに選ばれる選択肢と「それ以外」の中身は、分岐の位置にそのまま並べるので、くり返しを置ける。

### 8-3 読み込みは通し、警告にとどめる形

| 形 | 知らせ方 |
|---|---|
| 合流点の `name` が空 | 変換で警告 |
| ラベルの `name` が空 | 変換で警告。開始位置の一覧に出せない |
| 同じ名前のラベルが 1 つの手順に 2 つ以上ある | 変換で警告 |
| 無限のくり返しより後ろに、到達しないブロックがある | 編集画面と変換で知らせる。呼び出し先が原因なら呼び出しのブロックに出す |
| 区切りを 1 つも含まない、周回数ではない無限のくり返し | 編集画面と変換で知らせる |
| 周回数のくり返しの中に、分岐を通らずに行き当たる無限のくり返しがある | 変換で警告。周回数は使用されない |
| 周回数のくり返しのない手順に、分岐を通らずに行き当たる無限のくり返しがあり、2 周以上を指定した | 開始のときの変換で警告。周回数は使用されない |
| 周回数のくり返し(なければ手順全体)の、最後ではない周で、分岐の中の無限のくり返しに入る | 変換で警告。その後ろの周には到達しない |
| 長さが 1 フレームの入力 | 編集画面がその欄の下で知らせる。変換は知らせない(8 節の例外) |
| 呼び出し先の手順に `laps` が真のくり返しがある | 変換で警告。1 回として変換する |
| 呼び出し先の手順に `"@whole"` を指す「対象の回」がある | 変換で警告。1 回として変換する |
| 選ばれる回がない分岐の `otherwise` に中身がある | 編集画面と変換で知らせる |
| 到達しない選択肢がある | 編集画面と変換で知らせる |
| 1 つの分岐に時間切れが 2 本以上ある | 変換で警告。最短の 1 本だけを装置に渡す |
| 選択肢が入力の状態を変えたまま合流する | 変換で警告。`allow` に `branch-reset` を書けば出ない |
| 同じフレームで押下か「離す」が打ち消される | 変換で警告。その入力は出力に現れない |
| 同じフレームで、スティックかジャイロの同じ軸を 2 回設定する | 変換で警告。先に設定した値は出力に現れない |
| 長さ付きのスティックの倒し終わりと同じフレームで、同じスティックを倒し直す | 変換で警告。中央に戻らず、倒したままになる |
| ジャイロが一定の値のまま長く続く | 変換で警告。`allow` に `gyro-const` を書けば出ない |
| ゆらぎが長さ 0 のジャイロに書かれている | 変換で警告。有効にならない |
| ゆらぎの幅を足すと、ジャイロの値が i16 の範囲を超える | 変換で警告。超えない幅まで縮める |
| 待たない分岐に `wait_input` がある | 変換では使わない。警告は出さない |
| 条件か、映像ソースの名前の参照先がない | 開始の前のチェックで警告。条件の選択肢は自動では選ばれず、スクリプトにはその映像を渡さない |
| 条件に基準画像がない | 開始の前のチェックで警告。その選択肢は自動では選ばれない |
| 条件が読めない(形の誤り、壊れたファイル) | 開始の前のチェックで警告。その選択肢は自動では選ばれない |
| 条件かスクリプトの `capture` が見る「装置に設定している映像」が、装置に設定されていない | 開始の前のチェックで警告。条件の選択肢は自動では選ばれず、スクリプトにはその映像を渡さない |
| 条件かスクリプトの `capture` が見る「装置に設定している映像」が、この PC にない | 開始の前のチェックで警告。条件の選択肢は自動では選ばれず、スクリプトにはその映像を渡さない |
| 装置に設定している映像の設定が読めない(手で書き換えた `padcue.json`) | 開始の前のチェックで警告。条件の選択肢は自動では選ばれず、スクリプトにはその映像を渡さない |
| レーン間で、合流点を通る回数が選択待ちの選び方で変わる | 開始の前のチェックで警告 |
| レーン間で手順か周回数が違い、合流点を通る回数が周によって変わる(「n 回ごと」の選択肢の中など) | 開始の前のチェックで警告 |

「ジャイロが一定の値のまま長く続く」は、0 でない同じ値が 60 フレームを超えて続く区間である。くり返しは、中身の間ずっと値が変わらなければ、すべての回を通した長さで数える。分岐の出入りと、中身で値が変わるくり返しの回の境界では測り直すので、境界をまたいで同じ値が続く区間は短く見積もり、警告しないことがある。中身に分岐かくり返しがあるときと、回の途中で値を変えて同じ値に戻すときがこれにあたる。

「到達しないブロックがある」は、無限のくり返しの後ろに同じ中身の中で並ぶもの、囲むくり返しの、無限のくり返しに入った回より後ろの回とその後ろ、呼び出し先が無限のくり返しで終わるときの呼び出し元の続きを含む。囲むくり返しの警告は、入った回の次の回番号で示す(「3 回目」の選択肢の中の無限なら「4 回目以降」)。最後の回で入るとき(回数が 1 のくり返しを含む)は、どの回も実行するので出さない。そこにあるラベルも開始位置の一覧には出るが、選ぶと変換が拒否する(8-2)。

周回数のくり返しの中に、分岐を通らずに行き当たる無限のくり返しがあると、1 周目から先へ進まないので、周回数に何を指定しても結果は変わらない(開始位置の一覧の `uses_laps` が偽になる範囲と同じである。6-2)。周回数のくり返しに指定したこと自体が中の無限と矛盾するので、周回数によらず知らせる。周回数のくり返しのない手順では、手順を無限のくり返しで終えるのは普通の書き方で、周回数を指定しなければ矛盾はない。2 周以上の数を指定して開始したときだけ知らせ、周回数を無限にしたときは知らせない。

無限のくり返しが「対象の回」の付いた選択肢の中にあると、入るのはその選択肢へ進む周だけで、周回数は結果を変える(「最後の回」だけ停止させるまで続ける形など)。入る周が最後の周でなければ、「3 周目で無限のくり返しに入るため、4 周目以降には到達しません」のように、入る周と到達しない周を示す。最後の周で入るなら知らせない。周回数を決めない変換(編集画面と一覧。周回数 1 として変換する)では、1 周目が最後の周なので、1 周目で入る形も開始のときまで知らせない。

「到達しない選択肢がある」は、先頭からすべての周を通した変換で数える。途中の位置から始めた続きと、最後の回を解決しない続きでは数えない(前の周を通らない)。周回数を決めない変換では、周回数のくり返し(なければ手順全体)を指す「対象の回」(「最初の回」を除く)を持つ分岐を数えず、開始のときの変換(実行の周回数)で知らせる。周回数 1 として数えると、「5 回目」も「3 回ごと」も、「最初の回」と並べた「最後の回」も、選ばれないことになるからである。

同じ名前のラベルを警告にとどめるのは、位置を識別子で表すので実行に曖昧さがないからである。困るのは開始位置の一覧に同じ文字列が 2 つ並び、利用者がどちらを選んだのか分からないことだけで、名前が空のラベルと同じ性質なので、扱いも統一する。なお、開始位置の一覧は呼び出しツリーのすべてから作るので、同じファイルの中に重複がなくても、同じ手順を 2 か所から呼べば一覧には同じ文字列が 2 つ並ぶ。この形を警告で防ぐことはしない。同じ手順を 2 か所から呼ぶのは普通の再利用だからである。一覧の側で、手順の名前と呼び出しの並び順を付けて区別する。

## 9. 条件とフレーム表

### 9-1 条件

この形式が決めるのは次の 5 つである。

- 先頭に `kind` が `"condition"` の欄と `format` の欄を持つ。`format` の値は手順とは別に数える。
- 名前はフォルダー名であり、ファイルの中には書かない。
- 「判定する映像」は `source` の欄に持つ。`{"kind": "lane"}` は「装置に設定している映像」で、どの映像かは、実行する装置に開始した時点で設定されている映像で決まる。装置の台数にも PC にも依らないので、受け渡す条件はこの形にする。ほかの種類(`dshow`、`desktop`、`window`、`file`)は、カメラの名前、モニターの番号、ウィンドウのタイトル、ファイルの場所といった、その PC の実体を持つ。別の PC で見つからないときは、開始の前のチェックが知らせる(8-3)。判定する範囲は判定する映像に対する相対の値なので、別の PC でも意味を保つ。
- `condition.json` は、画像を、その条件のフォルダーの中の相対の位置で指す。フォルダーの外や絶対の位置は指定できない。指し方がフォルダーの中で閉じているので、条件の名前を変えても複製しても、`condition.json` の中を書き換えずに済む。10-4 の「置き換える」はフォルダーごとの置き換えであり、「別の名前でインポートする」はフォルダー名の変更である。インポートでは、画像にこの PC で新しい名前を付け、並びもそれに合わせて書く(下の項)。
- `condition.json` の欄は次のとおりで、どの欄も省略できず、これ以外の欄は拒否する(`format` は 1)。

| 欄 | 値 |
|---|---|
| `source` | 判定する映像(上の項) |
| `regions` | 判定する範囲 `[x, y, w, h]` の配列。x と y は 0 以上 1 未満、w と h は 0 より大きく 1 以下の、映像に対する割合。x + w と y + h は 1 以下。空なら画面全体 |
| `threshold` | しきい値。1〜100 の整数。一致度がこれ以上なら一致 |
| `refs` | 基準画像の位置の配列(`images/3f2a9c0d1b7e4a55.png` の形)。いずれか 1 枚に一致すれば一致 |
| `negatives` | 一致しないはずの画面の位置の配列。判定には使わない |

  画像の名前は、小文字の英字・数字・ハイフン・下線の 1〜64 文字に `.png` を付けたものである(位置の区切りは `/`)。Windows が予約している名前は使えない。同じファイルを別の綴りで指定できると、Windows は大文字と小文字の違いや末尾の「.」でも同じファイルを開くので、片付けやインポートが別の画像と混同する。padcue が追加する画像と、インポートした画像には、この PC で作る 16 桁の 16 進の乱数を名前にし、別の画像に同じ名前を使わない。編集画面の「元に戻す」の履歴は画像を位置で指すので、消えた画像の名前を別の画像に使うと、戻したときに別の絵になる。
- 基準画像を登録した直後に取得した画面は、基準画像の隣に `3f2a9c0d1b7e4a55.a1.png` と `3f2a9c0d1b7e4a55.a2.png` の名前で置く(しきい値の目安を求めるのに使う。observe-and-decide.md §2)。名前で基準画像と結び付くので、`condition.json` には一覧を持たない。
- `images/` には、`condition.json` が指していない画像があってもよい。条件の編集の画面は、追加した画像をその時点で置き、外した画像も元に戻せるようにすぐには削除しない。`images/` の中の、どの条件からも指されていないファイルは、操作画面を次に起動したときに削除する。

`source` は `kind` ごとに次の欄を持ち、これ以外の欄は拒否する。

| `kind` | 映像 | ほかの欄 |
|---|---|---|
| `lane` | 装置に設定している映像 | なし |
| `dshow` | DirectShow の機器 | `device`(機器の名前。必須) |
| `desktop` | モニター | `monitor`(整数。1 から順に各モニター、0 以下はすべてのモニターを合わせた画面。既定は 0) |
| `window` | ウィンドウ | `title`(タイトルの一部。必須)。当てはまるウィンドウが 2 つ以上あれば、どれも取り込まない。一度決めたウィンドウは、タイトルが変わっても、閉じるか見えなくなるまで使い続ける |
| `file` | 画像ファイル | `path`(PNG のファイルの場所。必須) |

スクリプトの `capture` に書く「装置に設定している映像」は、実行する装置の映像を指す決まった名前である。手順は装置に依らないので、装置の名前ではなくこの名前で書く。

### 9-2 フレーム表の CSV

CSV は `kind` も `format` も持たず、バージョンを判別できない(3 節)。この節の形を変えると、既存のファイルを別の意味に読むことになる。

- メタの列(入力ではない列)は次の 3 つである。`F` は連番のチェックに使う。`rep` はその行のくり返しの回数である。`disabled` は 1 ならその行を無効にし、空欄か 0 なら有効のままにする。ほかの値は拒否する。無効にした行は丸ごとなかったものとして扱い、時間も消費しない。編集画面の各行の「有効」のチェックを外すと 1 が入る。`F` に書くのはデータの行の番号で、ヘッダーを除いた行を上から 1、2、…と数える(ファイルの行の番号より 1 小さい)。無効にした行も数えるので、行を無効にしても番号の付け直しは必要ない。
- 1 行目はヘッダーである。列は使うものだけ書けばよい。フレーム表は、何も押さないことも含めて表のとおりに入力するので、書かなかった列は、すべての行が空欄の列と同じ扱いになる。手順の側で押し続けているボタンも、表の間は表のとおりに離れる。
  - ボタンの列: A B X Y L R ZL ZR PLUS MINUS HOME CAPTURE LS RS DU DD DL DR。セルは 1 が押す、0 と空欄が離すである。
  - 軸の列: LX LY RX RY。符号付きの生の値で -2048..2047、空欄は 0 である。
  - モーションの列: GY GR GP AX AY AZ。i16 の生の値である。空欄は GY、GR、GP、AX、AY が 0、AZ が 4096(静止した姿勢であり、重力 1G にあたる)になる。すべての軸が 0 は自由落下であり、実機にはない状態だからである。
  - 任意の列: F はデータの行の番号で、値は使わないが、書いてあれば連番をチェックする。rep は 1 以上の整数で、その行をその回数だけくり返す。空欄と、列がないときは 1 である。disabled を書かなければ、すべての行が有効である。
  - 入力の列(メタの列でない列)は 1 つ以上書く。
- 2 行目以降は 1 行が 1 フレームである。
- 文字コードは UTF-8 で、BOM も受ける。区切りはカンマである。
- ヘッダーの行の末尾の空の列名は 1 つだけ取り除く。データの行で、ヘッダーの列数より後ろのセルがすべて空なら、そのセルを取り除く。表計算ソフトが行の末尾にカンマを付けて保存しても読めるようにするためである。それ以外の空の列名と、列の数がヘッダーと合わない行は拒否する。
- 読み込みで拒否するのは、未知のヘッダー、重複したヘッダー、空の列名、入力の列がないヘッダー、列の数がヘッダーと合わない行、値域の外、1 未満か整数でない rep、空のファイル、セルのない空の行、有効な行が 1 行もない表(すべての行を無効にした表を含む)と、rep でくり返した後の行数が 100000 を超える表である。黙って解釈すると手順の長さが実装によってずれるからである。100000 行は既定の周期で約 27 分にあたり、rep の書き誤りで桁違いに長い表を読み込まないための上限である。上限は rep でくり返す前に合計で確認するので、大きな rep も展開せずに拒否する。列の数が揃ったすべて空欄の行は拒否せず、何も入力しない 1 フレームとして読む。F の連番のチェックはデータの行の番号を基準にし、rep で増えるフレーム数とは関係しない。拒否するときの場所は、ファイルの行の番号(ヘッダーが 1 行目)で示す。テキストエディターの行の番号と同じだからである。
- フレーム表がくり返しの中身になったときも、各行がすべての入力を決める。
- フレーム表を抜けたら、入る直前の状態へ戻す。最後の行で押していたボタンやスティックが、手順の続きへ残らない。戻すのは最後の行の次のフレーム、つまり次のブロックの開始位置なので、時間は消費しない。戻さないと「手順のどこにも書いていない入力」が最後まで残り、手順を読んでも分からない状態になる。くり返しの中身と同じ考え方である。
- 手順の側で押していたもの(`hold` など)は、フレーム表の間は表のとおりになり、抜けた後は手順の指示どおりに戻る。

## 10. エクスポートとインポート

### 10-1 エクスポートの形

出すものが 1 件で、それが 1 つのファイルなら、そのファイルをそのまま出す。それ以外は padcue ファイルにする。padcue ファイルは zip で、拡張子は `.padcue` とする。中の並びはプロジェクトと同じなので、展開すればそのまま読める。

- フレーム表 1 件は `<名前>.csv` になる。フレーム表は依存を持たないので、必ずこの形になる。
- 依存のない手順 1 件は `<名前>.json` になる。先頭の `kind` があるので、受け取った側は種類が分かる。参照先がエクスポート元のプロジェクトに見つからず、ほかに出すものがない手順も、その手順 1 件だけの `<名前>.json` になる(10-2)。
- 条件は画像を伴うフォルダーなので、1 件でも padcue ファイルになる。
- 手順が別の手順やフレーム表や条件を参照していれば、padcue ファイルになる。

padcue ファイルの中のファイル名は UTF-8 で書き、zip の汎用フラグの UTF-8 を示すビット(ビット 11)を立てる。名前には日本語も使え、その名前がそのままファイル名なので、文字コードを決めておかないと、受け取った側のツールで展開したときに名前が文字化けする。名前で書いた文書どうしの参照も、まとめて外れる。

```text
周回の手順.padcue
  pack.json
  procedures/周回の手順.json
  procedures/やり直し.json
  frametables/連続入力.csv
  conditions/完了画面/condition.json
  conditions/完了画面/images/3f2a9c0d1b7e4a55.png
```

`pack.json` は次の形である。

```json
{
  "kind": "pack",
  "format": 1,
  "created": "2026-09-07",
  "tool": "padcue 0.1.0",
  "note": "手順の一式です",
  "top": [{"kind": "procedure", "name": "周回の手順"}],
  "entries": [
    {"kind": "procedure", "name": "周回の手順"},
    {"kind": "procedure", "name": "やり直し"},
    {"kind": "frametable", "name": "連続入力"},
    {"kind": "condition", "name": "完了画面"}
  ]
}
```

`top` は利用者が選んだもの、`entries` は自動で追加した依存を含むすべてである。中の位置は `kind` と名前から決まるので書かない。内容の照合はインポートするときに実際のファイルから計算する。構成情報に書いた値は照合には使わない。構成情報は参考の情報であって、中身の正しさの根拠ではないからである。

構成情報の欄は、上の 7 つ(`kind`、`format`、`created`、`tool`、`note`、`top`、`entries`)である。手順と同じく、知らない欄があれば読み込みで拒否する(3 節、8-1)。欄を追加するときはバージョンを上げるので、同じバージョンで知らない欄があるのは、壊れているか手で書き間違えたかである。

構成情報の `format` が読めるバージョンでなければ、padcue ファイルを開かず、中の 1 件もインポートしない。手順や条件が読めるバージョンであっても同じである。構成情報の意味が分からないまま、中身だけをインポートすると、どれが利用者の選んだもので、どれが自動で追加した依存かを間違えるからである。読めるバージョンより新しいときは「新しいバージョンの padcue で作成されています」と知らせる。ほかの利用者と padcue ファイルをやり取りすれば、受け取った構成情報のバージョンが、ツールの読めるバージョンより新しいことは起きる。それ以外(`format` がない、整数でない、読めるバージョンより小さい)は、padcue ファイルが壊れていると表示する。

padcue ファイルを開くときは、まず中のファイルの数と、展開したときの大きさを確認する。上限は、ファイルの数が 10000 個、1 つのファイルが 64MiB、合計が 256MiB である。中身はメモリに読んで確認するので、上限がないと、小さく圧縮したファイルで大きなメモリを確保させられる。手順とフレーム表は大きくても数 MiB、条件の画像は 1 枚数 MiB なので、普通の使い方では上限を超えない。操作画面からインポートできるのは、48MiB までの padcue ファイルである。画面はファイルを base64 にして 1 つの要求で送るので、要求の大きさの上限(66MiB)に収まる大きさにしてある。

パスワードを設定した zip と、padcue が読めない方式(Deflate64 など)で圧縮した zip も、中を読む前に拒否する。padcue のエクスポートは、どちらも使わない。受け取った人が別のツールで作り直したファイルなので、padcue でエクスポートしたファイルを使うよう知らせる。

次に、zip のエントリ名をすべてチェックする。受けるのは、`pack.json` と、`procedures/`、`frametables/`、`conditions/` の 3 つのどれかで始まるエントリだけである。次のものは拒否する。

- ほかの名前で始まるエントリ。
- 絶対の位置(先頭の `/` や `\`、`C:` のようなドライブ文字)。
- `..` を含む名前。
- フォルダーやファイルへのリンク。

フォルダーのエントリ(名前が `/` で終わるもの)は中身を持たず、書き出さないので、このチェックに通さない。

エントリ名のうち名前にあたる区切り、つまり `procedures/<名前>.json` と `frametables/<名前>.csv` の `<名前>` と、`conditions/<名前>/` の `<名前>` は、2 節の名前の規則でもチェックする。名前がそのままファイル名になるので、保存先の外を指す名前も、ファイル名にできない名前も入れない。`conditions/<名前>/` の下は `condition.json` と `images/` の中の画像(`.png`)だけで、そこの区切りも同じ規則でチェックする。画像のほかを受けないのは、インポートすると条件のフォルダーにそのまま書くからである。条件の名前はフォルダー名そのもので、名前の中の点(「v1.2」)は拡張子として扱わない。

1 件でも合わなければ padcue ファイル全体を拒否し、何もインポートしない。padcue ファイルはほかの人から受け取って使うことがあるので、名前の細工を書き間違いとはみなさないからである。padcue ファイルの中に、同じ種類で 10-4 の照合では同じになる名前が 2 つあるときも拒否する。

チェックの順は、数と大きさ、パスワードと圧縮方式、エントリ名、構成情報のバージョン、中の 1 件ごとの読み込みである。名前が信用できない padcue ファイルは、構成情報を読むより先に拒否する。

構成情報と実際のファイルが一致しないときは、実際のファイルを正とする。構成情報は参考の情報であって、中身の正しさの根拠ではないからである。不一致でインポートを中止することはしない。

- `entries` にないファイルが入っている場合は、インポートの候補に出し、その件の行に「padcue ファイルの中の一覧にありません」と付記する(10-5)。構成情報の書き漏らしで、手順の参照先が警告なしに欠けるのを避けるためである。構成情報は中の仕組みの名前なので、画面では「中の一覧」と表示する。
- `entries` にあるファイルがない場合は、読めなかった件と同じくインポートできない件として出し、理由を「padcue ファイルに含まれていません」と表示する。それを参照する手順の参照先が、インポートした後で見つからない理由が分かるようにするためである。
- インポートの画面は、`entries` の全件を並べる。`top` は、どれが利用者の選んだものかを残す参考の情報であり、`top` に書いたものが実際になくてもインポートは拒否しない。

構成情報が読めても、中の手順か条件が読めないバージョンであることは起きる。手順について読み込みで確認するのは、種類とバージョンと、入れ子の深さ(8-1)だけである。ほかの形の誤り(8-1)がある手順もインポートし、インポート先の手順の一覧に「エラー」として出す。入れ子が深すぎる手順を拒否するのは、インポートが参照を書き換える処理そのものが、その手順で異常終了するからである。バージョンが新しいときは、プロジェクトの手順を読むときと同じく「padcue を更新してください」と付記する。条件は、プロジェクトの条件を読むときと同じチェックにかける。バージョンと `condition.json` の欄(9-1)を見て、基準画像と一致しないはずの画面に指している画像が padcue ファイルに入っているかも見る。チェックせずにインポートすると、その条件を使う手順を開始するたびに、読めない条件としてメッセージが出る。

読めなかった 1 件は、利用者が「インポートしない」を選んだものと同じ扱いにする。それを参照する手順まで外すことはしない。参照の行き先は 10-4 のとおりで、元からある同じ名前のものがあればそれを指し、なければ見つからない。読めなかった件と、その理由はインポートの画面に出す。インポートする手順がその件を使用していれば、参照がどれを指すかも、その件の下に出す(10-4、10-5)。

構成情報が読めないときに全体を中止するのと扱いが違うのは、壊れる範囲が違うからである。構成情報が読めないと、どれが利用者の選んだもので、どれが自動で追加した依存かが分からなくなり、padcue ファイル全体の意味が成り立たない。1 件が読めないだけなら、残りの手順の意味はそのままである。

インポートは、padcue ファイルのほかに単体のファイルも受ける。手順の `<名前>.json` と、フレーム表の `<名前>.csv` である。手順は頭に `kind` を持つので種類が分かり、CSV は拡張子で分かる。拡張子の大文字と小文字は区別しない(`手順.JSON` も受ける)。条件のフォルダーは受けない。条件は 1 件でも padcue ファイルにしてエクスポートするので、受け取るのは padcue ファイルである。フォルダーのまま受け取ったときは、プロジェクトのフォルダーに直接置けばそのまま読める(R15)。

### 10-2 何を入れるか

手順を選ぶと、その手順が必要なものを自動でたどって入れる。呼び出しツリーにあるすべての手順、それらが使うフレーム表、選択肢の「選択条件」が指す条件、その画像(基準画像、登録の直後の画面、一致しないはずの画面)である。

たどるときは、`body`、くり返しの `body`、選択肢の `body`、`otherwise` のすべてを見る。`otherwise` は選択肢の並びに入っていないので、たどり漏らしやすい。無効にしたブロック(`disabled` が真)の参照先も入れる。無効にしたブロックは有効に戻せばまた実行されるものであり、戻した先で参照が切れていては困るからである。

一度たどった手順は再びたどらない。同じ手順を 2 か所から呼ぶ形でも、呼び出しが循環している形でも、これで処理は終わる。循環そのものは変換が拒否する(6-3)。

足りないものがあるときは、出すのを中止せずに構成情報から外し、結果に「「周回の手順」をエクスポートしました。次のものは見つからないため含まれていません: 条件「完了画面」。」のように出す。ファイルはあるのに読めない手順(一覧では「エラー」の行)は、中の参照をたどれないので入れず、「次のものは読み込めないため含まれていません: 手順「準備」。」と分けて表示する。見つからないと表示すると、一覧に出ている行と矛盾する。

選んだもの自体が見つからないか読めないときは、何も出さずに拒否する。画面もコマンドも同じである。中身の欠けた padcue ファイルを渡すと、受け取った人は何が欠けたかを知らない。

### 10-3 入れないもの

- 登録情報(装置の ID と名前)、プリセット、実行記録、表示順、変換の結果、操作権の識別子、稼働中の目印。
- レーンの映像の設定(映像ソースと切り出しの範囲)。
- 周回数と開始位置。

周回数と開始位置を入れないのは、エクスポートは一覧の行から 1 件ずつ行うので、その時点では決まっていないからである。受け取った側は、実行・監視のレーンで決める。

登録情報とレーンの映像の設定を入れないのは、PC ごとに違うものだからである。P15(条件は装置の台数や番号に依存しない)から導かれる。実行記録と変換の結果と操作権の識別子と稼働中の目印は、その PC で起きた事実か一時の状態なので、渡す先では成り立たない。表示順はインポート先の並びと混ざる。

映像ソースの名前は捨てずに残す。条件の「判定する映像」も、スクリプトの `capture` も、「選択条件」がスクリプトの結果のときの `capture` も同じである。捨てて「装置に設定している映像」に戻すと、決まった画面を見ていた条件が警告なしに別の映像を見ることになり、判断を誤る。インポートした PC に同じ名前の映像ソースがなければ、開始の前のチェックで知らせる(8-3)。

拒否しないのは、映像ソースを用意する前でも、受け取った手順を動かせるようにするためである。このチェックは、条件の「判定する映像」だけでなく、スクリプトのブロックの `capture` と、「選択条件」がスクリプトの結果のときの `capture` にも同じように適用する。

スクリプトの `capture` に書いた名前がこの PC にないときは、手順の編集画面のその欄に「(見つかりません)」と出る。条件の「判定する映像」は、条件の画面で選び直す。名前の照合は 2 節の規則で行う。

スクリプトの `cmd` は手順の意味そのものなので入れる。そのかわり、インポートの画面で、インポートする手順が実行するコマンドの文字列をすべて出して確認を求める。文字列は構成情報ではなく実際のファイルから集める。インポートでは何も実行しない。

### 10-4 名前の衝突

名前が同一性の単位である。ファイル名がそのまま名前なので、照合も名前で行う。照合は、Unicode の NFC に正規化したうえで、英字の大文字と小文字を区別せずに行う(2 節)。インポートする前に 1 件ずつ扱いを決める。

padcue ファイルの中に、同じ種類でこの規則では同じになる名前が 2 つあれば、インポートを拒否する。プロジェクトの同じフォルダーに両方を置けないからである。種類が違えば別のフォルダーなので、手順の「Retry」とフレーム表の「retry」は同時に置ける。「置き換える」を選んだときは、元からあるファイル名の綴りをそのまま残す。元からある文書の参照はその綴りで書かれており、綴りを変える理由がないからである。

| 状態 | できること | 既定 |
|---|---|---|
| 同じ名前がない | インポートする / インポートしない | インポートする |
| 同じ名前があり、内容も同じ | インポートしない | インポートしない |
| 同じ名前があり、内容が違う | 置き換える / 別の名前でインポートする / インポートしない | 別の名前でインポートする |

内容が違うときの既定を「別の名前でインポートする」にするのは、元からあるものが警告なしに消えるのを避けるためである。別の名前は末尾に連番を付けた「やり直し (2)」で、その場で変えられる。連番は、元からある名前に加えて padcue ファイルの中の名前も避けて決める。中に「やり直し」と「やり直し (2)」があるとき、「やり直し」を「やり直し (2)」にすると、2 件が同じ名前に書かれて片方が消えるからである。

入力した別の名前は、次のどれかに当たれば使えない。その欄のすぐ下に理由を出し、「インポート」を無効にする。

- 名前の規則(2 節)に合わない。
- 元からある名前と同じ。そのまま書くと、元からあるものを黙って上書きする。条件ならフォルダーごと消える。
- ほかの行の名前(padcue ファイルの中の名前と、ほかの行が付ける別の名前)と同じ。一緒に入れる手順はほかの件を名前で指すので、どちらを指すのかが入れ替わる。

インポートするときも、書く前に全件を同じ規則でチェックし、1 件でも合わなければ何も書かない。1 件ずつ確認しながら書くと、途中の件で拒否したときに、前の件だけが書かれて残るからである。状態(表の左の列)も、このときにインポート先のプロジェクトを見て改めて決める。確認した後にインポート先に同じ名前のものができていると、「インポートする」はそれを上書きするので、確認したときと状態が違う件があれば、ファイルを選択し直してもらう。

チェックに通った後で、書き込みそのものが失敗することはある(ディスクの空きがない、ほかのアプリがファイルを開いている)。そのときは、参照される側から書く順(条件、フレーム表、手順)のおかげで、書き終えた件の参照は欠けない。書き終えた件は戻さず、書けなかった件とその理由、既にインポートした件を表示し、ファイルを選択し直して残りをインポートしてもらう。戻すための書き込みも同じ理由で失敗しうるからである。

同じ名前があり内容も同じ件は、選べる扱いが「インポートしない」だけなので、選択欄を置かず、状態だけを出す。インポートしても何も変わらないからである。

条件の「置き換える」は、フォルダーごとの置き換えである。`condition.json` だけを差し替えると、元からある画像と新しい条件が矛盾する。基準画像の指定が別の画像を指し、しきい値も別の画像に対して決めたものになる。画像は条件と一緒に保存するものであり、条件の一部だからである。そのかわり、置き換えで消える画像(基準画像と一致しないはずの画面)の枚数をインポートの前に示す(10-5)。画像は利用者が集めたものなので、何枚失うかを知らずに選ぶことにはしない。

フォルダーごと置き換えても、別の名前でインポートしてフォルダー名が変わっても、条件がそのフォルダーの中で閉じているのは、画像をフォルダーの中の相対の位置で指すからである(9-1)。フォルダーの外や絶対の位置を指す形にすると、置き換えも改名もフォルダーの外のものに及び、この表の扱いが成り立たない。

インポートは、padcue ファイルの中の参照を、実際に付けた名前へ書き換える。フレーム表を「連続入力 (2)」として入れたなら、一緒に入れた手順のフレーム表のブロックも「連続入力 (2)」を指すように書き換える。参照と中の名前は、この節の照合で結び付ける。参照の綴りが中の名前と大文字と小文字で違っても、同じものを指すからである。書き換えるのは padcue ファイルの中だけでよい。参照は、インポートするものの中からインポートするものを指すだけなので、元からある手順の参照は元の名前のままで正しい。

「インポートしない」を選んだものへの参照は、元からある同じ名前のものを指し、元にもなければ見つからない。インポートする手順がそれを使用しているときは、インポートの前に、その件の行の下に事実を出す。

- 内容の違うものをインポートしないときは、「「周回の手順」は元からある「やり直し」を使用します」と出す。受け取った手順が、インポート先の別の中身で動くことになる。
- 同じ名前がないものをインポートしないときは、「「周回の手順」が使用する「連続入力」が見つかりません」と出す。
- 内容も同じものは、何も出さない。中身が同じなので、意味は変わらない。

読めなかった件(10-1)も、同じ文をその件の下に出す。どちらも中止はしない。これは、同じ名前の別のものと、同じものの別のバージョンとを、ツールが区別できないことの帰結である。区別するための出所の識別子は持たない。

padcue ファイルに入っていない名前を指す参照(エクスポートしたときに見つからなかったもの)は、行がないので、インポートした後に、押した一覧の下で「インポートした手順が使用しているものが見つかりません」と知らせる。

識別子は書き換えない。ファイルの中だけで一意であればよいので、インポートした手順の識別子が元からある手順の識別子と同じ値でも困らない(6-1)。

### 10-5 インポートの前に見せるもの

- 何が入っているかの一覧と、1 件ごとに選んだ扱い。
- 構成情報の `entries` にないのに padcue ファイルに入っていたファイル。その件の行に付記する(10-1)。
- 読めなくて外した件と、その理由(10-1)。
- 名前が衝突している件と、「インポートしない」を選んだ件と読めなかった件について、インポートする手順の参照がどれを指すか(10-4)。
- 入力した別の名前が使えないときの理由(10-4)。
- 「置き換える」を選んだ件と、元からある手順のうちその名前を参照しているものの一覧。置き換えると、それらの手順の意味が変わる。
- 「置き換える」を選んだ条件について、そこで消える画像の枚数(10-4)。
- 「置き換える」を選んだ手順について、置き換えると見つからなくなるプリセットとレーンの開始位置(手順を保存するときの確認と同じ物)。
- 別の名前でインポートする件のうち、padcue ファイルの中でそれを使う手順がどれもインポートされないもの。インポートしても、どの手順からも使われない。
- インポートする手順が実行するコマンドの本文のすべて。別の名前でインポートする手順は、付ける名前で出す。

映像ソースの名前がこの PC にない件は、ここでは見せない。インポートの画面では映像ソースを選べず、インポートも拒否しないので、見せても何もできない。開始の前のチェックが知らせる(8-3、10-3)。

利用者が承認しなければ、1 件もインポートしない。1 件だけ外したいときは、その手順を「インポートしない」にする。

単体のファイルのインポートも、この画面を同じように通す。依存を持たない手順は単体の `.json` になるが(10-1)、その中にスクリプトのブロックがあればコマンドの本文を出して確認を求め、名前が衝突していれば 10-4 の表で扱いを決める。padcue ファイルかどうかで扱いを変えない。

## 11. 例

周回数のくり返しを持つ手順「周回の手順」の例である。

```json
{
  "kind": "procedure",
  "format": 1,
  "precondition": "開始の画面を開いた状態",
  "body": [
    {"type": "loop", "id": "lp-1", "name": "周回", "count": 50, "laps": true,
     "body": [
       {"type": "branch", "id": "br-1", "name": "1 周目かどうか",
        "arms": [
          {"name": "1 周目",
           "when": {"loop": "lp-1", "kind": "first"},
           "body": [{"type": "call", "id": "cl-1", "ref": "準備"}]}
        ],
        "otherwise": [
          {"type": "label", "id": "lb-1", "name": "2 周目から"},
          {"type": "call", "id": "cl-2", "ref": "やり直し"},
          {"type": "press", "buttons": ["A"], "frames": 5}
        ]},
       {"type": "wait", "frames": 960, "note": "読み込み"},
       {"type": "frametable", "ref": "連続入力"},
       {"type": "branch", "id": "br-2", "name": "完了画面を待つ",
        "arms": [
          {"name": "完了画面が出た",
           "what": {"kind": "condition", "ref": "完了画面"},
           "body": []},
          {"name": "時間切れ",
           "what": {"kind": "timeout", "frames": 3600},
           "body": []}
        ]}
     ]}
  ]
}
```

読み方は次のとおりである。

- `lp-1` が周回数のくり返しである。実行画面の周回数はこのくり返しの合計回数になる。`count` の 50 は、周回数を別のくり返しへ移したときに戻る値として残る。`lp-1` は `body` の直下にあり、選択肢の中身ではない(4-3)。
- `lp-1` があるので、この手順の分岐は `"@whole"` を指定できない(5-1)。「対象の回」の `loop` は `lp-1` を指す。
- `br-1` は「対象の回」だけで決まるので待たない。1 回目は「1 周目」の中身へ、2 回目から最後の周まではどの「対象の回」も当てはまらないので `otherwise` へ、どちらも待たずに進む。待たないので `wait_input` は書かない。
- `br-2` は「選択条件」を持つ選択肢が 2 本あるので、そこで選択待ちになる。時間切れは選択肢の「選択条件」なので、1 つの分岐に何本でも書ける(5-2)。
- `lb-1` から開始できる。位置は `{"name": "2 周目から", "path": [], "block": "lb-1", "turns": []}` である(6-2)。この位置をプリセットに保存した後でこの手順を改名すると、プリセットのレーンの `proc` は新しい名前へ書き換わる。実行の記録とログに残った手順の名前は古い名前のままである(2 節)。
- 30 周目を終えて 31 周目の先頭で停止すると、停止した位置は `{"path": [], "block": "lp-1", "turns": [31], "loops": ["lp-1"]}` になる(6-2)。周の境の `loops` は、そのくり返し自身である。
- 入力のブロック(待つ、押して離す、フレーム表)は識別子を持たない。

## 12. 概念の語と欄の名前の対応

| 概念の語 | この形式 |
|---|---|
| 手順の持つもの: 名前、ブロックの列、前提条件 | ファイル名、`body`、`precondition` |
| ブロックのメモと、無効にするかどうか | `note`、`disabled` |
| くり返しの回数(数か無限か周回数) | `count`、`laps` |
| ラベル、くり返し、分岐、合流点、スクリプト、別の手順の変わらない識別子(P23) | `id` |
| 分岐の持つもの: 名前、選択肢の並び、待つ間の入力 | `name`、`arms`、`wait_input` |
| 選択肢の持つもの: 名前、対象の回、選択条件、中身 | `name`、`when`、`what`、`body` |
| 対象の回: 最初の回、最後の回、n 回目、n 回ごと、残り n 回 | `when.kind` の 5 つの値 |
| 選択条件: 手動、条件、スクリプトの結果、時間切れ | `what.kind` の 4 つの値 |
| それ以外 | `otherwise` |
| 合流点の持つもの: 名前、時間切れ、待つ間の入力 | `name`、`timeout_frames`、`wait_input` |
| スクリプトの持つもの: 呼ぶ処理、完了を待つか、渡す映像ソースの並び | `cmd`、`wait`、`capture` |
| 待つ間の入力: 離す、そのまま | `"release"`、`"keep"` |
| フレーム表、別の手順、条件への参照 | `ref`(参照先の名前) |
| 条件の持つもの: 判定する映像、判定する範囲、しきい値、基準画像、一致しないはずの画面 | `source`、`regions`、`threshold`、`refs`、`negatives` |
