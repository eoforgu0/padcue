# フロー構造化データ仕様 v0(設計・レビュー用)

作成: 2026-07-29 ／ 状態: **実装済み**(pctool/padcue/flowfmt.py)。GUI とコンパイ
ラが読み書きする正本形式。

## 0. 目的からの演繹

- GUI(積み上げブロック)と 1:1 対応する**入れ子の構造化データ**であること(自由接
  続の線・任意循環を表現できない=不正状態を作れない)
- ブロック意味論(procedure-format.md)へ機械的に変換できること
- 分岐2種(待機なし/待機あり)を表現でき、画面認識は**差し込み口のみ**用意(実装は
  指示があるまで行わない)
- データモデルは編集UIの方式から独立(見せ方を変えてもデータ・変換・実行系は無傷)

## 1. プロジェクト構造(ディスク上)

```text
<プロジェクトフォルダ>/
  procedures/<名前>.flow.json   # フロー(本仕様)
  parts/<名前>.csv              # 行列部品(1行=1フレーム)
```

Excel を前提とした機能は置かない。CSV/JSON は汎用形式としての入出力であり、緊急
時は直接編集できる。

## 2. flow.json スキーマ

```json
{
  "schema": 1,
  "name": "素材周回",
  "pre": "拠点前・メニュー閉・カメラ北向き",
  "body": [
    {"type": "label", "text": "移動"},
    {"type": "stick", "side": "L", "x": 0, "y": 2047},
    {"type": "wait", "frames": 120},
    {"type": "stick", "side": "L", "x": 0, "y": 0},
    {"type": "press", "buttons": ["A"], "frames": 5},
    {"type": "hold", "buttons": ["ZL"]},
    {"type": "release", "buttons": ["ZL"]},
    {"type": "loop", "count": 3, "body": ["...node..."]},
    {"type": "part", "ref": "コンボ"},
    {"type": "call", "ref": "共通_メニューを開く"},
    {"type": "counter_branch", "arms": [["...奇数周..."], ["...偶数周..."]]},
    {"type": "wait_branch",
     "timeout_frames": 3600,
     "on_timeout": 0,
     "arms": {"成功": ["...node..."], "失敗": ["...node..."]}}
  ]
}
```

ノード種別(= GUI のブロック1種に対応):

| type                                  | 意味                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | 制約                           |
|---------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------|
| label                                 | 進捗表示・ログに出る名前                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | —                              |
| stick / press / hold / release / wait | DSL と同義(生値・フレーム整数)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | —                              |
| gyro                                  | ジャイロの回転速度(生値 i16)。`gp`(上下・未確認)/`gy`(ひねり・未確認)/`gr`(水平・実機確認済み、正=左回り)+ `frames`。frames > 0 はその長さだけ回して自動で 0 に戻す(press と同型)。frames = 0 / 省略は時間を消費せず次に変えるまで続く(stick と同型)。`sway`(既定 0)> 0 でゆらぎ(Switch 側ゼロ点自動較正よけの糖衣): 素の値を `sway_interval`(既定 60)フレーム続けるたびに +sway/−sway を `sway_period`(既定 2)フレームずつ対で入れる。interval=0 は常時交互。+と−を同フレーム数ずつ対で出すため合計回転量は 値×frames に厳密一致。余りは素の値。0 の軸は揺らさない。i16 を超える分は振幅を詰める) | 各値 -32768..32767             |
| loop                                  | 入れ子のくり返し(ブロック意味論=区間の正確な再生)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | count ≥ 1                      |
| part                                  | parts/<ref>.csv を展開                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | 参照存在検証                   |
| call                                  | 別 flow.json を展開(コンパイル時)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | 循環はエラー(未使用含め全検証) |

| counter_branch | **待機なし分岐**: 直近の囲みループの周回番号で腕を巡回選択 | ループ直下のみ・count % 腕数 == 0。**展開コンパイル**(周回をグループ化して展開するため実行時判定なし=µs すら不要、R1 完全非干渉) |
| wait_branch | **待機あり分岐**: 全ニュートラルで停止し、PC の指示で腕を選んで再開 | 後述 |

- ノード id は v0 では持たない(git 差分の綺麗さ優先。GUI v2 の undo/redo 設計時に再検討)
- 未知の type・未知のキーはエラー(前方互換より誤記検出を優先)
- **`"note": "…"`**(全ノード共通): 覚え書き。変換には一切使わず、画面にだけ薄く出る
- **`"off": true`**(全ノード共通): そのブロックを**丸ごと無かったもの**として扱う。
  「その時間だけ何もしない」ではなく**時間も消費しない**。くり返しや分岐に付けると
  中身ごと消える。ラベルに付けると再開点も作られない。**試しに一部だけ抜いて
  動かす**ための印であり、消さずに残せる
- **`"allow": ["1f", …]`**(全ノード共通): リント警告の抑止印。DSL の
  `# lint:allow-<名前>` と同じもの(例: `1f` = 1フレームの短さは意図的)

## 3. wait_branch の意味論 — セグメント連鎖方式(**採用しなかった当初案。記録として残す**)

> **この節は実装されていません。正本は §7 です。**
> セグメント連鎖(SEGEND オペコード・セグメント表)は、腕の長さが違うときの
> 時刻の付け替えが複雑になるため不採用にした。実装は「腕ごとに続きを展開する」方式。
> オペコードは STATE/SETCNT/DJNZ/JMP/END/AWAIT の6種のみで、SEGEND は存在しない。

- コンパイラは手順を**セグメントの連鎖グラフ**(基本ブロック列)に分割する: 先頭〜
  wait_branch が S0(終端 = AWAIT)、各腕の本体が S1..Sn(終端 = SEGEND next=共通続
  き)、共通続きが Sc。**共通続きは1つのセグメントとして共有し、腕ごとに重複展開
  しない**(当初案の重複方式はネストで指数的に膨張するため廃止)
- これにより **wait_branch のネスト・直列複数配置を自然に許容**する。上限はセグ
  メント数(255)と実行データ RAM プール(全セグメント合算 128KB)で、コンパイラが超
  過をエラーにする
- **AWAIT イベント**(procedure-format v3: timeout_frames u32 / on_timeout u8 =
  abort|腕番号 / 腕→次セグメント表はメタデータ): デバイスは全ニュートラル化して
  AWAITING 状態で待機し、`SELECT <segment, expected_hash>` で次セグメントへ。
  **SEGEND**(next: セグメント番号 | セッション境界)はセグメント間の即時連鎖
  (待機なし・O(1)、タイミング非影響)
- **セッション周回(loop_n)との関係**: 「1周」= 入口セグメントからセッション境界
  の SEGEND まで。**AWAIT は周回のたびに毎回停止し、毎回選択する**(画面認識判定
  を周回ごとに行う将来用途と一致。手動選択の省力化は PC 側の「前回と同じを自動選
  択」オプションで対応)。周回の時刻基準は経路の実経過フレームで進む(整数演算のみ、
  A-3 適合。腕の長さが違えば周回長も変わる=定義どおりの動作)
- **AWAITING での競合**(タイムアウト/停止2種/SELECT)の優先順位と遷移先は
  firmware-architecture.md §6 の遷移表を正本とする
- **source は PC 側の概念**: kind = "manual"(GUI に選択ボタンを表示)。将来
  "screen"(画面認識)等を追加してもデバイス側は無変更(SELECT が来るだけ)= 画面認
  識の差し込み口
- 全セグメントは実行開始前に一括転送(実行中のフラッシュ書き込み禁止と整合)

## 4. parts CSV スキーマ

メタ列(入力ではない列): `F`(行番号の連番検査)/ `rep`(その行の反復回数)/
**`off`(1 ならその行を丸ごと飛ばす。時間も消費しない。F の連番は行番号基準の
ままなので番号の付け直しは不要)**

- 1行目=ヘッダ。列は使うものだけ書く。**書かなかった列は「直前の状態を継続」**(そ
  の入力について何も言っていない扱い。hold 中のボタンが部品を通過しても切れない)。**書
  いた列の空セルは「離す/0」**(明示的にニュートラル)— レビュー指摘(loop との境界
  規則の非対称)への解決
  - ボタン列: A B X Y L R ZL ZR PLUS MINUS HOME CAPTURE LS RS DU DD DL DR(セル:
    1=押す、空=離す)
  - 軸列: LX LY RX RY(符号付き生値 -2048..+2047、空=0)
  - モーション列: GP GY GR AX AY AZ(i16 生値)。空欄は GP/GY/GR/AX/AY = 0、**AZ =
    4096(静止姿勢=重力1G)**。全軸 0 は自由落下で実機には無い状態のため
    (binfmt.REST_A* / matrix._BLANK)
  - 任意列: F(行番号。値は無視、書いてあれば連番検証)/ rep(この行を n 回反復、既
    定1)
- 2行目以降: 1行=1フレーム
- 文字コード: UTF-8(BOM 許容)、区切りはカンマ
- 検証(レビューで追加): 未知ヘッダ・**重複ヘッダ**・値域外・空ファイル・**セルの
  無い空の行**はエラー(黙って解釈すると手順長が実装依存でずれるため)。**列数が揃っ
  た全空セルの行は有効な1フレーム**(記載列すべて離す/0)。F 列の連番検証は **CSV
  行番号基準**(rep による展開フレーム数とは無関係)
- 部品はループの本体になった場合、ブロック意味論(区間の正確な再生)に従う。記載し
  た列については行が完全な定義である
- **部品を抜けたら、入る直前の状態へ戻す**(2026-08-02 確定)。部品の最後の行で押
  していたボタンやスティックが、手順の続きへ漏れない。戻すのは部品の最後の行の次
  のフレーム(= 次のブロックの開始位置)なので**時間は消費しない**
  - 理由: 戻さないと「手順のどこにも書いていない入力」が最後まで残り、手順を読ん
    でも分からない状態になる。くり返しの本体と同じ考え方(塊の中の状態は塊の外へ
    漏れない)
  - 手順側で押していたもの(`hold` など)は手順の指示なので、部品を抜けたあと元ど
    おり続く(部品がその列を書いていた場合、部品の区間だけは部品の指定が優先され
    る)

## 5. コンパイル規則

1. call / part / counter_branch を展開し、単一または複数セグメントのイベント列へ
   (ブロック意味論・リントは procedure-format.md のものを全適用)
2. label はイベント index との対応表(PC 側メタ)として出力し、進捗表示・異常ログ
   の位置情報に使う(バイナリには載せない)
3. 出力: セグメントごとの手順バイナリ+メタ(ラベル表、警告、セグメント遷移表)

内部・緊急編集用として維持(flow.json と同じコンパイラ基盤に接続)。正本は flow.json。

## 7. 実装(v0)の確定仕様 — 待機分岐

当初案(共通の続きを1つのセグメントとして共有する連鎖方式)は再基準化が複雑になるため、
**v0 は「腕ごとに、分岐より後ろの続きを展開する」方式**にした。

- `wait_branch` は **AWAIT イベント1つ + 腕ごとの独立した経路**にコンパイルされ
  る
- 各腕は「腕の中身 + 分岐より後ろの続き」を持ち、それぞれ `END` で終わる。腕の長
  さが違っても続きの時刻が正しくなる
- **制約**: トップレベルのみ(loop / 周回分岐の中には置けない)、入れ子不可、腕は
  最大4本。これにより展開量は「腕の数 × 続きの長さ」に収まる
- **時刻**: 待っている間はタイマーを止める。**待った時間はエンジンの時計から丸ご
  と抜ける**ので、予定時刻の付け替えは要らない(待った長さは精度に影響しない)。進
  捗の経過フレームにも待ち時間は入らない(「待つ間はタイミングを刻まない」の定義
  どおり)。※ v0 の一時期、これに加えて「待った実時間をフレームに直して加算する」
  コードがあったが、カウンタが止まっている以上その値は常に 0 で、動いていなかっ
  た(2026-08-04 に削除)。加算が実際に効いていたら待った長さぶん二重に進み、再開
  後の最初の入力がその時間だけ遅れて出る
- 待機中は**全ニュートラル**(押しっぱなしを残さない)。`timeout_frames` 超過時は
  `on_timeout`(0=中断 / 1..n=その腕へ)
