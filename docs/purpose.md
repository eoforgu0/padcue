# 目的

padcue が何のためにあるかを定める。ここに書くのは「なぜ・誰が・何ができるか・何を含むか」だけで、どう実現するかは書かない。要件・方針・仕様・設計は、すべてこの文書から導く。

## 1. 何をするものか

利用者が決めた一連のゲーム操作を、利用者に代わって Nintendo Switch に対して実行する。

利用者は「何を、どの順で、どんな状況になったら」を**手順**として書く。padcue はその手順のとおりに、コントローラーの入力を Switch へ送る。Switch から見えるのは通常のコントローラー操作だけで、本体にもゲームにも手を加えない。

## 2. 誰が、どこで使うか

- 利用者は、**自分で装置を組み立てて使う人**である。製品として配布するものではなく、保証・問い合わせ対応・配布元からの自動更新は想定しない。そのぶん、組み立てから日常の運用までを、文書だけを頼りに進められるようにする
- 1 人の利用者が、1 台以上の Switch を、自分の家庭内ネットワークの中で使う
- くり返し使うツールである。初見の分かりやすさは大事だが、日々の操作の速さと確実さを損なってまで、初めて使う人に合わせることはしない

## 3. 何ができるか

次の 2 つができる。特定のゲームには依存しない。

1. 同じ操作を、決めた回数か停止させるまでくり返す。人が見ていなくても続く
2. 「何フレーム目に何を押すか」を決めて、そのとおりに再現する

この 2 つは設計を評価するときの基準であって、システムの根幹はどちらにも依存しない。

## 4. 価値の優先順位

設計上の判断は、次の順で価値を守る。下位の価値のために上位の価値を損なわない。

1. 意図どおりに実行される。2 つの意味がある
   - **時間の正しさ**: 意図した時刻に、意図した入力を Switch が受け取る
   - **状況の正しさ**: 手順が前提とする画面と進行の状況で、Switch がその入力を受け取る

   どちらが欠けても手順は破綻する
2. 見ていなくても動く。異常時には暴走せず停止し、人の関与は必要な箇所だけで済む
3. 試行錯誤が速い。手順の追加や変更は日常的に起きる。手順を書き、修正し、試すまでの手数が少ない

## 5. 含むもの・含まないもの

| 含む | 含まない |
|---|---|
| 手順の作成・保存・整理 | ゲーム内容の解析(本体メモリの読み出しなど) |
| 手順の実行と停止 | 本体やゲームの改変 |
| 状況の観測と、それに基づく判断 | オンライン対戦・ランキングなど他者に影響する使用 |
| 手順から利用者の任意の処理を呼び出す仕組み | 特定のサービスや用途に特化した連携 |
| 複数台の同時運用(台数を固定しない) | 量産品としての配布 |
| 人が見ていない間の安全(異常時に停止し、暴走しない) |  |
| 利用者どうしでの手順と条件のやり取り |  |

## 6. 前提とする条件

- 任天堂株式会社とは無関係の、非公式の個人プロジェクトである
- オフラインまたはローカルの用途に限る。利用規約への適合は利用者の責任で行う
- 対象は Nintendo Switch 2 と初代 Switch である
- 信頼できる家庭内ネットワークの中で使い、インターネットへは露出させない
