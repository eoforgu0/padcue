# 操作画面の個別の判断

一般的な Web やアプリの慣習から外れている選択と、その理由である。原則は [gui-principles.md](gui-principles.md) にある。

- **緑は健全と稼働**(「実行中」のチップ、接続の丸)。gui-principles.md §6 の「平常時に彩度を使わない」は大きい色面を戒めるもので、9px の丸と小さいチップは対象外である。稼働と接続を緑で示すのは、「健全」の合図である。人が選ばないと進まない待ちは黄色の外周で示し、異常停止は赤いバッジで示すので、緑と二重にならない。
- 主操作ボタン(開始、保存)の彩度の高い塗りは、gui-principles.md §6 の意図した例外である。塗った主操作ボタンは広く使われる慣習で、面ではなくボタンの形として読まれる。「平常時に彩度を使わない」は地と面についての決まりで、主操作の塗りは除く。
- **削除のアイコン**: ゴミ箱はファイルや登録そのものを削除する操作に、閉じるアイコンは並びや表示から外す操作(記録やメッセージを閉じるのも含む)に使う。同じ「消す」でも、消えるものが残るかどうかが違うので、形も分ける(gui-principles.md §6 の「同じ意味は同じ形」の裏返し)。
- **状態のバッジとボタンの形**: ボタンは枠で、状態のバッジ(「待機中」「未保存」など)は地の色で示し、枠を持たせない。どちらも小さな角丸で並ぶので、枠の有無まで同じだと、灰色の「未保存」が押せない「やり直す」と同じに見える(gui-principles.md §6 の「同じ意味は同じ形」の裏返し)。バッジの形をした押せるもの(編集画面の見出しの「1P 実行中」)は、押せるので枠を持つ。
- **記号**: 行のアイコンは、文字の記号ではなく線画(SVG)で描く。文字の記号は書体に左右され、小さいと潰れて区別できない。記録中と手動操作中は、記号ではなく文字のバッジで示す。「区切りで停止」と「停止」の違いは、色と位置と名前が示す。
- 「待つ」ブロックだけ左の枠線を出さない(app.css)。左の枠線が途切れることを、上から読んだときの区切りにする。gui-principles.md §6 の「色を持たせるのは、それが何かをほかが示していないときだけ」は、区切りとして枠線を出さないことも含む。
- **有効のチェック**: 入っているときは薄く、外したときだけ警告の色の枠で目立たせる。平常時に彩度を使わず、外した行だけを目立たせる(gui-principles.md §6)。行に余白がないので、チェックに文字のラベルは付けない。外したときの枠がその代わりになる。
- **「接続」の 2 つの意味**: PC と装置(レーンのバッジ「未検出」)と、装置と Switch(装置の行の下段「… に接続中」、Switch 本体の一覧の「1P が接続中」「未接続」、レーンのメッセージ「Switch に USB で接続されていません」)。装置と Switch の側は、文の中で必ず相手(Switch・本体の名前)を指定する。PC と装置の側は、状態の語では「接続」と言わず、「未検出」とその反対の「見つかっている」で言う(装置の削除を無効にしている理由「未検出になるまでは削除できません」、見つかった装置の一覧の「見つかっていません」)。失敗の文では「接続」を使い、相手を IP アドレスか「装置」で指定する(「192.0.2.20 に接続できません」)。
- 開始・区切りで停止・停止の 3 つのボタン: 回数は周回数の欄が持つので、実行のボタンは 1 つでよい(1 回だけ実行したいときは欄に 1 を入れる)。停止は、区切りまで進んでから停止するものと、その場で停止するものが意味の違う別操作なので分ける。
- **押すと名前が逆の操作に替わるボタンは、ダブルクリックの 2 回目を受けない**。対象は gui-principles.md §7-12 の、名前も替えるボタンである。手動操作の「手動操作を開始」と「手動操作を終了」、記録の「記録を開始」と「記録を停止」、レーンとグループの見出しと一括操作の「区切りで停止」と「予約を取り消す」がこれに当たる。要求の応答と状態の再取得は数十ミリ秒で済むので、人のダブルクリックの 2 回目(0.1〜0.2 秒後)は、名前が替わった後のボタンを押す。受けると、始めた手動操作や記録がすぐ終わり、付けた予約がすぐ取り消される。

  2 回目かどうかは click の detail で見る。OS のダブルクリックの間隔(Windows の既定は 0.5 秒)の中で同じ所をもう一度押すと、2 以上になる。間隔より後に押せば 1 に戻るので、逆の操作として受ける。間隔の中で、意図して逆の操作を押すことはできなくなるが、それは受け入れる。キーボード(Enter と Space)で押したときは 0 なので、いつも受ける。

  選択待ちの選択肢と、合流点とスクリプトの待ちの「待たずに進む」も同じに扱う。名前は替わらないが、押すと次の待ちのボタンに入れ替わりうるので、2 回目が同じ所に出た次の待ちの選択肢を押してしまう。1 つの待ちで選べるのは 1 回だけなので、受けなくて失うものはない。

  名前が替わらない「停止」は対象にしない。2 回目に押しても停止するだけなので、受けない理由がない。装置の「LED を点滅」も同じで、2 回目に押しても、点滅がそこから 5 秒に延びるだけである。開閉のボタン(タイムラインの見出し、フォルダー)も対象にしない。要求を送らず、結果はその場で見え、もう 1 回押せば戻る。ダブルクリックで開いて閉じるのは、details 要素など、ほかの開閉の UI と同じである。

  判定は `web/core.js` の `ignoreSecondClick` だけが持ち、対象のボタンはこれを通す。
- **LED を点滅させた装置は、押した行の丸も同じ 5 秒だけ点滅させる**。うまくいったことは文で示さない(gui-principles.md §6)。どの行を押したかが分かり、LED のない模擬装置でも押せたことが分かる。装置の LED と同じく 0.15 秒ごとに点灯と消灯をくり返し、色は状態の色ではなく文字の色にする(赤や緑のまま点滅させると、異常や稼働の通知に読める)。見つかった装置の行は、使う前の装置の状態を示さないので丸を置かないが、点滅させる間だけ同じ場所に出す。動きを減らす設定(prefers-reduced-motion)のときは、点滅させずに輪で示す。
- 失敗のメッセージには、次にできることを書く。起きたことだけを言われても、読む人は次に何をすればよいか分からない。次にできることがないとき(想定していないエラー)は、起きたこととエラーの名前だけを書く。読む人は仕組みを知らないので、中で使っている仕組みや工程の名前(名前を引く、収集、内部エラー)は出さない
  - 補足: メッセージの文は選んでコピーできること。人に見せるためにコピーしたいのは、まさにこの文である。選択を外してよいのは、ドラッグして動かすハンドルだけ
- **変換の失敗と警告は、開いた時点で出す**。保存を押すまで待たずに出す。文は「N 番目(ブロックの種類): 文」で、押すとそのブロックへ移る(要約まで入れると括弧が入れ子になり、文の中の名前と重なる)。N は列に見えている順の番号で、無効にしたブロックも数える。コマンドの文も同じ番号で示す(file-format.md §8)。置いたばかりで選んだままのブロックの分は、選ぶのをやめるか保存するまで出さない(置いている最中に、まだ書いていない値を責めない)。原因のブロックは赤、警告のあるブロックは黄で示す(一覧の「エラー」も押せて、開いて原因のブロックを選ぶ)。
- **空状態**は、何がないかを書き、次に行う操作か、名前から読めない使い道を付け加える(gui-principles.md §7-12)。装置が 0 台のときは「装置がありません」と、電源と Wi-Fi の案内を出す(見つかった装置があれば案内は出さない。次に行う操作は「追加」である)。ログは「ログはありません」、プリセットは「プリセットがありません」と、何を保存できるかを出す。
- **丸は色で区別する**。レーンの状態はチップの文言でも、異常は装置の行の枠線でも伝える。装置の一覧の丸だけは色にしか頼らない(既知の限界)。
- **文字の大きさ**は Windows の文字の指針に合わせる。標準の太さの字は 12px 以上、太字は 14px 以上(それより小さいと読めない言語があり、日本語はそれに当たる)。本文は Windows のデスクトップのアプリと同じ 12px(日本語の UI フォント Yu Gothic UI の 9pt)にし、補足も同じ大きさで色で分ける(12px と 14px を同じ画面で比べると、12px でも読め、一覧に入る行が多い)。名前と見出しは 14px の太字(600。Windows は強調に Bold ではなく Semibold を使う)。14px より小さい日本語は太字にせず、状態は色・枠・バッジで表す。10px(fs-tight)は数字と英字だけの狭い所(ON のセル、日付)に限り、日本語は入れない。値と役割の対応は app.css の冒頭のトークンで定め、テスト(uicheck の画面に出た文のテスト)が全画面で守られているかを見る
  - 補足: 日本語の見出しにも字間を広げない。日本語は字間を空けずに組むのが基本で(日本語組版処理の要件)、字間を広げるのは英字の大文字の見出しの習慣である
  - 補足: 拡大率 100% の FHD では、CSS の 1px が画面の 1 画素になる。基準幅(下)を決めた前提(150%)では 12px が 18 画素で出るが、100% では 12 画素のまま出る。文字の大きさは 100% の画面で読めることを基準にする

### デスクトップとマウスの前提(gui-principles.md §0 の補足)

この画面は、デスクトップでマウスで操作することを前提にする。このため、WCAG 2.5.8(ターゲット 24px)、タッチの当たり判定、幅 430px 未満のレイアウトは対象外とする。基準幅は 1280px(gui-principles.md §3)で、横にはみ出すものは、`main>*{min-width:0}` と、表とタイムラインの中だけのスクロールで抑える。タッチと小さい画面に対応するときは、この前提から見直す。

### アクセシビリティと細部の決めごと

- 枠線ボタンのコントラスト(WCAG 1.4.11): 枠線だけのボタン・タブ・アイコンボタンの枠は、入力欄と同じ `--line-strong`(3:1 台)にする。`--line`(1.58:1)では足りない。塗り(primary)・危険(danger)は独自の枠色を持つので対象外。
- **キーボード到達**: 一覧行(手順・フレーム表・条件)・手順ブロック・パレット項目を `tabindex` と Enter・Space で操作できるようにする(`keyActivate`)。中に `<button>` を含む行(.proc/.blk)には role=button を付けない(「ボタンの中に対話要素」を禁じる ARIA に反するため。操作できることは `:focus-visible` の枠と aria-label で伝える)。対話要素を持たないパレット項目だけ role=button。フォルダーの開閉は `<button>`(.foldertoggle)なので、そのまま到達できる。
- **記号だけのボタンの名前**: 記号(▶・▼ など)は `aria-hidden` の span に入れて読み上げから外し、名前は `aria-label` に持たせる(title と同じ文)。中に記号があると、読み上げはそれを名前にする。同じ働きのボタンは同じ名前で呼ぶ(図の開閉は、レーンでも手順の編集でも「入力ごとの行を表示」)。
- **支援技術への状態通知**: メッセージ(`showIn`)には、失敗に role=alert、警告と成功と案内に role=status を付ける。ログ領域には role=log、送達エラーには role=alert を付ける。ログは 1 秒ごとの取得で中身が同じなら描き直さない(署名で判定。role=log の重複読み上げと無駄な再描画を同時に防ぐ)。
- 設定パネルのフォーカス管理: 開いたらパネル内へ、閉じたら ⚙ へ戻す(外を押して閉じたときは奪わない)。role=dialog + aria-label、⚙ に aria-haspopup=dialog。行のメニュー(⋯ と ▾)を開くと閉じる(メニューとパネルは一度に 1 つだけ開く)。
- 操作の後のフォーカス: 状態を変える操作のボタン(`act` を通すもの)は要求の間無効になり、Chrome はフォーカスを body へ移す。済んだ後も body のままなら、押したボタンへ戻す。押したボタンが消えた・隠れた・無効になったときは、そのレーンのカード(一括操作ではすべてを選ぶチェック)へ移す(`focusBack`)。

  「開始」「停止」「操作権を取得」のボタンへは移さない。開始の後にフォーカスが「停止」にあると、Enter をもう一度押しただけで始めた実行が停止する。押すと名前が逆の操作に替わるボタン(「区切りで停止」「手動操作を開始」)も、押したボタンへ戻さずにカードへ移す(`data-flips`)。戻すと、Enter をもう一度押しただけで、いま済ませた操作を打ち消す。フォーカスを受けるカードは役割(group)と名前を持つ。

  待つ間に利用者がほかへ移したフォーカスは奪わない。何もない所を押したときも同じである(フォーカスは body へ移るが、外れたのではなく利用者が選んだ)。
- 条件の範囲の内側ドラッグ移動: 矩形の内側をドラッグすると、大きさを保って位置だけ動かせる(画像クロップの通例)。四隅をドラッグすると大きさが変わる。内側では cursor:move で、動かせることを示す。
- prefers-reduced-motion: 動きを減らす設定のときは、バッジの点滅と成功の合図の淡いフェードを行わない(状態は色と枠が示すので、動かさなくても伝わる)。
- フレーム表グリッドの「元に戻す」: 塗り(ドラッグ含む)・行の挿入や削除・範囲コピー(フィルと Ctrl+D)の直前に行全体を覚えておき、「元に戻す」ボタンと Ctrl+Z で戻せるようにする。数値は確定(Enter・Tab・欄を離れる)の単位でスナップショットし、セル単位で戻せる。打っている途中は入力欄自身の Ctrl+Z(文字単位)に任せ、欄の値が確定した値と違う間はアプリの「元に戻す」の対象にしない。
- 角丸・重なり・影・余白のトークン: 面と容器の角丸は `--radius-lg` の 1 つにし、半径の 6 段、z-index の重なり順、唯一のドロップシャドウは役割の名前のトークンにする。余白にも、文字の大きさと同じく、役割ごとに 1 つのトークンを当てる考え方を適用する。ただしトークンが役に立つのは、その役割がくり返し使われる(1 か所修正すれば揃う)か、離れた箇所が一緒に動かないと壊れる(結合)ときに限る(fs トークンが少数の役割を何度も使い回すのと同じ理屈)。

  この基準で共有される 3 つ、`--gap-section`(main/stack/lanes の縦リズム)・`--gap-row`(.row/.btngrp の操作間)・`--tl-label`(タイムラインのラベル列幅。トラック・目盛り・現在位置がこの 1 点で揃い、ずれると不整合になる。つまり結合している)をトークンにする。

  残りの余白は、ほぼ要素ごとに違う微調整で、セレクター自身が役割を示しているので生値のまま置く。別トークンにしても「一度しか使わない別名」が増えるだけで、再利用も結合の恩恵も生まれない。線引きは、値が同じかどうかではなく、共有と結合があるかどうかである(fs-sub と fs-body が同じ 12px でも別のトークンなのと同じ)。
- コントラストの余裕: 明るい配色の muted の文字は、AA の 4.5 をわずかに上回るだけである(地と surface-2 の上で 4.68 から 4.84)。surface-2 や muted を動かすときは計算し直す。

### 既知の限界

- 一覧の行を 1 つずつタブでたどると、行の中のアイコンのぶんタブの数が増える。行と、行の中のアイコンが、それぞれ到達点になるためである。
- 装置の一覧の丸は、色にしか頼らない。
